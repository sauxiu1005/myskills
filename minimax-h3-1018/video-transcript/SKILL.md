# 视频转录工作流

这个技能用于把上传的视频或音频文件转成准确、可阅读的逐字稿。它不是“Whisper 优先”的流程。默认生产路径是：

```text
媒体文件
→ ffmpeg 探测
→ 快速抽取/标准化音频
→ 内置 ASR 生成字幕源
→ 读取 SRT
→ 整理为 Markdown 逐字稿
→ 必要时 Whisper 兜底
```

当用户上传媒体文件并要求转录、生成字幕、整理 Markdown 逐字稿、提取金句、整理播客/访谈/会议内容，或构建可搜索音视频资料库时，使用这个技能。

## 核心原则

ASR 语音识别只需要音频，不需要视频画面。对于视频文件，必须先准备一份干净、标准化的音频文件。这样可以提升稳定性，避免视频容器/编码兼容问题，也方便后续复用和排查错误。

Whisper 很有用，但依赖重、安装成本高。它应作为本地/离线兜底方案，而不是默认主流程。

---

## 步骤 1：确认输入文件

支持常见视频和音频格式，包括：

- 视频：`.mp4`、`.mov`、`.m4v`、`.webm`、`.mkv`、`.avi`
- 音频：`.mp3`、`.wav`、`.m4a`、`.aac`、`.flac`、`.ogg`、`.opus`

如果媒体分析工具不识别某个后缀，不要立刻失败。像 `.m4v` 这类文件可能仍然是有效媒体文件，应改用 ffmpeg probe 探测。

需要检查：

1. 文件存在且可访问。
2. 时长合理。
3. 至少存在一条音轨。
4. 如果用户指定语言，则使用用户指定语言；否则根据内容自动识别或选择最可能的语言。

如果没有音轨，停止流程并告知用户：该文件没有音频，无法转录。

---

## 步骤 2：先抽取并标准化音频

所有视频转录任务都必须先抽取音频，再送入 ASR。

推荐的 ASR 输入音频格式：

```text
WAV
单声道
16 kHz
PCM signed 16-bit
```

对应的 ffmpeg 逻辑：

```bash
ffmpeg -i input_video.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le asr-input.wav
```

含义：

- `-vn`：忽略视频流，只处理音频
- `-ac 1`：转成单声道
- `-ar 16000`：采样率统一为 16 kHz
- `-c:a pcm_s16le`：输出标准 WAV PCM 音频

如果输入本身就是音频，也建议在必要时统一标准化，保证后续 ASR 行为可预测。

保留抽取出来的音频路径。它可以继续用于：

- 重新转录
- Whisper 兜底识别
- 人声/背景声分离
- 降噪和音频清理
- 声音克隆参考准备
- 人工复听校对

---

## 步骤 3：主 ASR 引擎——内置字幕生成

默认使用内置媒体字幕/ASR 能力，在音频抽取完成后运行。

期望输出：

- SRT 字幕文件，作为转录源文本
- 可选 ASS 字幕文件，如果工具同时返回
- 字幕条数和识别时长

用 SRT 作为后续整理 Markdown 的 source of truth。除非用户明确要求，并且当前工作流允许，否则不要把字幕烧录进视频。

主 ASR 成功的判断：

1. 成功生成 SRT 文件。
2. 字幕条数大于 0。
3. 识别时长和媒体时长大致匹配。
4. 语言判断合理。
5. 文本不是空白，也不是大量重复幻觉。

如果主 ASR 成功，不要再运行 Whisper，避免重复工作。

---

## 步骤 4：Whisper 兜底策略

本地 Whisper 只作为兜底方案使用。

以下情况才启用 Whisper：

- 内置 ASR 工具失败
- 内置 ASR 返回空结果或无效结果
- 内置 ASR 语言明显识别错误
- 用户明确要求“用 Whisper”
- 用户要求本地/离线转录
- 用户需要 Whisper 特有的 JSON/TSV 输出，且依赖已经可用

使用 Whisper 前，先快速检查依赖：

```bash
python3 -c "import whisper, torch; print('whisper ok')"
```

如果缺依赖，不要静默花很长时间安装大包。应告知用户本地 Whisper 当前不可用，并询问是否允许安装，除非用户已经明确授权。

Whisper 依赖较重，尤其是 `torch`。运行时临时安装可能因为网络不稳定而失败或耗时很久。更推荐把 Whisper 作为预装好的兜底能力使用。

当 Whisper 可用时，优先转录标准化后的 WAV，而不是原始视频。

建议默认模型：

- 5 分钟以内短视频：`small` 或 `medium`
- 长录音：先用 `small`，速度更稳
- 高精度交付：资源允许时用 `medium` 或 `large`
- 如果语言已知，显式传入语言；中文使用 `zh`

Whisper 可输出：

- `txt`
- `srt`
- `vtt`
- `json`
- `tsv`

如果最终要整理 Markdown，优先保留 `json` 和 `srt`：JSON 保留分段信息，SRT 便于人工复核。

---

## 步骤 5：读取并清理转录源

在写最终文档前，必须读取生成的 SRT 或 JSON。

清理规则：

1. 保留时间戳。
2. 将过短字幕片段合并成更适合阅读的段落。
3. 轻度添加标点、断句和段落。
4. 修正明显的空格、大小写或格式问题。
5. 不改写说话人的原意。
6. 不编造缺失内容。
7. 对疑似识别错误的短句做备注。
8. 品牌名、人名、产品名、专业术语优先使用用户提供的写法。

说话人标注：

- 如果明显只有一个说话人，可使用已知姓名；未知则使用“说话人”。
- 如果能明显区分多人，可标注“说话人 1”“说话人 2”，或在证据充分时使用推断出的姓名。
- 不要凭空编造具体说话人姓名。
- Whisper 本身不可靠地完成说话人识别；说话人分离是另一个任务。

---

## 步骤 6：生成用户可读的 Markdown

如果用户要求“逐字稿 / Markdown / 可阅读转录稿”，不要只返回原始 SRT，而应生成 Markdown 文档。

推荐结构：

```markdown
# <文件名或视频标题> 完整字幕逐字稿

## 视频/音频信息

- 文件名：...
- 时长：...
- 语言：...
- 说话人：...

## 简短摘要

...

## 章节目录

1. ...
2. ...

## 完整逐字稿

### 章节标题

[00:00:01 → 00:00:08]
**说话人：** ...

## 关键观点总结

- ...

## 可复用金句/引用

- “...”

## 转录备注

本稿基于自动语音识别生成，并已进行轻度标点、断句和阅读性整理。专有名词和个别短句建议结合原始音视频人工校对。
```

如果用户只要 SRT/VTT，则提供字幕文件，不要过度整理。

如果用户要内容复用，可增加：

- 博客大纲
- 社媒文案
- 金句库
- 节目笔记
- 搜索关键词

---

## 步骤 7：保存输出

对于逐字稿交付，应保存为画布文本节点，便于用户查看和继续编辑。

有价值的中间文件也要保留：

- 标准化 WAV 音频
- SRT 字幕文件
- JSON 转录文件，如果已生成

不要重复添加已经由工具注册过的媒体节点。工具返回的路径应原样使用。

---

## 失败处理

### 没有音轨

停止并说明：该媒体文件没有音频轨道，无法转录。

### 内置 ASR 失败

兜底顺序：

```text
内置 ASR 失败
→ 检查本地 Whisper 是否可用
→ 如果可用，用标准化 WAV 跑 Whisper
→ 如果不可用，询问是否安装 Whisper 依赖或请用户提供其他媒体文件
```

### Whisper 依赖缺失

明确说明：

```text
本地 Whisper 当前不可用，因为缺少 openai-whisper / torch。主 ASR 已失败；是否允许我安装依赖后再试？
```

不要重复执行同一个失败的安装命令。如果 `pip` 或 `brew` 因网络/DNS 问题失败，应说明具体失败原因，并在再次尝试其他安装路线前征求用户许可。

### 转录质量差

如果转录噪声较多，可建议：

- 上传更清晰的音频
- 先做人声/背景声分离
- 降低背景噪声
- 提供说话人姓名或专有名词表
- 如果 Whisper 可用，改用 `medium`/`large` 重跑

### 语言识别错误

如果输出语言明显错误，应尽量使用显式语言参数重新运行 ASR。

---

## 默认设置

除非用户另有要求，默认使用：

- 音频抽取：单声道、16 kHz、WAV PCM s16le
- 主 ASR：内置字幕生成
- 兜底 ASR：本地 Whisper，仅在已安装或用户授权时使用
- 转录 source of truth：SRT 或 JSON 分段
- 最终可读交付：Markdown 文本节点
- 说话人标注：保守、基于证据
- 文本整理：只做轻度标点和段落优化

---

## 边界说明

- 本技能负责转录和转录稿整理。
- 不负责创作音乐或生成新语音。
- 不保证完美说话人分离。
- 除非用户明确要求且当前工作流允许，否则不把字幕烧录进视频。
- 不应把 Whisper 当作必需主方案；Whisper 是兜底/本地选项。
