# 动效与运镜参考

写分镜（STEP 4–5）和检查转场（STEP 5–6）时使用。把“要流畅”变成代码能执行、检查能验证的决定。目标是让知识短片像一段连续的演示；不要求每个镜头都做形变，也不要求用 3D。

## 1. 镜头卡（分镜中每镜一张）

| 字段 | 填写内容 |
|---|---|
| 新信息 | 观众在这一镜学到的唯一一件事。没有新信息的镜头删掉或合并。 |
| 视觉焦点 | 视线必须停在哪个对象上，起止时它在屏幕的位置。 |
| 景别 | 相对焦点对象的近/中/全（例如硬币特写、图表全景）。 |
| 相机起止与目的 | 两端的世界坐标中心和缩放，以及为什么动：跟随、揭示、对比、停稳供阅读。写明“不动”也是有效选择。 |
| 主体动作 | 主体做什么，按 准备→接触→响应→收势 写（§2）。 |
| 衔接对象 | 带入下一镜的对象 id 及方式（§4），或写“有理由的硬切”并说明原因。 |
| 标签 | 出现哪些标签、相对动作何时出现（§3）。 |
| 阅读停顿 | 是否以刻意停留结束、停多久。 |

## 2. 动作因果

每个可见结果之前都要有可见原因。

- **准备：** 小的预备动作（蓄力、下沉、脚靠近）。
- **接触：** 原因发生的瞬间；此处速度不为零（撞击、推动）。
- **响应：** 结果出现，带轻微过冲或跟随。
- **收势：** 系统到达新状态，然后由别的东西把运动接下去。

在代码里由原因推导结果（推杆位移由踏板角度算出，车轮角度由角速度积分得出），不要各自独立做动画。踏板两秒压完、之后画面只剩文字淡入，就是停滞的片子：响应必须在画面某处继续（压力推进、卡钳合拢、车轮减速、镜头跟随）。

## 3. 错峰与可读

- 主体、镜头、标签错开：主体先动，镜头在一拍内跟上，标签在它所描述的原因之后出现（约 0.1–0.4 秒）。标签不能在结果可见之前抢先宣布。
- 有意允许阅读停顿：完成的图表或结论停留到读得完（一组短标签约 1–1.5 秒）。停顿要事先声明，它不算停滞。
- 图表坐标轴稳定：数据到来前先建好坐标轴，观众阅读时不缩放、不挪动，刻度在目标尺寸下清晰。

## 4. 跨镜连续

- **共同对象 id 与锚点。** 被传递的对象全程用一个 id（如 `sample`、`force`）。在每个镜头边界记录它的世界位置、尺度、方向和速度；下一镜从这些值开始。
- **世界坐标与相机分开。** 对象在世界坐标里；相机是独立轨道（中心、缩放）。“整体平移缩放”是相机运动，不是把每个对象重新摆位。两者分开，才能分别检查对象连续和取景。
- **衔接方式优先级：**
  1. 语义对象接力——同一对象改变含义（硬币→结果点→频率曲线的头部）。
  2. 路径延续——运动沿下一个结构继续（踏板力→推杆→活塞→管路→卡钳）。
  3. 遮挡揭示——前景对象经过，露出下一层。
  4. 匹配切换——切点前后形状/位置相近。
  5. 有理由的硬切——用于强调、新章节或对比；说明理由。
- **避免：** 每段都从零 ease-in、再 ease-out 停下；用整屏淡出淡入当转场；方案里承诺连续，实际却是幻灯片式淡入淡出。

## 5. 两类迁移示例（见 `scripts/motion-kit/`）

**硬币→点→曲线。** 抛硬币（准备：拇指下沉；接触：落到结果槽），一边缩成结果点一边已经开始飘向图表，然后成为累计频率曲线的头部，它的轨迹就是曲线。镜头先跟着硬币向上，再拉远，在点到达之前揭示坐标轴。坐标轴提前建好并保持不动；曲线明显收敛之后才出现 “FREQUENCY → 50%”，随后是声明过的阅读停顿。

**脚→踏板→主缸→车轮。** 脚靠近并接触踏板；踏板角度通过运动学驱动推杆和活塞；一个力的标记沿 踏板→推杆→活塞→管路→卡钳 前进；卡钳夹紧（接触），车轮由积分得到的角速度减慢（响应），镜头追随标记后拉远展示整个系统。压力前沿的速度是**概念示意的节奏，不是刹车液压力的真实传播速度**；观众可能误解时，在片中或报告里说明。

## 6. 工具与检查

`scripts/motion-kit/motion.js`（无依赖，可在 Node 和浏览器中运行）：
- `track(keys)`：带速度的关键帧路径；中间关键帧不写速度时运动会穿过关键帧继续；`d: 0` 表示有意停下。
- `relay(parts)`：让同一对象在多条路径间接力；空档以位置和速度都匹配的曲线衔接。
- `action(spec)`：准备→接触→响应→收势；`stagger()` 标签错峰；`polyline()` 按弧长走路径；`camera()` / `project()` 世界坐标到屏幕；`integrate()` 确定性累积（如车轮角度）。
- `checks`：`continuity`（边界处位置/速度跳变；只有声明的接触点允许速度突变）、`handoffDip`（交接中途停下再起步）、`seekDeterminism`（乱序与重复 seek 得到相同状态）、`stalls`（声明停顿之外画面无任何运动）。

运行 `node scripts/motion-kit/check.js` 检查示例；其中包含一个反例对照，检查器必须把它标出来。打开 `scripts/motion-kit/preview.html?scene=coin` 或 `?scene=brake` 按目标帧率观看（加 `&t=` 定格）。

局限：这些检查是关于状态的数值证据，不能证明画面看起来顺滑。确定性以 `state(t)` 为准；Chromium 对页面上第一次绘制的虚线或模糊描边可能有轻微不同的抗锯齿，细小的亚像素差按容差记录，不要用长时间预热渲染去掩盖。每帧重置全部画布状态（透明度、虚线、字体、变换）。

## 7. 检查流程（适度）

1. 先找风险区间（交接、镜头反向、3D↔2D 切换），通常每段 2–4 秒。
2. 按目标帧率连续观看这些区间（短片段或预览页），不能只看静帧。静帧和数值测试不能用来声称视觉顺滑。
3. 必须局部修复：位置/尺度/方向明显跳变；承诺连续却停下再起步；残留阴影或旧 3D；计划中的连续交接变成幻灯片式淡入。只修受影响区间并复查，再渲染全片。
4. 不可用的修法：延长片长、加更多文字、改帧率、强行固定镜头数。
5. 不破坏连续和阅读的小瑕疵（标签稍早、次要元素淡入偏软）记录即可，不反复迭代。

## 8. 声音

保留指定 BGM 作为底。只在发生物理事件处加稀疏、低音量的音效：接触、释放、揭示。不要给每个镜头运动或转场都加 whoosh。
