# Vibe 知识短片

当用户希望把一个知识主题制作成带音乐、可验证、可编辑的代码生成讲解片时使用本 Skill。常见输入是一句话主题，也可以附带参考片、资料或指定音乐；交付可播放 MP4 与可编辑项目。不要暗示只靠文字就能渲染成片，应使用可用的本地渲染与编码环境。

## 固定参考与素材纪律

当项目采用参考片的表达语言时，先读取 `references/reference.md`；写镜头卡、对象接力、运镜和检查转场时读取 `references/motion-camera.cn.md`。只借鉴具体实验、克制的编辑式排版和解释性运动，不复制作者署名、标题、文案或历史顺序。

音乐使用本项目已提供或确认、适合预定发布用途的音轨，或遵循无音乐要求。本 Skill 不分发参考片音轨，旧项目的选择不作为新用户默认。复用所选音轨的有效分析，不从文件名推断内容；在方案中说明适配当前时长的音乐窗口。不擅自替换、变速或循环短音频来填满长片，缺失或不适用时在渲染前说明。

## 固定执行顺序与阶段门禁

以下七步是必经顺序，不是可选建议。不得因为想加快执行、沿用示例或已具备渲染能力而跳过。已完成且仍有效的步骤可复用证据，不重复询问或执行；已有信息不等于未展示方案的批准。

在项目文本记录中维护：当前步骤、已确认规格及其用户来源、创意方案版本与批准记录、预览/验收证据、未解决事项。每次进入下一步前核对门禁；条件未满足时说明缺项并停在当前步骤，不得把“推荐”当作用户确认，也不得用后续产物倒填确认记录。此记录只用于本 Skill 的执行连续性，不另建多阶段生产计划。

### STEP 1：主题与核心问题

接收一句主题、文案或参考资料，提炼本期要回答的一个问题。不编造年代、人物、引文或历史关系，不先做完整分镜或渲染。

**通过条件：** 主题和核心问题清楚；确有歧义时只补问必要信息。

### STEP 2：一次收齐制作选项

优先从本轮请求和已确认上下文提取信息，在同一轮选择中补齐尚未明确的项目，不重复问已回答的问题。

- **时长与交付模式：** 20秒测试样片、30秒、60秒、90秒、120秒或自定义。没有偏好时推荐60秒，但需用户接受；20秒是时长，不自动等同于测试模式，另记录是测试还是正式成片。
- **发布平台：** 抖音/快手、视频号、小红书、B站/YouTube或自定义用途。多平台需选一个主版本，列明用户真正需要的独立适配版本，不自动扩增交付数量。
- **语言与讲解方式：** 确认观众语言，选择配音、讲解字幕或仅图表短标签。配音和字幕分别记录；配音不自动开启字幕，未请求的字幕默认为关闭。
- **音乐：** 沿用本项目已确认的音轨；否则与其他制作选项一起确认用户提供或具有适用授权的音乐，或无音乐方案。记录选择和权利来源，文件存在本身不代表可发布。

**通过条件：** 时长、平台/用途、交付模式、语言、讲解方式和音乐方案已明确。用户明确说“按推荐”可接受本轮已展示的具体推荐，不能授权尚未展示的未知选项。

### STEP 3：推荐画幅与尺寸，确认规格

根据平台和知识图表复杂度展示推荐及理由。这是制作建议，不是平台唯一上传规格。

| 发布场景 | 推荐画幅与正式尺寸 |
|---|---|
| 抖音/快手/视频号竖屏信息流 | 9:16，1080×1920 |
| 小红书竖版笔记 | 3:4，1080×1440 |
| B站/YouTube横屏 | 16:9，1920×1080 |
| YouTube Shorts等竖屏短视频 | 9:16，1080×1920 |

全幅多曲线、并列概率分布等复杂图表应解释横屏优势；若用户选择竖屏，应重排对象、坐标轴、标签和比较顺序，不能裁切横屏或把整图缩得无法阅读。用户自定义规格优先；发现技术限制时先说明再请用户选择，不能静默降级。正式成片帧率推荐30fps；测试可推荐24fps，但都应展示并记录。

步骤2与3可在同一轮收集与确认，但逻辑上先有平台/内容依据，再给出尺寸推荐。呈现一份简短规格摘要，包含时长、平台、模式、画幅、像素尺寸、帧率、语言、配音/字幕和音乐方案。

**通过条件：** 用户已指定或明确接受具体规格。已明确给出的规格无需再确认；缺任何影响执行的规格时，不进入创意方案制作。

### STEP 4：核实知识并确认创意方案

使用可靠一手或权威资料，将来源对应到主张；重新计算关键结果，区分定理、模拟、近似和视觉比喻。只讲一条主线，不照搬参考片的历史顺序。

向用户展示简短方案：回答什么问题、用什么实验/图表、开头到结论的叙事、按确认时长分配的段落、连续对象转场（每次交接由哪个对象 id 带过去，或硬切的理由）、音乐节点及已选讲解方式。每个主体场景须展示采样、分支、累积、收敛、传播或比较等可观察过程，不用粒子配大段文字替代解释。优先复用音乐分析，不猜BPM或机械每拍换镜头。

**通过条件：** 用户明确批准当前创意方案。展示后停下等待，不把选择时长/尺寸、“做个视频”或此前方案的批准当作本方案批准。用户已提供并明确批准的完整方案可以复用；不增加逐镜审批。

### STEP 5：编写代码并检查关键部分

按批准方案生成固定随机种子数据、详细分镜与源码。图表和排版优先Canvas/SVG，仅在空间形态有解释作用时用3D。以绝对时间驱动，保证同一帧可复现。

每镜写一张镜头卡（`references/motion-camera.cn.md` §1）：新信息、视觉焦点、景别、相机起止与运动目的、主体动作（准备→接触→响应→收势）、衔接对象 id、标签时机和阅读停顿。世界坐标与相机分开；在每个镜头边界记录被传递对象的位置、尺度、方向和速度。衔接优先语义对象接力、路径延续、遮挡揭示、匹配切换；有理由的硬切可以用。不要每段都从零 ease-in 再停下，不用整屏淡出淡入当转场；不强制全片形变或3D。`scripts/motion-kit/` 提供绝对时间的 `track`/`relay`/`action`/`camera` 工具和检查（`node scripts/motion-kit/check.js`），含两类迁移示例（硬币→点→曲线；踏板→主缸→车轮）；压力或信号的示意传播不得冒充真实传播速度。

先验证核心实验、目标尺寸下图表可读性与坐标轴稳定、高风险交接与运镜、遮挡、残影及随机跳帧一致性；预览结果和分析证据能复用就复用。中间帧和日志不得自动上画布。

检查要适度，但对运动要诚实。以下情况必须拦下：知识错误、关键文字看不清或重叠、渲染缺失或损坏、核心实验看不懂，以及这些转场问题——位置/尺度/方向明显跳变、计划连续却停下再起步、残留阴影或旧3D、承诺连续交接却做成幻灯片式淡入。局部修复：先按目标帧率连续观看2–4秒的风险区间，只修受影响区间并复查，再看全片。静帧和数值检查不能用来声称视觉顺滑。不能靠延长片长、加文字、改帧率或固定镜头数解决运动问题。标签稍早、次要元素淡入偏软等小瑕疵记录即可，不反复迭代。在保留的BGM之上，只在接触、释放、揭示时刻稀疏加音效，不给每个运动都加 whoosh。

**通过条件：** 关键部分检查通过并记录证据，且无未解决的知识或显示错误。用户未要求预览审批时不额外增加确认；已要求的审批必须等待。检查无法完成时说明边界并停下，不能虚报通过或直接全片渲染。

### STEP 6：渲染与验收

严格按已确认规格渲染并检查知识、图表、声音、完整解码、时长、画幅和帧率。只修受影响部分，不因局部失败重跑已有效的工作。

**通过条件：** 实际导出媒体和验收证据均可用。仅授权测试时只制作并交付测试样片，之后停止；正式成片已获授权且创意已批准时，预览通过后直接完成正式渲染，不重复问是否开工。需改变已确认时长、平台、画幅、语言、音乐、交付数量或创意方向时，先说明影响并由用户决定，回到受影响的最早步骤复核，只重做失效部分。

### STEP 7：交付与停止

交付MP4、可编辑源码、重渲染说明、知识来源、数据与音乐时间点。保留可替换的数据、字幕（如有）和音频映射。画布只放最终样片或成片；源码和报告作为项目文件交付。

**将最终 MP4 放入当前项目可用的媒体展示区**，核实能打开和播放；只展示最终作品，同片修正可在支持时归为该作品的新版本。宿主无法展示时，交付真实可播放文件并明确限制。源码和报告保留为项目文件，不把中间帧当作最终交付。

**通过条件：** 最终 MP4 可通过项目展示或交付文件实际播放，说明检查结果及任何限制。测试样片交付后不能自动升级为长片；额外画幅或平台版本必须有明确请求。技能验证、提示词讨论或文件修订请求不是视频制作授权，不启动此生产流程。

## 视觉基准

黑金是默认视觉风格，不是能力边界；用户明确指定的视觉风格优先。

- 近黑背景、温暖象牙白文字、香槟金重点，暗红只用于明确的反例或警示分支。
- 使用克制的衬线编辑式排版、留白、细线和微弱光晕；避免通用网页卡片、巨大装饰字和无理由的霓虹。
- 字幕要短，保证观众能同时阅读和观看实验；在手机尺寸检查图表标记、字幕和来源是否遮挡。
- 年代、人物和角落来源只在有助于解释时出现，不仿冒参考作者的署名或标志。
- 保持视觉语言统一，但必须为新主题重新设计对象。概率片可以使用硬币、采样和分布；神经网络则应展示连接与信号。

## 必须通过的验收

- 主张与模拟、来源一致，不编造引文或历史细节。
- 每个重点概念至少有一次直观演示，字幕不是全文口播稿。
- 字体正常显示；图表标签、刻度、边界正确，无溢出和遮挡。
- 时长、画幅、帧率、帧连续性和音画同步正确。必须检查实际渲染表面和导出文件，不能只相信命令行参数。
- 导出的 MP4 确实包含目标音频，不能只确认项目里存在音频文件。
- 结尾留出音乐余韵，不在句子或乐句中间硬切。
- 对连续形变转场，检查对象连续性、全幅图表可读性、无意外3D残留或透明缓冲拖影，并验证随机跳帧结果确定。

## 开发 draft 与正式成片

不再默认两分钟或横屏。严格沿用步骤2–3确认的时长、平台、画幅、尺寸与交付模式；没有时长偏好时仅推荐60秒，仍需用户接受。开发测试可推荐20秒、24fps，输出代表性关键帧与一个样片。低分辨率draft必须保持已确认画幅，展示具体尺寸并获接受后才渲染：例如16:9为1280×720、9:16为720×1280、3:4为720×960。正式成片使用已批准的正式尺寸，不得用draft参数静默替代。仅授权测试时样片完成即停止；正式制作授权也不能跳过创意方案批准与技术预览检查。

Draft 必须覆盖开场、核心实验和结论，不能只截取铺垫。保留用户指定的音乐窗口，并记录裁剪、增益变化或重新编码。复用已验证的数据、字体、依赖和音乐分析。

验证实际 Canvas/WebGL 尺寸、draft/final 状态、时间映射和导出媒体。缓存键应区分尺寸、fps、模式、源码/数据指纹和场景映射版本。如果渲染器只检查图片尺寸，源码修改后必须使用新缓存目录，不能把旧帧缩放后冒充原生输出。只补缺失或损坏帧；场景修改后只失效受影响时段；先测试最慢段再增加并发。

对于连续形变图表序列，要让解释对象连续变形，而不是切换成互不相关的小卡片。全幅图表必须保留可读的坐标轴、标签、基线、刻度和结论，并持续足够时间。当3D对象交接给图表时，要在图表时段明确隐藏3D对象并清理相关缓冲；检查多个时间点和随机跳转。

## 复用已有音画分析

优先使用已有的媒体事实、语义分析和用户已验收的关键帧检查作为证据。不要为了重复确认已经接受的转场而再次分析图像，尤其不要使用可能自动创建画布关键帧的分析路径。只有出现新参考、缺少尺寸/时长事实或存在未解决视觉问题时才重新分析。用户明确要求不要再分析时，应依赖已有证据，并诚实说明验证边界。

## 画布与项目卫生

画布只放用户需要直接查看的最终媒体，以及用户明确要求的少量单张预览。逐帧序列、接触表、调试截图、源码、JSON、中间音频和验证日志都保存在项目目录。Draft 通常最多放一个样片，正式交付通常只放一个最终视频。不要批量导入调试帧，也不要使用会自动生成关键帧节点的分析路径。

## 复现示例

以下命令仅供已批准的横屏20秒测试，在 `scripts/sample-project` 中运行；不是工作流默认值，不能绕过门禁。采用其他规格前，必须按确认规格调整脚本与布局。

先准备 Python 3.9+ 和独立环境。`scripts/sample-project/requirements.txt` 声明了 Playwright、Pillow、NumPy、SciPy 与 imageio-ffmpeg；Chromium 需要单独安装。渲染前运行依赖预检，检查模块导入、Chromium 可执行文件与 FFmpeg 可用性，不生成媒体；预检不代表浏览器系统库或输出质量已经通过验证。

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python tools/check_dependencies.py
```

运行下面命令前先提供本项目获准使用的真实音轨。`music/approved-track.m4a` 只是示例路径，不是随包文件：将获准音轨放到该位置，或将命令中所有同名路径替换为实际路径。确认所选音乐窗口在本例中至少覆盖20秒，不擅自循环或拉伸短音轨。针对真实音轨重新生成 `music/music_map.json` 并检查测量时间点；随包历史分析不能证明当前音轨的节奏或发布权限。这组音频命令不实现无音乐交付；获准制作无声项目时须调整编码与验收逻辑。`tools/verify.py` 仍保留历史样例的1920×1080、30fps检查，验证下面1280×720、24fps的draft前须按规格调整。

```bash
python tools/check_dependencies.py --track music/approved-track.m4a
python tools/analyze_music.py music/approved-track.m4a music/music_map.json
python3 tools/render.py frames --start 0 --end 20 --fps 24 --width 1280 --height 720 --workers 2 --draft --out frames/draft20
python3 tools/encode.py --frames frames/draft20 --start 0 --end 20 --fps 24 --track music/approved-track.m4a --audio-start 0 --out out/draft20.mp4
```

编码后将最终文件放入项目可访问的交付位置并核实播放，再报告交付。

`scripts/sample-project` 只是参考实现，不代表未来主题必须使用相同的时长、音乐窗口、数据模型或镜头布局。通用规则保留在 Skill 中，一次性测量数据应放在项目报告里。
