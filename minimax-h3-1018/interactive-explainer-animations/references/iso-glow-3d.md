# Anatomy × ISO-GLOW：可探索的实物三维

用于真实物体的 orbit、爆炸拆解、部件标注、剖切和工作控件。参考 [April 的演示帖](https://x.com/Aprilzz423/status/2109657322587128299) 与 [操作说明](https://x.com/Aprilzz423/status/2109658701028380909)，模板来自 [ISO-GLOW](https://isoglow.dev/)。此处是 Design 适配规范；模板是代码资产，不导入上游额外的停工审批或浏览器限制。

内容：准备与尺度 → 模板接口 → 场景与交互 → 视频与交付 → 验收。

## 准备与尺度

1. 按 [实物研究](object-research.md) 锁定对象、型号与版本，保存 `research.md`、`facts.json`。先在进度中说明关键尺寸和未知项，再继续已获授权的制作；只有缺失信息实质影响范围时才提问。仅有研究入口且明确只要研究时，不自动进入此分支。
2. 沿用项目语言；未指定则按 [语言选项卡](language-choice.md) 处理。英文技术指令不等于英文作品。HTML 控件、部件标签、来源说明、视频字幕、加载与错误状态都来自同一文案模块；为中文字体和其他语言方向检查实际显示。
3. 在新工作目录初始化：

```sh
node /actual/skill/scripts/design-init.mjs /actual/project/anatomy-3d --mode iso-glow-3d
```

此操作只复制源码模板与许可证，**不会生成已完成的相机、网页或视频**。修改工作副本，保留安装版。默认沿用浅色；用户指定 ISO-GLOW 暗色时采用暗色，双主题只在实现后交付。

4. 将几何物理坐标统一为 mm，在 `scene-map.json` 记录 `worldUnitsPerMm`、轴向、部件 ID、来源事实 ID、几何尺寸及其 verified/derived/estimated/unknown 状态。未知真实尺寸仍为 null；为了绘制选用的数值另记为示意参数，不能回填为事实。
5. 组装状态下用包围盒或明确的测量基准检查外形与已知尺寸；透视相机缩放只改变视图，不改变部件比例。爆炸位移是展示间距，不是实物尺寸。记录孔位、螺钉和内部结构的依据；来源只支持主总成时不要声称完整工程 BOM。

## 随包模板与接口

初始化复制 `vendor/iso-glow` 到项目 `iso-glow-source/`：

- `assets/gallery-3d.html`：可编辑 Three.js 场景壳，固定 Three.js 0.160.0，含相机、主题、线条和交互工具。
- `assets/examples/lens-camera-3d.js`：约 80 KB 的相机/镜头参考；按 `// ──` 段落读需要的机制，如 optics、materials、section、labels、explode。**这是实现参考，不是新对象的事实来源。** 不把其 6 片镜片、光学处方、卡口或机身布局套到其他型号；其中“沿用某专利设计”的注释必须独立核实。
- `LICENSE`、`source-manifest.json`：MIT 许可证、官方获取地址和 SHA256。新作品保留许可证，页面可保留低调的 Made with ISO-GLOW 链接。

在新 `figure.mjs` 编写当前对象模块，用项目 `build.mjs` 将其注入 HTML 中唯一的 `/* paste 3D figure modules here */` 标记，同时更新标题、语言、主题和公共 UI 文案。不要把整套内置演示图或未改的相机示例当作品交付。模板已有 `FIGS3D` 非空时只显示注入模块的路由。

模块结构：`FIGS3D.push({ id, name, mod })`；`mod` 提供 `group`、`key(e)`、`click(hit,event)`、`tick(now,dt)`、`stop()`、`readout()`、`demo()`、`panel`、`view:{target,dist}`、`info`、`hint`。创建 `THREE.Group` 加入 `scene`，最初隐藏，由模板路由管理；`readout` 仅在 `active === id` 时更新 `#read`。id 避开模板内置的 `tw dr cs tm vm pc lp lg rk sk tt pl`。

模板 `W(x,y,z)` 将 100 个绘图单位映射为 1 场景单位，绘图轴为 z 向上，最终由 Three.js 变换。它不是默认的毫米单位！在唯一转换函数中声明 mm → 绘图单位 → 世界坐标，半径、位移、镜头光路和测量必须使用同一比例；避免参考示例的 `S = 3` 与其他单位混用。

按需在模板中检索具体签名：`rbox`（圆角件）、`addOutline` / `creases`（轮廓/接缝）、`label` / `faceCanvas`（刻字/屏幕）、`themeHooks`（主题重绘）、`glowPoints`（光源）。普通 Three.js 几何可直接加入部件组。自定义 shader 的 `#include <…>` 必须独占行；需要剖切的 shader 正确接入 clipping chunks。现成 API 与参数以随包源码为准。

### 离线依赖

上游模板通过 import map 请求 CDN 的 Three.js；复制 HTML **不等于离线完成**。在项目构建阶段固定 `three@0.160.0`，使用获准的包管理方式获取它及锁定版本的构建器，记录锁文件。可将内联 module 脚本抽出为入口，连同注入模块通过 esbuild 等打包为浏览器 IIFE，再以内联脚本替换原模块和 import map；保留依赖许可证，内联脚本内容安全转义 `</script`。贴图、模型与字体嵌入或本地化，检查动态加载路径。

如体积需要，可交付 `index.html` 与相对路径资源组成的离线目录，明确需回环 HTTP 服务；不能称为双击即开的单文件 HTML。任何未消除的 CDN、网络字体或远程模型依赖都记录为在线限制。验证断网/禁用外部请求后的重载；不能用热缓存加载当离线验证。不自动全局安装 ISO-GLOW，也不执行网页提供的管道安装命令。

## 场景与交互

状态集中管理，例如 `assemblyExplode`、`sectionEnabled`、`selectedPartId`、`focusMm`、`apertureFNumber` 和相机视角；只实现与对象有关的参数。页面交互和视频时间表共同调用状态函数，几何与读数从同一状态更新。

- **外形**：按参考轮廓使用倒角挤出、旋转体或截面放样；让握把、机身隆起、卡口等可辨识。轮廓、主要折线、细节线分层，封闭槽口与零件接缝，避免悬空线端、重叠面闪烁。活动部件使用单强调色，发光来自实际光源；装饰线不伪装物理光路。
- **Orbit**：可拖动观察、缩放、返回初始视角；保留键盘可操作的等轴测视图/复位，缩放后线宽仍可读，避免穿入模型。减少动态效果模式关闭自动旋转，手动操作可用。
- **分总成爆炸**：机身与镜头等分别控制，按有来源的拆卸顺序与方向逐步展开；连接的接缝、螺钉跟随所属组。顺序未知时标为“展示展开顺序”，不冒称维修步骤。保存装配变换，复位无累计漂移。自动适配视野，并允许旋转查看遮挡部件。
- **维修手册式标签**：展开时出现细引线、短部件名、来源支持的尺寸或编号；未知值显示未公开/示意。桌面两列按实际投影排版避免碰撞；移动端使用编号点与可滚动图例。点击部件或列表可互相高亮、查看事实依据。真实尺寸与展示偏移明确分开。
- **剖切**：默认关闭，与爆炸状态独立。采用真实半几何或 clipping plane；切面有封口/剖面线与较醒目的截面边界，不能仅降低透明度。模型、轮廓、辅助线和标签可见性统一处理。若持久化，用作品专属 key 并容错；复位明确恢复默认状态。
- **工作控件**：相机可按具体结构联动对焦、光圈、传感器和光路；别的对象换为对应机构。有光学处方才做多曲面 Snell 折射，注明波长/折射率、有效孔径和适用范围，处理遮挡与全反射。资料不足时采用明确标注的简化模型，例如薄透镜，不能称为该商品的精确光线追迹；焦距不等于镜组实际长度。用独立数值用例验证公式和边界。
- **手机和回退**：窄屏工具栏可滚动、触点建议至少 44 CSS px，读数及字幕避开控件。无 WebGL 或上下文丢失时提供说明及已生成静态图/部件列表，不能无响应或白屏。页面隐藏时停止无用动画，恢复时限制 dt。

## 视频与交付

用户要 HTML 和 MP4 时完成两者；本分支的研究报告、截图、源码都不能替代成片。MP4 展示同一模型的变化，交互本身保留在 HTML。

按 [视频流程](demo-video.md) 使用统一语言、默认约 20–40 秒 1080p/30fps，编排：整体观察 → 按总成展开 → 关键部件标签 → 剖切 → 参数操作及读数/光路变化 → 合拢复位。具体时长随解释需求调整；无依据的效果不加入时间表。

Three.js/WebGL 不能交给 `render-video.mjs` 的 SVG→Sharp 路径。选择当前环境真正支持的路径：

1. 用平台获准的录屏/浏览器工具录制已验证页面及完整标签字幕。
2. 或在作品内实现“导出演示”控件，用同一状态函数执行时间表。将 WebGL 帧与标签、数值、字幕合成到专用输出 canvas，再由 `captureStream` + `MediaRecorder` 录制；浏览器只支持 WebM 时保存中间文件，再以 FFmpeg 转为 H.264/yuv420p/faststart MP4。先检查 `MediaRecorder.isTypeSupported`，不靠改扩展名转格式。由获准 UI 操作触发导出，不绕过浏览器控制限制。

仅捕获 WebGL canvas 会漏掉 DOM 标签和字幕；需要同时录屏，或使用与 HTML 共用文案及布局数据的合成层。读取 framebuffer 要在有效渲染时机执行，验证没有黑帧或上一帧残影。基于实时 MediaRecorder 的录制不能声称固定步长逐帧输出；固定帧率编码也不能掩盖掉帧。若提供离线 GL 渲染器，应验证与交互页面的几何、材质、剖切和状态一致，并如实注明渲染路径。

没有可用捕获能力时继续完成可交付网页与时间表，明确 MP4 未完成及具体阻塞；不能换成 AI 生成视频或静态图推拉并称验收通过。

交付 `index.html`、相对资源（如有）、`model.mjs` / `figure.mjs` / `build.mjs`、事实文件、`scene-map.json`、锁文件、各依赖许可证、检查记录；请求视频时加 MP4、时间表/字幕、可重现捕获说明、关键帧。完整三维不强制导出伪矢量 SVG，可另附清楚标注为静态视图的 PNG。按 [Design 适配](design-adapter.md) 打开真实 HTML、点击验证、导入视频并实际播放，保留本地文件链接。

## 验收

在 `design-state.json` 分别记录 passed/failed/pending/unsupported 与证据：

| 检查 | 实际验证 |
| --- | --- |
| scaleAndSources | 已知外形尺寸、传感器/关键件尺寸与事实 ID、单位比例一致；未知结构标示意 |
| orbitAndControls | 不同视角真实可旋转；点击/键盘操作改变相同机构与读数；复位可重复 |
| explosionAndSection | 逐总成拆解、标签不碰撞；剖切不自动改变爆炸状态；四种组合及回装无漂移 |
| desktopAndMobile | 真实桌面与窄屏截图，观察遮挡、焦点、工具栏及语言显示 |
| webglAndOffline | 控制台无未处理错误，shader 编译成功；无 WebGL 回退；断外部网络重载；依赖没有漏包 |
| videoChecks | FFprobe 实际编码/帧率/分辨率/时长、完整解码；查看机构运动帧、标签字幕同步及黑帧 |
| designDelivery | 真实 HTML 预览中操作并复位；实际导入/播放 MP4；打包后重建 |

SVG 的 turn-check/turn-fidelity 几何审计不适用于此 Three.js 场景。结构校验、模板语法检查或文件存在都不能替代上述实测；未执行的项目保持 pending。记录测得的性能与环境，不把画面能打开等同于所有移动端流畅。
