# HTML 与视频的统一语言选择

## 何时显示

制作新作品、写最终用户可见文字之前确定语言。同一项目已有明确的用户语言指令或卡片答案时记录并沿用，不重复询问；用户要求沿用既有作品语言也算明确选择。中文聊天本身不等于选择中文，参考材料的语言也不替代输出语言。

缺少明确选择时，显示一个**单选语言选项卡**，标题为“请选择作品语言（统一用于 HTML 界面、图解文字和视频字幕）”，选项：

- **中文**：默认简体中文，`zh-CN`；用户指定繁体或地区变体时沿用。
- **English**：英语，`en`；用户指定地区变体时沿用。
- **其他**：继续询问“请填写具体输出语言，例如日语、法语、阿拉伯语”，接受自由输入，确定实际语言后才能开始制作。

卡片提问可随对话语言本地化；保留这三个选择的含义。“其他”不是一个输出语言，不能直接写入 HTML lang 或字幕。用户直接输入具体语言也视为有效选择，无需先点击“其他”。只更新 skill、阅读文件或讨论方案时不显示该卡，也不改动已交付作品的语言。仅进行实物研究、交付研究报告时也不弹作品语言卡，报告沿用用户明确语言或对话语言；继续制作 HTML/SVG/视频时再按本规则选择。

## 平台实现

优先使用当前 Design 环境真实提供的通用单选卡工具，先读实际 schema，再映射上述标题和选项。不要虚构工具名，也不要调用无关的 onboarding 或审批工具模拟语言卡。

若提供 `functions.request_user_input_async`，可使用：

```json
{
  "questions": [{
    "title": "请选择作品语言（统一用于 HTML 界面、图解文字和视频字幕）：",
    "options": ["中文", "English", "其他"]
  }]
}
```

选“其他”后用自由文本问题收集具体语言；若对方随选择已填写语言，不再追问。某些组件自动提供 Other/自由输入时，映射该内置入口，不添加重复选项。当前环境没有卡片工具时，明确说明只能文字选择，列出相同三项并等待，不能声称已展示卡片。

工具返回“已呈现”、UI 预选、空答案、取消或超时均不代表用户选择。等待期间可检查依赖、研究原理、编写纯模型及无文字几何；带文字的作品及视频保持待选，不自行选中文。有效用户答案到达后持续完成后续制作，不增加逐阶段确认。

## 项目记录与共用文案

在 `design-state.json` 的 `outputLanguage` 保存：

```json
{
  "status": "pending",
  "choice": null,
  "locale": null,
  "label": null,
  "direction": null,
  "source": null
}
```

`status` 使用 `pending`、`awaiting-other`、`selected`；`choice` 使用 `zh`、`en`、`other`。确定语言后写实际 BCP 47 标签、可读名称、`ltr`/`rtl` 与用户消息或卡片答案来源。例如选择 English 后为 `selected / en / en / English / ltr`。保留用户原话来源；无法判断具体语言时询问，不猜 locale。该设置作用于本项目 HTML、SVG、视频、字幕及新增作品说明，不自动改变对话语言。

将作品文案集中在同一 `copy`/`i18n` 数据模块，HTML 构建和视频场景共同读取，避免两份硬编码文案。统一标题、按钮、提示、图例、状态、错误消息、可访问名称、视频章节及字幕；专名、公式、单位和代码标识保持准确，不将显示翻译用于模型判断。项目模型输出语义键或结构化数值，由语言层生成可读文案。

HTML 设置正确的 `lang` 和 `dir`；SVG 文字与可访问描述同样使用所选语言。视频烧录字幕、可选 SRT 和时间表来自同一语言版本，按该版本重新计算换行和阅读时间。默认仍无旁白；若用户另行要求旁白，也沿用所选语言。选择“其他”后验证实际字体覆盖、连写、双向文字和排版；遇到缺字或不支持的文字系统先解决渲染支持，不能悄悄换成中文或英文。

## 验收与语言变更

在真实 HTML 初态、操作后状态、手机窄屏和编码后视频关键帧中检查语言一致性、缺字、截断和字幕时长；只验证过的语言才报告通过。源码示例的英文/中文不能被当成项目默认语言。

用户后续更改语言时更新项目记录与共用文案，重新构建 HTML/SVG、字幕和视频，并复核布局；保留原版本，清楚标识新版本。不要只翻译 HTML 而继续交付旧语言 MP4。默认制作单语言作品，不擅自增加网页运行时语言切换器或导出多语版本。
