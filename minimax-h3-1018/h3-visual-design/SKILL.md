# H3 Visual Design

主文件只判断视觉技法，不承载具体风格配方；确定路线后按需读取对应 reference，由该 reference 完成设置、Prompt、生成和交付规则。

## 1. 触发条件

当用户要交付以下任一类聚焦的动态视觉技法时，进入本 Skill：

| 属于本 Skill 的意图 |
| --- |
| 直接生成动态字体或包装片，或给人物、产品、Logo、场景、口播或原片加入动态字体、标题、卡片、图形、字幕、标志处理、材质纹理或 AE 感版式。结果可以包含用户指定的准确文案、根据事实整理的文案、口播字幕、跟随主体的文字，以及主体与周围空间之间的设计化转场。 |
| 制作 TD / TouchDesigner / CV 追踪视觉，把主体被系统感知的数据显性化，例如追踪框、角标、拓扑线、点云、数字编号、扫描网格、局部负片、颜色反转、调试叠层或 AI 感知视角。画面应明确跟随人物、物体或场景，而不是泛化的抽象特效。 |
| 让真实生活空间或真人表演与二维手绘、涂鸦、蜡笔或粉笔动画产生可见的接触和互动，例如手绘物件进入房间、环绕人物、响应动作，或在实体与手绘状态之间连续变形。 |

判断依据是用户要交付的核心结果。如果需求的核心是另一类最终交付物，说明它超出本 Skill 的边界并结束本 Skill，不指定其它 Skill 或 workflow；不因单个关键词扩大本 Skill 范围。

## 2. 路线选择

| 主导意图 | 路线 | 必读 reference |
| --- | --- | --- |
| 给人物、产品、Logo、场景、口播或原片加入动态字体、标题、卡片、图形、字幕或 AE 感包装 | `typography-packaging` | [typography-packaging.md](references/typography-packaging.md) |
| 制作 TD / TouchDesigner / CV 调试视觉、追踪框、拓扑线、数字 ID、局部负片或“AI 看见的世界” | `td-cv-tracking` | [td-cv-tracking.md](references/td-cv-tracking.md) |
| 制作真人生活空间与二维手绘、涂鸦、蜡笔、粉笔动画融合的视频 | `handdrawn-live-action` | [handdrawn-live-action.md](references/handdrawn-live-action.md) |

明确出现 TD/CV 或手绘融合意图时优先进入对应路线；其余动态字体、Logo、口播和素材包装进入 `typography-packaging`。不要因为“炫酷”“特效”“视觉感”这类弱信号猜路线，缺少决定性信息时只询问一次用户想使用哪种表现技法。

一个任务默认只读取一条路线。用户明确要求组合两种技法时，先确定主路线，再只补读另一条相关 reference；不得预读全部路线或把三套规则拼进同一 Prompt。

`typography-packaging` 路线只询问缺失的成片画幅和时长。风格与文字优先采用用户要求；未提供时基于已有事实构思并直接展示，不追加确认轮次。其它内部默认设置遵循该路线 reference。

## 3. 共同执行约束

1. 在本 Skill 内一次连续完成执行，不允许后续环节重新设计已经确认的方向。
2. 只读取所选路线明确要求的 references；路线 reference 是具体问询、Prompt 结构、生成方式和完成条件的真相源。
3. 只使用真实存在的附件、已有素材和用户事实；不得虚构素材路径、品牌、文字、人物身份或参考关系。
4. 保留用户明确指定的模型、时长、画幅、主体、文案和声音要求；只询问会阻塞所选路线的缺失信息。
5. 路线生成最终 Prompt 后，展示给用户的 Prompt 与实际用于 H3 生成的 Prompt 必须字符级一致；任何后续环节不得摘要、翻译或二次改写。
6. 具体路线的硬规则优先于本主文件的通用规则；路线未通过自身完成检查时不得交付。
