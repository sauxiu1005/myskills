# Blender 产品广告

以同一完整产品母模型支撑所有镜头。主链路为 **资料 → Product Evidence Analysis → PRODUCT_MASTER → 产品验证 → 广告分镜 → Shot Asset Check → 必要补建 → Camera/Animation/Text UI → 低清预览与迭代 → Blender 渲染与工程交付 → 4 张广告关键帧 → 关键帧 + Blender 视频驱动 MiniMax H3 成片**。收到制作请求后实际执行，不以方案或脚本代替视频成品。

核心执行为 Codex + Blender + bpy/Blender CLI。Blender MCP 仅为已验证可用时的可选接口；Computer Use 仅在需要界面观察、播放或交互检查时使用。Blender 完成可编辑产品与运动底片后，按第9–10步进入广告关键帧与 MiniMax H3 后期生成。不得加入新清士或擅自引入 GPT Image 等其他生成服务；关键帧美术默认用 Blender 渲染、文字与合成完成。无需更换 Codex 模型或购买指定订阅。

## 1. Product Evidence Analysis：先理解证据

读取 [证据与建模规则](references/product-evidence.md)，用 [产品简报](templates/product-brief.md) 和 [假设报告](templates/assumptions-report.md) 整理输入。

- 接受任意一种或多种资料：多角度图片、实拍图、结构图、尺寸图、草图、产品网页截图、说明书、文字描述、品牌资料、Logo。STEP/STP/FBX/OBJ/GLB/BLEND 都是可选输入，不能因没有 3D 文件要求用户补交模型。
- 标记每项信息为资料支持、推断、缺失或冲突；记录来源页码/图片区域/原文位置、适用版本、可信范围。用户文字可作为用户提供的设计规格，但不称为已测量实物。
- 对建模必须但不关键的缺失项自行合理补全，记录采用值、理由、影响对象和可见镜头、替换方法；未知尺寸使用明确声明的暂定尺度。不能把比例估计称为精密测量。
- 只有缺失信息直接影响关键结构或功能真实性，且不能安全补全时，才询问具体问题；同时继续无关部分。不要以常规倒角、隐藏面或美术取舍为由反复请求批准。用户要求确认的节点则等待明确回复。
- 已有 3D 文件优先导入、检查和修复；保留原件。STEP 先核实可用 CAD 转换，不假定 Blender 原生支持。某文件不能导入时，仍可利用其他已提供资料推进，不将格式问题变成必须提供模型的门槛。

## 2. 建立完整 PRODUCT_MASTER

先确认实际 Blender 运行路径与版本，按 [执行说明](references/execution.md) 使用 bpy。无模型时由 Codex 编写并执行建模脚本：统一坐标和尺度 → 完整外形与装配 → 主要部件 → 可见接口/控制件 → 材质与 Logo。有模型时导入修复，避免无理由重建。

保存 `PRODUCT_MASTER.blend`，包含语义化 `PRODUCT_MASTER` 集合及 `BODY`、`BUTTON_*`、`KNOB` 等实际存在的部件。完整指产品整体可辨识、外部结构完整、主要装配关系成立；不意味着预先虚构全部内部工程。母模型不只是一面镜头布景，也不要求提前制作不可见微细结构。

建立固定装配基准、部件命名、单位与尺度依据、锁定项/允许修改项；记录源文件和建模脚本。假设部件关联 assumption ID。材质表达可调整，但不擅自改变有证据支持的形状、数量、接口或 Logo。Logo 缺失时不假造品牌标志。展示用分离姿态不能覆盖母模型的装配基准。

## 3. 产品验证，先于分镜

输出足以核对形状的正/侧/顶或三分之四视图，按产品选择必要角度。配合 `scripts/inspect_scene.py`，核对比例、关键尺寸依据、零件数量、装配、接口、Logo、材质和外链资源。统一坐标与装配帧比较尺寸，不用旋转后的世界包围盒冒充产品规格。

实际看图；先区分几何、灯光、材质、镜头造成的问题。将结果写入简报和 [检查记录](templates/review-log.md)。按已明确标准由 Codex 验证即可继续，不强制人工审批；未知关键事实或用户明确指定的确认节点才请求判断。标为“依据现有资料完成视觉验证”，不声称工程认证。未通过的关键产品问题先修复，不在错误母模型上制定最终分镜。

## 4. 基于实际模型生成广告分镜

读取 [产品摄影规则](references/product-cinematography.md) 和 [Camera/bpy 落地](references/blender-camera.md)，填写 [分镜表](templates/shot-plan.md)。引用实际对象名、证据 ID、已验证卖点与母模型版本；不能先凭空写广告再拼出一个产品。

每镜必须包含：**Shot ID、时长与帧范围、核心信息、景别、机位角度、焦段、DOF/焦点、构图、运镜、产品动作、灯光、切镜理由/前后关系**。补充功能依据、文字/UI、资产依赖和验收条件。

一个镜头一个核心信息；Hero → Detail → Feature → Macro/Structure → Hero 是可按产品删改的信息节奏，不是硬套固定镜数。避免连续重复景别；若为了动作连续而保留同景别，说明信息变化和切点。明确何时保持机位、何时移动、何时切到新镜头。

允许局部、微距、Exploded View、拆分重组和功能动作；真实内部结构与功能声明必须有证据。未知内部可改为外部特写或明确标识的概念结构示意，不能以广告创意为由伪装事实。功能段写出 Action → Reaction，区分硬件操作、软件响应和外部服务；包装示意不冒充软件录屏。

## 5. Shot Asset Check：分镜驱动补建

逐镜填写 [资产检查表](templates/shot-asset-check.md)，把摄影机可见范围和动作需求与实际母模型比较：局部高精模型、内侧面/内部模块、可动部件、拆解层级、Pivot、Parenting、材质/UV、背面和接缝是否够用。

标为复用、局部增强、独立资产、需证据或不需要。只补建分镜真正需要的资产；关联 Shot ID、母模型对象、证据/假设 ID、修改原因及验证视角。没有依据的内部模块不自动生成真实结构，优先修改镜头或采用标识明确的示意。产品事实变化需回到证据分析，并更新母模型与受影响分镜。

独立高精模块保存在 `shot_assets/` 并记录与母模型的映射和可见性切换，避免镜头间比例、外观和装配跳变。只检查而没有新增资产时仍交付资产清单，注明复用对象与原因。

## 6. Blender Camera / Animation / Text UI

当用户要求混合运镜与切镜、丝滑、明显运镜、动态广告或认为镜头过静时，必须读取 [运动设计与验收](references/motion-direction.md)，同时规划相机轨迹与产品的展示动作。未知功能只限制未经证实的功能/内部动作，不应一并禁止整机悬浮、转向和倾斜等明确的美术展示。


基于母模型另存 `FILM.blend` 或逐镜工程，保持产品同源。按分镜设镜头、帧段、灯光、可动部件与文字，焦段/DOF/移动均有数值或轨迹，不能只写“高级运镜”。可用 `scripts/camera_rig.py` 作为基础相机辅助，具体构图仍须渲染检查。

按真实轴和行程设置动作；分离前保存装配变换，设父子关系并验证复位。动作开始、过程、结果与阅读停留清楚可见。文字/UI 使用 Blender Text、曲线/平面、材质或合成/VSE；检查中文字体、屏幕安全区和遮挡。镜头和动画名称对应 Shot ID，脚本重跑采用新版本或受控更新，防止重复对象/关键帧。

## 7. 低清预览、检查与迭代

先渲关键静帧，再输出完整时序的低清视频。`scripts/render_frames.py` 只负责抽帧，不代替动态检查。检查产品一致性、穿模、Pivot、回弹/复位、镜头碰撞/突跳、景深漂移、反射、文字、动作结果与切镜节奏。记录实际看的帧和片段；不能凭进程成功判定画面合格。

用户要求动态效果时，必须额外验证运动的屏幕可见变化和连续性：不能仅以相机有关键帧、设置了 Orbit 或顺利渲染作为通过。按 motion-direction.md 记录起/中/末帧、运动幅度、速度衔接和实际动态检查；发现仍像固定机位时先修改预览。

反馈定位到对象、参数和帧段，保存检查点并迭代。只改片尾等局部请求保留已认可范围；共享材质/灯光或连接变化时扩大复查范围。无界面播放能力时采用可用视频查看能力或连续抽帧检查，并如实记录仍未验证的动态部分，不声称已完整观看。

有地面、柔阴影或大面积渐变背景时，按运动设计参考中的“背景时序稳定性”检查正式引擎的连续短片；Workbench预演与稀疏抽帧不能验证灯光和阴影闪烁。

## 8. Blender 底片渲染与工程交付

预览通过后恢复正式质量，核对帧率、尺寸、帧段、活动相机、色彩、依赖和末帧。优先可续渲图像序列，再在 Blender 合成/VSE 输出 MP4；编码能力不支持时说明实际限制，必要时可用本地编码工具只作封装/编码，不替代 Blender 制作。检查缺帧、重复帧、最终音画同步（有音频时）与完整播放。

按 [项目报告](templates/project-report.md) 交付至少：`blender_motion.mp4`、`PRODUCT_MASTER.blend`、可编辑影片工程、必要 `shot_assets/` 与清单、`renders/`、实际执行 `scripts/`、storyboard/shot list、assumptions report、project report。整理字体/贴图和外链，打包支持的资源，其他用相对路径；重新打开交付副本验证。只有实际生成并检查的文件才称为完成，缺失工具时完成可做部分并明确剩余工作。

## 9. 选取并制作 4 张广告关键帧

读取 [广告关键帧与 H3 后期](references/ad-keyframes-h3.md)，填写 [关键帧表](templates/ad-keyframes.md)。基于已经通过时序检查的 Blender 视频，固定选第0秒的首帧与最后一帧，再选两个不同时间的内部关键帧，共4张。内部帧优先覆盖切镜后、高难度运镜和与首尾在景别/构图上差异明显的状态；兼顾两个内部帧的差异，不能简单等距抽取。

将对应帧作为构图与主体基准，重新高质量渲染，用背景设计、灯光、文字、配色和合成制作统一风格的广告关键帧。保持主体身份、几何、部件、比例、姿态与镜头一致；美术包装不能伪造产品功能或隐藏已知模型错误。保存4张原始帧、4张广告帧及帧号/时间/选择理由/修改清单，核对成组一致性。

## 10. 关键帧 + Blender 视频生成 MiniMax H3 广告

按同一参考文件准备 H3 多模态输入：4张广告关键帧负责产品身份、视觉风格与对应时刻的构图，Blender 视频负责相机运动、产品动作、切镜时间与节奏。以实际可用 H3 接口核实输入模式、图片/视频数量、时长、画幅和时间锚定能力，再提交；不能假定4图加1视频一定能被任一入口同时接受。

编写明确的素材角色与时间线，保留已认可的混合运镜、装配关系及品牌文案。生成后检查整片产品漂移、切点、运动、背景闪烁、文字和音频，必要时迭代。H3 结果不是几何或逐帧保真的保证，提示词不能替代实际检查。最终交付 `final_h3.mp4`，并保留 `blender_motion.mp4`、关键帧、提示词、实际请求参数、任务记录、检查报告及原 Blender 工程。若接口或必要授权不可用，交付已完成素材与待提交包，明确 H3 未生成，不用提示词冒充成片。
