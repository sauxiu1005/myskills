# 执行与数据回传

以下命令与脚本是此 Skill 的实现辅助，不是原文附带代码。调用前读取当前场景和本机 Blender 版本，使用该版本可用的 API，不对用户源文件运行写入脚本。

## 运行条件与路径

查找用户机器上的 Blender 可执行文件，验证版本与命令行是否可运行。macOS 常见路径为 `/Applications/Blender.app/Contents/MacOS/Blender`；其他系统使用实际安装位置。下列示例中的 `blender`、`/project/`、`/skill/` 都需要替换为实际路径，并使用带引号的参数或进程参数数组，不能把用户文本拼接成可执行命令。

`bpy` 脚本通过 Blender 运行，不要求系统 Python 单独安装 bpy。使用 `--python-exit-code 1` 让脚本异常反映为失败退出码，并保留输出日志；退出成功后仍须验证文件和画面。

原始模型只读保留；制作时另存展示副本。一个工作副本同一时刻只允许一个写入者。命令行进程与已打开的 UI/MCP 会话可能持有不同场景；检查前明确文件、场景、版本与帧号，不假定后台修改已同步到窗口。

## STEP / CAD 输入

先检查已提供的 CAD 读取或转换能力。原文没有指定转换器，本 Skill 也不绑定额外软件。没有可用转换路径时利用其他已提供资料继续建模；确实只有无法读取的 CAD 文件时，请求可读资料或必要的环境配置，不编造 `bpy.ops.import_scene.step`。转换后检查单位、整体尺寸、独立部件和装配位置，不能只凭“导入成功”进入制作。

## 场景报告

```sh
blender --background "/project/PRODUCT_MASTER.blend" --python-exit-code 1 \
  --python "/skill/scripts/inspect_scene.py" -- \
  --output "/project/reports/assembly_v001.json" --collection "PRODUCT_MASTER" --frame 1
```

`--collection` 与 `--frame` 可省略；指定集合必须确实存在。脚本记录局部位置、世界矩阵、包围盒、材料、基本动画标志、资源和渲染设置。尺寸以 Blender 单位记录，同时返回场景单位比例。报告路径已存在则拒绝覆盖。

此报告是核对证据，不是几何等价判定。它不会导入模型、识别某对象就是旋钮、自动锁定产品或验证采购件。数量相同不代表形状相同；约束、修改器、实例、驱动、动画与资源需要按任务进一步检查。单位未知时不要给出未经依据的毫米数值。

## 静态检查帧

```sh
blender --background "/project/PRODUCT_MASTER.blend" --python-exit-code 1 \
  --python "/skill/scripts/render_frames.py" -- \
  --output-dir "/project/previews/v001" --frames "1,12,24" --percent 25
```

脚本使用现有场景、摄影机、渲染器和色彩设置，仅临时降低输出尺寸，生成 PNG 与清单，不保存 `.blend`。输出目录须不存在，防止覆盖已有结果；失败时可能留下部分帧，检查日志后用新版本目录重试。含合成器文件输出节点的场景需要单独审查的渲染脚本，以避免额外路径写入。项目的其他输出节点、缓存、序列和渲染回调同样需要事先检查。

该脚本不会自动搭建产品摄影棚，也不是完整动画预览或最终视频生成器。Codex 应在查看目标场景后针对实际对象创建材质、灯光、相机和动画脚本，先验证一个小功能段，再扩展。静态图检查直接打开输出文件；现场播放和交互通过可用 Computer Use。

## 完整预览与最终渲染

在展示副本设置好活动相机、帧范围、帧率、输出格式和适用渲染参数；预览可降低分辨率与采样，但功能时间关系必须保留。可通过 `bpy.ops.render.render(animation=True)` 或当前 Blender 命令行的动画渲染入口输出完整范围。先检查实际文件和动态效果，再进入正式质量。

长片可在新的帧序列目录渲染 PNG/EXR，核对范围完整后在 Blender 视频序列编辑器组织顺序、帧率与所需音乐，并使用当前构建支持的视频编码输出最终视频。若当前构建不支持所需编码，明确限制；不能把图像序列重命名成 MP4。合成/编码工程与 3D 主工程可分别保存，均应保留可复现关系。

正式渲染前重新核实：正式质量、输出尺寸、帧范围、活动相机、字体、贴图及动画末尾。抽取动作前、中、后与镜头衔接帧，并播放完整成片。保留完成帧以便失败续渲；全局设置变化会使部分已渲帧失效，不能混合不一致版本。

## MCP 与 Computer Use

存在可用 MCP 时，先读取场景状态并确认目标工程，再用当前实际暴露的工具执行操作。没有 MCP 仍可走命令行；不指定虚构工具名、不自动安装插件。

需要现场交互时使用当前环境的 Computer Use 能力，先读取真实窗口状态再操作。它可切换视图、移动时间轴、播放与执行 UI 操作；既不局限于看图，也不要求所有批量任务改走点击。无界面能力时仍可读取渲染图和场景报告；需要完整运动判断却无法播放时明确待检范围。
