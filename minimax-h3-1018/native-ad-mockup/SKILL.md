# 原生广告样机

把产品做成像真实手机截图一样的软广静态图。输入可以是产品图、产品页链接，也可以只是文字产品信息。

本 Skill **不依赖**品牌文件夹、本地产品图目录或预先建立的品牌系统。它从当前对话附件和用户提供的产品信息开始工作。

---

## Step 1 — 询问产品准备情况和软广格式

在写提示词或生成图片前，先问用户两个问题；如果用户已经说明，则直接跳过。

### 1. 是否已有产品 / 产品图

问：

> 你已经有产品图或包装图了吗？

给具体选项：

- 使用已上传附件
- 我会上传产品图
- 从产品页 / URL 获取
- 暂时没有产品图，先按描述做概念草稿

规则：

- 如果用户上传了图片，把它作为产品视觉锚点。
- 如果用户给了产品页链接，在可用时把它作为文案和产品卖点来源。
- 如果只有文字描述，就明确按概念草稿处理，不声称包装完全真实。
- 如果有多张图，需要询问或判断角色：产品图、风格参考、版式参考、场景参考。

### 2. 想生成哪种原生软广格式

问：

> 你想做哪种原生软广图片？

给具体选项：

- iMessage / DM 对话
- 微信风格朋友推荐
- 小红书种草笔记
- 小红书评论区问答
- 小红书商品卡
- 手机结账页 / 购物车
- 低电量 / 系统弹窗
- 提醒事项 / 日历 / 待办 App
- 天气 / 身体状态 App
- 办公聊天 / Slack-like 聊天
- 成分科普 / Clean-label 卡
- 倒计时 / 稀缺感卡片
- 用户评价 / testimonial 卡
- 前后对比 / comparison 卡
- 用户自定义格式

如果用户选择多个格式，每个格式生成一张，组成统一的一组图。

如果用户说“全部 / 所有能力 / 都来一个”，根据产品品类和平台选择 4–6 个最合适的格式。

---

## Step 2 — 分析产品和参考图

对每张产品图，只提取生成所需的信息：

- 产品形态：条包、瓶子、软管、盒子、设备、食品、服装等。
- 可见品牌和产品文字。
- 包装结构和显著设计信号。
- 材质感和产品类别。
- 可迁移的品牌信号：形状、标签、排版逻辑、重复视觉元素。
- 生成图里必须保持准确的部分。

如果用户提供了广告版式参考，则提取：

- 格式类型和版式逻辑。
- 内容区域和视觉层级。
- 文案槽位及其作用。
- 产品摆放逻辑。
- 字体处理方式。
- 是否需要手机 mock 外框。

不要复制参考图中的第三方品牌身份。只取结构，不取颜色、Logo、字体或品牌标识。

---

## Step 3 — 写或改文案

根据选择的格式和产品证据写文案。

文案规则：

- 如果用户或产品页提供了真实卖点，优先使用真实卖点。
- 如果没有真实卖点，写低风险生活方式文案，避免医疗、功效、量化承诺。
- 原生软广文案要短、自然、像截图里的内容。
- 聊天格式使用短气泡，不写长句。
- 小红书格式用自然种草口吻，不写企业广告腔。
- 评论区问答用于处理真实异议：价格、口味、使用场景、尺码、甜不甜、肤质、便携性、日常习惯等。
- 商品卡使用简短标签和一个明确 CTA。

当任务高风险、品牌敏感或输出数量较多时，先把文案槽位给用户确认。若用户已说“你看着办 / 直接做”，则按合理默认继续。

---

## Step 4 — 比例和输出数量

默认比例为 `4:5`，除非用户另有要求。

支持比例：

- `4:5`：默认社交信息流 / 小红书 / Meta 静态广告
- `9:16`：Story / Reels / Shorts / 抖音
- `1:1`：方图信息流
- `3:4`：竖版商品卡
- `16:9`：横版展示

一组图默认保持同一比例，除非用户要求多比例。

---

## Step 5 — 提示词构造规则

每个提示词必须包含：

- 产品视觉锚点；有图片时传入图片路径。
- 选择的原生软广格式。
- 外层比例。
- 手机原生格式必须写手机 mock 外框。
- 内屏比例锁定。
- 字体和可读性约束。
- 平台 Logo / 水印安全约束。
- 要渲染的准确文案。

### 手机 UI 样机规则

以下格式必须使用：手机截图、聊天截图、App 界面、iMessage/DM、低电量弹窗、提醒事项、天气 App、结账页、小红书、微信聊天、手机电商界面。

- 外层广告画布按用户指定比例。
- 内层手机屏幕保持真实高瘦比例。
- 不要把手机界面拉伸或压缩去填满画布。
- 除非用户要求无边框，否则默认加入真实、细边、不抢戏的手机 mock 外框。
- `4:5` 推荐结构：外层画布 → 近景或居中手机 mock → 自然高瘦内屏。
- 文字和 UI 元素必须保持正常横向比例。
- 禁止瘦长字、condensed 字体、纵向拉伸、异常 tracking、变形气泡、压缩行高。
- 英文 iPhone-like UI 使用接近 SF Pro / San Francisco 的系统字体比例。
- 中文移动端 UI 使用接近 PingFang SC / 现代中文系统字体比例。
- 聊天格式优先使用手机近景裁切，保证文字足够大。
- iMessage/DM 顶部必须有更多留白：联系人区域要高、干净、有呼吸感，联系人和第一条气泡之间要有明显距离。
- 复制交互模式和版式逻辑，不复制平台官方 Logo 或专有标识。
- 不出现真实 App Logo、平台水印、生成标识、随机通知、二维码、假官方认证或无关 UI。

## Step 6 — 内置模板

以下模板作为内部模板使用，根据产品、文案和比例填充。

### iMessage / DM 对话

生成一张 iMessage/DM 灵感聊天截图，放在真实细边手机 mock 外框内。外层是 [比例]。优先使用手机近景裁切，不展示完整手机，让屏幕和文字更大。内屏保持自然高瘦比例，不拉伸。字体接近 SF Pro 比例：正常字宽、自然 tracking、不瘦长、不 condensed。顶部是干净的联系人区域，居中显示联系人名，可有头像和小字标签。顶部区域要高、有留白；联系人和第一条气泡之间要有明显垂直空间。聊天只用 3–5 条短气泡，每条短文本，不挤字。最后放产品预览卡，包含产品名、副标题/URL 和产品图。底部输入栏可写 “iMessage” 或 “Message”。不要平台 Logo、官方标识、水印或随机通知。

### 微信风格朋友推荐

生成中文朋友聊天截图，放在真实手机 mock 外框内。使用通用国内聊天 App 视觉，不出现微信 Logo 或专有标识。内屏保持自然比例。字体接近 PingFang SC。对话要像朋友之间自然推荐：一个真实生活痛点、一个追问、一个自然产品推荐。可在底部加入产品链接卡。不要平台 Logo、水印、二维码、假认证或拉伸中文。

### 小红书种草笔记

生成中文小红书风格种草笔记截图，放在真实手机 mock 外框内。内屏保持自然比例。顶部包含头像占位、用户名、关注按钮。标题是种草标题。正文 2–4 行自然中文，基于产品事实。商品卡包含产品名、副标题、标签和“去看看”按钮。可加入评论预览。模仿内容机制，不出现小红书 Logo、水印、二维码或平台标识。

### 小红书评论区问答

生成评论区问答型手机截图。主体是评论串：一条主帖短句 + 3–5 条评论和回复，用来处理产品异议。底部可放产品卡。中文必须正常字宽、可读。不要平台 Logo 或水印。

### 小红书商品卡

生成手机电商商品卡截图。顶部生活化标题，中间是商品卡，包含产品图、产品名、副标题、卖点标签和一个 CTA。底部加一句使用场景或信任提示。整体像 App 内商品卡，不像传统海报。

### 手机结账页 / 购物车

生成干净的手机结账页或购物车截图。包含商品行、缩略图、商品名、副标题、优惠码、价格、CTA 和信任提示。保持平台中性。

### 低电量 / 系统弹窗

生成通用手机系统弹窗软广。中心是弹窗标题、短正文和两个按钮，旁边或下方展示产品卡/包装。不要硬复制 iOS 官方标识。

### 提醒事项 / 日历 / 待办 App

生成提醒事项、日历或待办 App 截图，用日程或待办项把产品变成日常习惯。

### 天气 / 身体状态 App

生成天气或身体状态 App 截图，把用户状态或使用场景做成有趣的预报。底部加入产品卡。

### 办公聊天

生成通用办公聊天截图。不要真实 Slack Logo。用短办公室语境消息和产品链接卡。

### 成分科普 / Clean-label 卡

生成成分或 clean-label 教育卡。使用清晰层级、卖点行、产品图和信任标签。不一定需要手机 mock，除非用户要求。

### 倒计时 / 稀缺感卡片

生成高紧迫感静态广告：倒计时、库存条、优惠标签、产品主视觉、CTA 和 disclaimer。不一定需要手机 mock，除非用户要求。

### 用户评价 / Review 卡

生成原生评价卡：短评价、头像占位、产品卡和 CTA。不要假平台 Logo。

### 前后对比 / Comparison 卡

生成对比卡：两个状态、短标签、产品解释和 CTA。没有证据时不要写强功效承诺。

---

## Step 7 — 生成图片

每个选择的格式生成一张图。

批量输出规则：

- 一组图保持产品识别一致。
- 一组图保持比例一致。
- 手机外框和字体规则保持一致。
- 只变化原生格式、文案角度和版式。
- 不要把多个格式硬塞进同一张图，除非用户要求拼图。

---

## Step 8 — 验收与迭代

生成后检查：

- 需要手机 mock 的图是否有手机外框。
- 内层手机屏幕比例是否自然。
- 文字是否可读、字宽是否正常。
- iMessage/DM 顶部留白是否足够。
- 是否出现平台 Logo、水印、二维码或假官方标识。
- 产品是否接近用户提供的参考。
- 是否仍像原生截图，而不是传统海报。

如果用户要求修改，保留已认可部分，只改指定区域，例如：顶部留白更多、气泡更少、字体更大、手机更近、换软广格式、产品更突出等。
