# 多语言识别、字体选择与排版规则

## 1. 识别故事语言

1. 以用户明确指定的成片语言为最高优先级；没有明确指定时，识别每个原文段落实际使用的语言与文字系统。
2. 识别结果至少记录：`language_tag`、`script`、`writing_direction`、`source_text_policy`。示例：`zh-Hans / Han / ltr / preserve`、`ar / Arab / rtl / preserve`。
3. 多语言或混合文字按段落、句子或必要的行内片段分别标记，不要把整篇强行归为单一语言。
4. 不依据聊天语言、界面语言、Skill 文件语言或目标市场自动翻译原文。用户未要求翻译时，逐字保留原文、标点、数字、大小写和专名。
5. 无法区分语言、文字方向或用户是要保留原文还是翻译时，只询问这一项，不追加无关制作问题。

## 2. 字体选择

1. 字体必须真实存在于当前渲染环境，或由用户提供并有权使用；不得猜字体文件路径或虚构字体已安装。
2. 先做字符覆盖测试，至少覆盖该节点全部字母/汉字/假名/谚文/阿拉伯字母、数字、标点、引号和货币符号。出现缺字方框、替代字形或错误组合时，换用覆盖完整的字体或经过验证的回退链。
3. 用户明确指定字体时优先使用；不可用时说明原因，并提供风格相近且覆盖完整的可用字体，不静默替换。
4. 默认字体方向按文字系统选择：
   - 简体/繁体中文：覆盖对应汉字集的中文字体；手写故事优先经过验证的中文手写体或楷体。
   - 日文：完整覆盖汉字、平假名、片假名与日文标点的日文字体。
   - 韩文：完整覆盖谚文与所需汉字的韩文字体。
   - 拉丁/西里尔/希腊文字：支持所需重音、连字和大小写的字体。
   - 阿拉伯、希伯来等文字：必须支持对应字形塑形与从右向左排版。
   - 天城文、泰文及其他复杂文字：必须使用支持组合标记和复杂塑形的字体与渲染器。
5. 混合文字可使用验证过的字体回退链，但字号、基线、字重与视觉风格要协调；不要用图像模型生成准确文字。

## 3. 语言感知排版

1. 书写方向：拉丁、汉字、假名、谚文等默认从左到右；阿拉伯、希伯来等默认从右到左。混排时使用正确的双向文本顺序，不手工倒序字符。
2. 断行：
   - 中文、日文、韩文遵守禁则，避免行首出现句号、逗号、闭引号等，避免行尾留下开引号。
   - 拉丁、西里尔、希腊文字按词边界换行，不在单词中间硬切；需要断词时使用该语言的断词规则。
   - 阿拉伯、希伯来文字保持词序、字形连接和标点方向正确。
   - 泰文等无空格分词语言使用语言感知分词，不按固定字符数机械切行。
3. 阅读时间按语言和信息密度估算，不使用单一“每秒字数”覆盖所有语言。长句优先重排、分行或分屏，不擅自删改原文。
4. 用户要求竖排时，先确认目标语言和字体支持，再按该语言规范处理标点、旋转字符与阅读顺序；不把横排简单旋转冒充竖排。
5. 数字、日期、单位、专名和引号保持原样；翻译任务中也要单独核对这些高风险字段。
6. 文字始终位于独立可编辑图层，并完整留在固定安全区内。不同画幅需要重新断行与排版，禁止通过横向拉伸、裁切或缩小到不可读来适配。

## 4. 节点验收

当前节点生成后只做轻量文字检查：确认没有缺字方框、乱码、错误方向、严重遮挡或不可读缩放。随后展示给用户，询问“是否通过”。轻微字距、换行审美或字体风格偏好由用户确认；未经用户明确要求，不自动更换字体、重排或重生成资产。
