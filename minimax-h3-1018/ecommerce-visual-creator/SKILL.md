# 电商视觉策划与执行

把“原始商品资料”转成“可直接交给设计师或生图模型执行”的视觉方案。交互语言遵循用户与当前会话要求；商品页面语言按目标市场和用户确认执行，不改变证据与合规边界。

## 运行原则

1. **证据优先**：用户提供的包装、参数、资质、检测、品牌资料和明确事实 > 已核验的官方最新平台规则 > 本 Skill 的参考资料 > 合理假设。
2. **按任务路由**：只交付用户需要的层级，不强制走完整流程；不要为了“流程完整”重复追问已知信息。
3. **不把假设写成事实**：缺资料时标记“待确认”，不要补造销量、评价、证书、检测、专利、资质、功效、排名或平台规则。
4. **先统一视觉，再写细节**：同一套图必须先锁定产品身份、构图、色彩、光影、字体、背景和禁止漂移项。
5. **平台规则有时效性**：涉及当前尺寸、禁限词、类目政策、主图要求、资质或审核规则时，优先查官方最新来源；无法核验时明确标记“未核验”，不要凭旧规则下结论。
6. **高风险合规不做最终法律结论**：食品、保健品、医疗器械、健康护理、儿童用品等场景，按保守口径处理，并说明需要以目标市场法律、监管和平台最新规则为准。

7. **先画布成品，最终确认后再 Photoshop**：先在画布制作包含文案、字体、参数、标注和完整排版的成品主图与成品详情图。用户明确最终确认具体成品版本与范围之前，不调用 Photoshop 做连接检查、预览、字体查询、排版、修图或源文件准备。最终确认后，默认交付 Photoshop 多图层源文件与对应成品预览。仅策划、文案、提示词和审查不触发源文件制作；用户明确只要平面图时尊重其范围。
8. **视频生成前必须选择模型**：标准候选为 MiniMax H3 与 SD 2.0，不自动选中任何一个。每个新的实际视频制作任务，先核验实时可用性，并在首次视频生成前弹出单选询问框：“这次视频使用哪个生成模型？”，按顺序提供且仅提供两个标准选项：“MiniMax H3”“SD 2.0”。等待用户明确选择；不能把沉默、“继续”、旧任务模型或此前自动默认值当作本次选择。记录本次任务选择，全部镜头、同任务续做及重试沿用，不逐镜重复询问；新的视频任务重新弹框。候选不可用或不兼容时，说明具体限制并取得明确的兼容决策，不静默选择另一个模型或换成其他变体。用户主动提出两项以外的模型时，按明确例外另行澄清，不默认增加第三项。选模型不替代美工图、创意、分镜及完整逐镜视觉审核；仅策划或修改Skill不触发媒体生成。对外名称以实时目录为准，并核验所选模型的时长、参考容量、画幅与分辨率，不能机械沿用旧模型设置。

## 执行模式

根据用户意图自动选择，不要机械暂停。

### A. 标准模式

适用于方向不清、视觉成本高、用户明确要求“先策划/先分镜/确认后再做”。

1. 先输出《视觉策略与证据账本》。
2. 再输出 Storyboard。
3. 在真正进入大量最终文案或生图 Prompt 前等待确认。

### B. 一次性交付模式

用户明确说“直接出完整方案”“一次性给我”“按你判断做完”，或资料已经足够明确时，直接完成策略、Storyboard、执行稿和画布成品，不做不必要的中途确认。视频任务仍须遵守宣传片分支的创意与分镜审核门。不能跳过进入 Photoshop 前的成品最终确认：要求做完整套，不等于批准尚未展示的成品。

### C. 审查/改稿模式

用户已经有主图、详情页、文案、Prompt 或设计稿时，不从零重做。先找出问题，再给最小必要修改：

- 转化逻辑问题
- 视觉层级问题
- 证据或合规问题
- 平台适配问题
- 文案与画面不一致
- 风格漂移

### D. 设计师交接模式

用户需要“给设计师开工”的执行稿时，直接使用 `references/output-contracts.md` 的结构化交付格式。

## Step 0：任务路由与最小输入

先判断用户要的是哪一类产出：

- 主图 / 商品图
- 详情页 / PDP
- Amazon Listing / A+ / Brand Story
- 广告素材 / 短视频封面
- 图内文案
- Storyboard / 图片规划
- 生图 Prompt
- 合规审查 / 改稿
- 跨境本地化
- 商品宣传片 / 产品宣传视频

优先获取以下信息：产品是什么、目标平台/市场、目标人群、核心卖点与参数、可用证据、已有视觉资料/参考图。

只有缺失信息会改变定位、合规边界或关键画面时才追问，最多追问 3 个关键问题；其余缺失项采用最合理假设继续，并显式标注假设。

## Step 1：建立证据账本

任何会进入最终页面的事实型、数据型、效果型或资质型宣称，先放入证据账本。

| 宣称/卖点 | 来源 | 状态 | 最终处理 |
|---|---|---|---|
| 包装或资料明确写明 | 用户资料 | 已确认 | 可使用，保持原意 |
| 可由参数直接推导 | 用户资料 | 有依据 | 可转成利益表达，但不扩大 |
| 需要检测/认证/平台规则支持 | 缺少证据 | 待补证 | 改中性表达或保留占位 |
| 涉及治疗、保证性效果、虚构背书 | 无合法依据 | 禁止 | 不进入最终稿 |

最终稿只能使用“已确认”或“有依据”的内容。“待补证”必须转为中性表达、占位符或待确认项。

## Step 2：判断成交驱动力

不要默认所有产品都用同一套“痛点文案”。从下列类型中选 1 个主驱动力 + 最多 1 个辅驱动力：

| 驱动力 | 典型场景 | 视觉重点 |
|---|---|---|
| 视觉/质感 | 美妆、饰品、家居、礼盒 | 材质、光影、比例、包装、氛围 |
| 痛点/效率 | 清洁、收纳、工具、生活用品 | 问题场景、使用前后、步骤缩短 |
| 理性/参数 | 3C、家电、设备、功能型商品 | 参数翻译、机制、规格、兼容性 |
| 信任/证据 | 食品、茶饮、母婴、高客单商品 | 产地、工艺、资质、检测、品牌证据 |
| 情绪/身份 | 香氛、服饰、礼赠、宠物、生活方式 | 场景、审美、仪式感、身份认同 |

然后把卖点做成：`Feature -> Advantage -> Benefit -> Evidence`。

只保留 Top 3 购买理由。没有证据支撑的“猛卖点”不因为转化需要而放宽边界。

## Step 3：锁定 Campaign Style Lock

至少明确：

- **产品身份**：包装文字、Logo、颜色、比例、结构、材质、关键细节必须保持什么不变。
- **构图体系**：主体占比、视角、留白、视线流向、是否允许人物/道具。
- **色彩体系**：主色、辅助色、强调色；避免无理由漂移。
- **光影体系**：自然光、棚拍、硬光、柔光、轮廓光等。
- **字体与信息密度**：标题、数字、说明层级；移动端优先可读。
- **背景与场景**：纯底、棚拍、真实场景、品牌氛围。
- **Reference Fidelity**：有参考图时，列出必须保留与允许变化的元素。
- **Negative Constraints**：禁止新增的 Logo、配件、纹理、人物特征、结构、功效符号或不真实细节。

如果用户上传了产品图或包装图，必须先以图中真实产品为准，不得为了“更好看”擅自改包装结构、Logo、口味、规格或配件。

## Step 4：规划 Storyboard

不要把“5 张主图”当成死规则。默认可用 5 张作为起点，但应根据平台、用户要求和信息量调整。

常见主图任务：

| 角色 | 任务 |
|---|---|
| Hero / KV | 一眼识别产品 + 单一核心购买理由 |
| Benefit | 把核心参数或功能翻译成用户收益 |
| Proof | 用真实证据建立信任 |
| Compare | 用客观维度降低选择成本，不虚构竞品数据 |
| Scene | 放入真实使用场景，强化代入 |
| Spec / CTA | 规格、组合、适用条件或下一步决策信息 |

详情页/PDP 常见叙事顺序：

`承接首屏 -> Top Benefits -> 机制/材质/工艺 -> 场景 -> 证据 -> 对比/选择 -> FAQ -> 规格/CTA`

根据商品和平台删减，不强行凑模块。

涉及 Amazon、Shopify、TikTok Shop、Temu、Shopee、Lazada、淘宝、天猫、京东、拼多多、抖音小店等平台时，读取 `references/platform-playbooks.md`。如果用户问的是当前具体审核规则、尺寸、禁词或类目要求，优先核验官方最新规则。

## Step 5：执行输出

每张图/每个模块至少交付：

1. **视觉任务**：这张图负责解决什么决策问题。
2. **画面描述**：主体、构图、镜头、背景、材质、光影、信息层级。
3. **图内文案**：标题 + 必要副文案；优先短、具体、可证实。
4. **设计说明**：第一视觉落点、阅读顺序、数字/证据如何突出、免责声明或注释放哪里。
5. **生图 Prompt**：主体 + 构图 + 场景 + 材质 + 光影 + Style Lock + 参考图约束。
6. **Negative Prompt / 禁止项**：避免包装变形、Logo 错误、文字乱码、结构新增、人物肢体异常、风格漂移等。
7. **证据备注**：如果该图含数据、资质、对比或效果表述，标出其证据来源。

跨境场景不要逐字翻译中文卖点。做本地化：保留事实边界，调整表达习惯、单位、场景、购买理由和信息密度。

### 先完成画布成品，不提前进入 Photoshop

1. 用户授权实际出图后，使用可用的画布图像创作与编辑能力，制作面向消费者的完整主图和详情模块，包含已确认文案、字体、数字信息及排版。
2. 在画布展示成品供用户检查。无字摄影底图、文案文档、分镜、提示词和内部拼图不能代替成品。允许保留必要参考素材，但不得借素材准备之名提前进入 Photoshop 排版。
3. 美化、构图、文案、字体等修改先在画布成品上完成；不要每生成一张无字底图就打开 Photoshop 补字、再让用户审预览。若画布路径无法完成必要处理，应报告限制，不静默绕过确认门。
4. 成品展示后等待用户最终确认，并记录具体获准版本。方案确认、风格确认、单张样稿通过后要求继续整套，都不等于尚未展示成品的最终确认。

### 为最终确认后的分层制作保留素材

- 保留原始参考、可复用视觉素材、准确文案及最终画布成品，此时不启动 Photoshop。
- 画布阶段可以用文字和图像合成在一起的完整平面成品进行视觉验收；可编辑源文件在用户最终确认后再重建。
- 后续 Photoshop 阶段再将文字重建为独立文字层，并按实际需要制作可替换主体、蒙版或智能对象。明确说明重建范围及仍与摄影背景合并的部分；平面成品是视觉校准依据，不是原始可编辑图层已经存在的证明。

## Step 6：五维质量门

先检查硬性阻断项，再做质量判断。

### 硬性阻断项

出现任一项，不能直接交付最终稿：

- 编造或无法追溯的资质、检测、认证、销量、评价、排名、专利、数据。
- 产品身份与用户素材冲突，例如包装、规格、颜色、Logo、结构被改错。
- 把“待补证”内容写成确定事实。
- 当前平台规则未核验却写成“平台明确规定”。
- 高风险品类使用治疗、保证性效果或扩大批准范围的表达。

### 五维 Pass/Fail

| 维度 | Pass 条件 |
|---|---|
| 证据与合规 | 关键宣称可追溯，风险项已降级或删除 |
| 转化逻辑 | 每张图有独立决策任务，Top 3 购买理由清楚 |
| 视觉层级 | 第一落点明确，文字密度和主体比例合理 |
| 一致性 | Style Lock、产品身份、字体、色彩、光影不漂移 |
| 可执行性 | 设计师或生图模型无需猜关键元素即可执行 |

任一维度 Fail，就修对应问题后再交付。不要用其他维度的高分抵消。

如果用户明确要求量化评分，可使用 1–5 分并给出每一分的可解释依据；不要用没有锚点的“80/100”制造伪精确。

### 成品最终确认门

内部质检通过不等于用户确认。先展示画布上的成品主图和详情图，再请求用户确认这些具体版本，之后才可进入 Photoshop。“方案确认”“风格可以”“样稿确认，继续做完”“继续美化”等均留在画布创作阶段；只有明确最终确认已展示成品（例如“这些主图和详情图定稿，进入 Photoshop”）才放行对应版本。若用户只明确批准部分成品进入源文件制作，就仅处理该子集，不推断其余版本也已通过。后续修改某张图时，先重新完成该图的画布审核，再更新对应 Photoshop 文件。

## Step 7：Photoshop 分层源文件与画布交付

1. **触发与执行**：仅在画布成品质检通过，且用户明确最终确认具体版本后，进入 Photoshop，无需再重复询问是否需要 PSD。按照确认稿忠实完成成品主图和成品详情图的分层制作；不在此阶段重新设计方向、擅改文案或混入试稿。
2. **能力确认**：只有最终确认后，才检查 Photoshop 操作、保存与源文件交付能力；批量制作源文件前先核实交付路径。不能仅凭软件名、文件后缀或调用请求宣称完成。若源文件无法交付，应说明阻塞并取得用户认可的替代方式，不能声称已完成画布源文件交付。
3. **按元素分层**：按实际存在的元素组织背景、产品、人物、装饰、文字、标识、效果等命名图层或分组。文字保持可编辑；可替换素材尽量保留为智能对象；抠图使用非破坏性蒙版；调色尽量保留调整图层。没有的元素不创建空壳层凑数。
4. **处理已有平面图**：如源素材仅为合成图，需分离或重建必要元素并清除原有烧录文字，避免叠字。无法无损恢复被遮挡区域或内部细节时说明重建范围；不能承诺恢复生成前并不存在的原始图层。
5. **组织文件**：独立设计默认独立 PSD；详情长页可按模块分组，保持可单独修改与导出。超出 PSD 实际限制时使用适合的 Photoshop 大文档格式并说明。画板结构可依交付需求采用，不擅自合并无关设计。
6. **验收**：保存后重新打开，检查图层树、文字可编辑性、素材替换、蒙版、链接与字体缺失情况，并将合成预览与已确认设计对照。不能把一张平面图置入 PSD，或重复若干整图层，称为可二次修改的多图层设计源文件。
7. **画布展示**：保存源文件至当前项目，交付真实可访问的 PSD／适用大文档源文件及预览，在画布显示可打开或下载的文件节点与对应预览。预览不能代替源文件；仅有聊天路径也不算画布交付完成。已经自动入画布的文件不得重复添加。
8. **失败边界**：Photoshop 未连接、导出失败或画布不支持该文件交付时，保留已完成的平面作品，明确报告阻塞与未完成项，并提供连接、重试或经用户同意的替代方案；不得伪造 PSD、把 PNG 改扩展名，或在未经同意时换软件冒充 Photoshop。

### 美工图到宣传视频——必须遵守的顺序

1. 先完成本次所需的电商主图和详情美工图，展示成品，并获得用户对具体版本和范围的最终确认，再开展宣传视频内容策划。原始商品参考图、风格确认、分镜或未完成样稿不能代替此门槛；已有完成且确认的美工图直接复用，不重复出图。
2. 用户最终确认美工图后，主动用一次问题卡询问是否基于这些图制作宣传视频，提供“需要／不需要／稍后”选择。询问本身不授权生成。若用户此前已明确要视频，不重复问意愿，直接补齐未知输入；用户拒绝后不反复推荐，除非用户重新提出。
3. 每个分镜镜头规划为5秒，全片15–30秒，片头、转场与结尾都计入。未明确时用选择卡提供15／20／25／30秒（3／4／5／6镜）。超出范围或无法整分5秒的请求，先选择兼容时长或明确批准时序范围例外，不静默修改。交付前逐镜核验5秒分配及实际导出总长。
4. 用户需要视频但要求不明确时，在视频策划和生产前弹出问题卡，每轮最多三问，只问尚未确定的项目：①以5秒镜头组成的15–30秒准确总长；②视频画幅／方向及用户需要时的像素尺寸；③配乐使用生成音乐、用户上传音乐还是不配乐，必要时明确音乐情绪。15／20／25／30秒、16:9／9:16／1:1仅为可选示例，不是擅自采用的默认值。静态美工图尺寸不自动代表视频画幅；明确确认过的视频选择直接复用。旁白或音效只在用户要求或确有依赖时澄清，字幕仍默认关闭。未知时长、画幅与配乐不能用未经同意的假设填补；其他创意缺口仅在阻断时询问。
5. 根据定稿美工图发展视频：将选定主图和详情图映射到开场吸引、可见表面／细节、已核实参数、使用场景及CTA；保留产品身份、已确认文案、视觉语言和目标市场，动作不能引入未经证实的结构或主张。仍须确认视频创意和完整时长分镜；视频生产前每镜均须有获准视觉参考；足够的定稿图直接复用，仅批量补齐缺失分镜视觉，不替换已批准美工图及事实依据。
6. 用户在美工图未完成或未确认时要求视频，先解释前置条件并完成图片制作与审核。用户提供现成美工图时，若尚未明确确认，仅核实这些具体版本是否定稿。要求“不实际生图”时可复用已定稿成品；没有此类成品则暂停，请用户提供或澄清任务范围，不擅自出图或绕过顺序。仅策划任务可交付暂定文稿，但不放行视频生产。
7. 视频询问不取消或阻断已约定的静态源文件交付。已确认平面成品足以作为视频参考，不以PSD重建完成作为视频前置条件；视频请求不授权新增PSD或重做无关美工图。

### 5秒镜头制作补充

每次商品宣传视频任务必读 `references/product-promo-production-supplement.cn.md`。执行脚本→含声音计划的故事板→获准逐镜视觉→逐镜视频→获准音频层→资源齐备后剪辑导出；每镜5秒、全片15–30秒及逐镜视觉覆盖替代旧片段默认，但不绕过确认、证据与详情图对应门。

### 视频逐镜对应定稿详情图

定稿详情图是每个镜头的产品构图、展示细节、画面介绍和视觉效果依据，不只是产品身份或配色参考。无字视频仍执行构图对应。用户明确批准的偏离仅作用于指定镜头和属性；要求图片动起来不等于授权重新设计。

1. **先绑定来源，再写镜头**：每个镜头标明具体获准图片、版本；详情长页还须定位模块或区域。分别记录每张来源对产品身份、构图、展示细节、文案或画面效果的贡献。细节展示镜头须对应其详情模块，开场或收尾可采用已批准主图；不能随意借用其他模块文字。一张详情图可拆成多个镜头，一个镜头也可组合兼容来源，但贡献及获准偏离必须明确。覆盖用户要求的全部模块，选取或压缩依据已批准范围，不静默遗漏。
2. **继承具体构图与可见设计**：记录来源中的产品视角／朝向、展开或收纳状态、画面占比、位置、裁切、关键部位、人物／道具关系、背景结构、光影特征、留白和视觉阅读顺序。保留相关图文关系、局部特写／嵌图布局、箭头和标签指向；原图直接承载配色及细节视觉依据。不能把细节特写模块改成无关的居中产品大全景，也不能为制作方便换成新的通用影棚模板。
3. **文字介绍必须对应当下可见内容**：沿用绑定模块的准确已确认文案、已核实事实、单位和限定说明。说明某部位或用途的文字可读期间，该部位或用途必须清晰可见；引线在运动中持续指向正确部位。讲解机构就展示该机构，不能配另一处表面或仅有氛围的美观镜头；不能把某模块的尺寸、部件名称或性能主张安到另一部位。图片不能单独证明材质成分或性能。准确文字、字体核验及获准替代继续遵守下方贴字规则；无字请求不主动加字。
4. **适配时间与画幅，不换一套设计**：完整时长分镜中写明主要可读停留阶段与原图对应的构图，以及允许的入场、退场、运镜或产品动作。改横竖画幅时，通过等比重构画面、调整间距和换行保留相对层级、产品识别、所述细节及图文关联；不能拉伸产品、裁掉证明细节、补造无依据的隐藏结构或套通用贴字模板。要求的动作或画幅与上述关键关系确实冲突时，先展示具体适配方案并获准，再生产；已批准的相同决策直接复用。
5. **映射必须进入实际生产**：每个镜头描述和实际制作参考都携带绑定原图、具体构图要点、对应细节、准确获准文案与允许动作；传入真实来源图片，不能只列文件名或用文字摘要代替。新增干净产品图与规划分镜图只能补充，不能挤掉对应详情图；参考数量限制使必需来源无法携带时，先解决制作路线。普通参考不自动变成精确首尾帧，除非用户明确要求该时序。文字分开合成时仍须与原图设计和被介绍的运动部位对应。
6. **在既有分镜审核中确认对应表**：使用下表，不另加重复确认轮次。缺少来源绑定、相关细节不可辨认、版本冲突或偏离未确认时，阻断受影响镜头，索取可读替代或最小必要决策；不能猜测、静默丢弃必需模块或套通用画面。完整图镜对应表是视频生产前置，原有美工图、创意和分镜确认门均保留。
7. **逐镜与各自原图验收**：将每个镜头的代表性构图／可读停留帧与绑定模块并排查看，再检查实际运动和文字时序。核对产品状态、视角、占比、位置、可见部位、场景、构图、准确文案、字体、引线、层级、可读关联和获准适配。只有产品相似但构图无关，或文字清晰却介绍不可见部位，均不通过。按镜头记录来源版本及通过／不通过／未检查，只修失败镜头或贴字，保留合格画面。元数据和导出成功不证明画面对应，无法审核时说明未检查项；本规则不授权重做已有媒体。

| 镜头／时间 | 来源图片／版本／详情模块 | 产品构图及可见细节 | 准确获准文案／事实依据 | 字体排版与图文关系 | 动作、可读停留及画幅适配 | 已批准偏离／验收结果 |
|---|---|---|---|---|---|---|
| 每个计划镜头填写 | 定位实际来源并区分贡献 | 视角、状态、占比、位置、裁切、背景和所述部位 | 准确原文或明确无字 | 层级、位置、标签及引线终点 | 文字可读时保持对应细节可见 | 无、已批准变化或待解决；成片后记录通过／不通过／未检查 |

### 视频贴字必须延续定稿美工图

当已批准的宣传片需要画内广告文案、规格、标签或CTA时执行本规则；不主动给无字视频加字，也不视为对白字幕授权。

1. **以定稿设计为依据**：制作贴字前，查看对应的定稿主图／详情图及可用的已确认文案或可编辑源文件。每个贴字镜头绑定具体来源图片与版本，沿用其已确认的准确措辞、语言、数字、单位和限定说明。选择与镜头相关的已有文字，不照搬整页；模糊字符或数字须与确认稿／源文件核对，必要时询问，不凭看图猜测。删改、翻译、新参数或新CTA必须在分镜中获得明确确认；图片里出现过的无依据主张也不能沿用。
2. **继承完整字体与排版体系，不只是复制文字**：记录标题／副标题／参数的层级、可核实的字体、衬线或无衬线特征、字重、相对字号、字距、行距、换行、大小写、对齐、文字位置、边距、色彩关系，以及原有描边、阴影、标签和底形。让原图直接承载配色视觉依据。不同镜头可继承不同模块职责，但须属于同一套设计；定稿图之间有实质风格冲突时请用户确定依据，不随意混搭。
3. **为视频适配排版，不重新换一套设计**：保留来源的层级、对齐、相对位置和留白，仅根据已确认的视频画幅、可读停留与主体运动调整尺寸、换行和位置。文字处于安全区，避开产品、人脸、猫爪及运动路径。入场、停留、退场采用与原设计协调的克制动效；只有经过批准且能力支持时才做贴附场景或跟踪文字。除非原美工图采用该样式或用户批准更改，不得默认套用白字半透明黑底字幕框、通用参数卡或无关装饰字体。
4. **核实字体与实现能力**：优先使用名称可核实、实际可用且已授权的原字体，或用户提供的已授权文字资产。仅凭平面图片不能确认具体字体名称。原字体未知、缺失或当前能力不支持时，说明限制，请用户提供字体／源文件，或确认视觉匹配的替代字体；不静默回退系统默认字体，不宣称精确复现。当前渲染方式无法还原已批准排版时，先解决可用合成方式或取得替代方案批准，不为图省事降低设计标准。
5. **分镜可审核，成片文字准确**：每个贴字镜头在分镜注明来源图、准确文案、字体层级／样式、位置、动效和可读时间，把贴字一起纳入分镜确认。改变样式时先提供针对性的预览或审核，再最终合成。生成文字难以稳定准确时，优先用干净视频画面加独立合成的同风格文字层；不能把整张平面海报盖在动态画面上，不能重复烧录已有文字或接受乱码。已批准的同一风格决策不重复询问。
6. **对照美工图验收成片**：将有代表性的视频帧与来源设计并排检查，并播放入场、停留、退场过程；核对文案数字、层级、字体外观、间距、对齐、配色、底形、可读性和动态遮挡。导出成功或元数据不能证明视觉一致。只修有问题的贴字／镜头，保留合格画面；无法验证时如实说明未检查项。原有美工图定稿门、Photoshop边界、字幕按需及成片30秒上限不变；增加本规则不授权重新生成已有媒体。

## 产品宣传视频分支

用户触发商品宣传片时，读取并在本 Skill 内执行 `references/product-promo-workflow.cn.md`。该内置流程来自用户提供的 promo-video：来源核验 → 产品视觉与创意确认 → 全时长 Hook-Body-CTA 分镜审核 → 能力检查 → 获准逐镜视觉 → 5秒镜头视频与获准音频层 → 资源齐备后合成导出 → 成片验收交付。不能用一次立即生成整片代替此流程。

执行上方视频模型二选一询问框：MiniMax H3 或 SD 2.0，不自动默认。仅复用本次同一视频任务已经明确确认的选择；首次视频生成前若尚未选择，则停止并询问。复用已确认简报、产品身份与视觉决策；方向未定时提出三种选择，并明确纯产品或人物路线。快速初版/一次性交付不豁免创意和分镜审核。用户要求“不实际生图”时复用已定稿且用户确认的电商美工图和逐镜视觉参考；某镜缺少足够视觉时请求补充或明确修改范围；没有已确认美工图时停在图片前置门；有条件的规划图不触发 Photoshop。依赖声音的生产开始前解决声音路线，字幕默认关闭；付费生产和最终合成前解决尚未批准的选择。仅方案请求停留在文档，修改 Skill 不授权媒体生成。不能把元数据检查或超时分析当作内容验收通过。

## 合规与时效性

涉及合规时读取 `references/compliance-rules.md`。该文件是保守执行框架，不是法律意见。

特别注意：

- 免责声明不能“修复”本身不允许的宣称。
- 绝对化、比较、价格、认证、健康/医疗、功效、用户评价等表达都要看证据和目标市场。
- 普通食品、保健食品/膳食补充剂、医疗器械、健康护理、儿童用品等不可混用同一套宣称逻辑。
- 平台规则、法律、监管政策和类目要求可能变化；能联网或有官方文档时优先核验。

## 关键失败模式

- **提前使用 Photoshop**：画布还只有底图或样稿时就排版、查看预览或批量存 PSD。改为先完成画布成品并获得对应版本最终确认。
- **把继续当定稿**：用户确认风格并要求做完剩余图片，不代表批准尚未展示的版本。继续画布制作，展示成品后再请求最终确认。
- **过度追问**：资料足够时仍不断问问题。改为明确假设并继续。
- **流程机械化**：纯策划任务被无理由反复打断。按执行模式处理；视频创意/分镜审核与 Photoshop 最终确认不属于可跳过的暂停。
- **固定 5 张**：不看平台和信息量硬凑 5 张。按视觉任务调整数量。
- **卖点堆砌**：一张图塞多个购买理由。每张图只解决一个主要决策问题。
- **平台规则过期**：把历史经验写成当前规则。需要时核验官方最新来源。
- **合规靠敏感词**：只删词不看宣称逻辑。必须看“事实 -> 证据 -> 用户理解”。
- **跨境直译**：中文文案逐字翻译。改做本地化重写。
- **参考图失真**：为了视觉效果擅自改变产品结构或包装。优先产品真实性。
