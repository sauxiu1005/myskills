# 声音设计

根据文字描述设计和预览自定义 AI 声音。

**语言规则**：始终使用用户使用的语言与其交互。

## 支持的语言

hub_design_voice 最佳支持：**中文、英文和日文**。其他语言的结果可能不稳定。如果用户想设计其他语言的声音，警告质量可能不理想并在继续前请求确认。

## 提示词编写指南

基本提示词结构：**职业 + 性格特征 + 声音特征 + 语速节奏**

好的提示词示例：
- 「一位充满激情和活力的体育评论员，语速快，声音洪亮，能够点燃气氛」
- 「一位古代侠客，声音洪亮正气凛然，充满豪侠之气，语速果断干练」
- 「一位温柔知性的深夜电台女主播，声音低沉磁性，语速缓慢，带有治愈感」
- 「一位开朗的年轻幼儿园老师，声音明亮清脆，语速适中，温暖鼓励」
- 「神秘的故事讲述者，深沉沙哑的声音，语速刻意放慢，营造悬念」

不好的提示词（太模糊）：
- 「一个好听的声音」——缺乏具体特征
- 「男声」——没有个性或风格描述

## 工作流程

### 步骤 1：改写提示词

从用户的描述中提取意图，改写为符合「职业 + 性格特征 + 声音特征 + 语速节奏」结构的高质量提示词。

- 如果用户的描述已经足够具体，直接使用
- 如果太模糊（如「一个好听的声音」），追问所需的职业/场景、声音风格和语速偏好
- 改写后向用户展示提示词待确认

### 步骤 2：确认语言

询问用户希望声音使用哪种语言（推荐中文/英文/日文以获得最佳效果）。

### 步骤 3：预览文本

询问用户选择如何提供预览文本：

1. **用户指定文本** — 直接提供预览文本（最多 200 字符）
2. **自动生成** — Agent 根据声音风格和语言生成自然、口语化的预览文本（15-30 字符）

自动生成规则：
- 文本应匹配声音风格（体育评论员得到激动人心的解说词，温柔主播得到舒缓的台词）
- 使用口语化、说话风格的语言，而非正式书面语
- 中文：15-30 字符，英文：10-20 词，日文：20-40 字符

### 步骤 4：调用 hub_design_voice

调用 `hub_design_voice` 工具：

```
prompt: <步骤 1 改写后的提示词>
preview_text: <步骤 3 确定的文本>
```

### 步骤 5：呈现结果

成功后展示：

1. 试听音频：`![试听音频](<trial_audio_url>)`
2. voice_id
3. 使用的提示词和预览文本

格式：

```
## 声音设计结果

<试听音频>

- **Voice ID**：`<voice_id>`
- **提示词**：<使用的提示词>
- **预览文本**：<使用的预览文本>

此 voice_id 可直接用于后续的音频生成。
```

失败时，告知用户错误信息并建议调整描述后重试。

### 步骤 6：迭代或保存

**必须使用 `question` 工具**（不要使用纯文本选项）向用户提出两个问题：

**问题 1 — 满意度：**
1. **满意，保存它** — 保存到记忆以供未来复用
2. **不满意，需要调整** — 收集反馈，调整提示词后重新生成（不要用完全相同的提示词+文本再次调用）

**问题 2 — 记忆范围（与问题 1 一同呈现）：**
- **当前项目（推荐）** — 保存到当前项目的记忆中。仅在此项目中可用；适合项目专用声音（如「这部短剧的旁白」、「这个播客的主播」）
- **用户级别（全局）** — 保存到用户级别的记忆中。所有项目都可使用；适合通用的个人声音资产（如「我的品牌声音」、「常用男播音」）

两个问题应包含在一个 `question` 调用中，让用户一次性回答。

保存格式：

```
voice_id: <id>
name: <用户起的昵称或 Agent 根据声音特征创建的简短名称>
prompt: <设计时使用的提示词>
language: <语言>
usage: <适用场景描述>
```

告知用户：「此声音已保存。你可以在未来的会话中通过名称引用它（如'使用 XX 声音'）。」
