# 旁白音色预设 v2.0

本表只用于旁白。人物对白必须保持视频原声，不能从本表生成对白。

本文件受主文件 v1.0.1 的交付边界、授权与停止规则约束。音色统一要求不是整批作废或追加生成授权；本文件不得启动最终视频装配、混音、烧录字幕或导出 QC。

## 选择原则

STEP 0 必须执行：先根据题材、情绪、目标平台（抖音 / 红果 / ReelShort 等）推荐 2–3 个音色，再让用户确认或试听。用户未选择时保持待确认，不把沉默当作选音色、试听生成或整批生成授权。

下列 voice_id 为预设命名约定。调用前必须向当前 MiniMax 音色目录校验；目录中不存在时展示“试听 / 自定义”并要求用户选择可用 voice_id，不得静默替换。

## 推荐逻辑（必须执行）

1. 先判定短剧类型：都市悬疑 / 情感婚恋 / 古风权谋 / 校园成长 / 逆袭 / 惊悚等。
2. 再判定叙事视角和情绪：第一人称或第三人称、冷静 / 紧张 / 温柔 / 爽感。
3. 结合平台推荐：抖音偏清晰、前置钩子和口语感；红果偏连续叙事、情感承接和耐听度。
4. 输出“推荐首选 + 备选男声 + 备选女声”，说明理由，让用户确认。

## 锁定规则

- 一集保持用户批准的旁白 voice_id 与 profile/参考音频锁；不得静默换音色。用户明确要求整集换音色时先版本化项目锁，再单独确认全量旁白生成范围与费用，保留旧版。
- 首轮旁白优先一条母轨；不支持母轨时，全部文本在同一 TTS batch/session 内生成。以下局部修复是获授权后可用的补充批次例外，不允许据此把首轮拆成逐镜零散生成。
- 项目锁记录 `speed`、`pitch`、`emotion`、`pause_policy`、`volume`、`sample_rate`、`codec`、响度目标及表达风格；这些值不得按镜头临时调整。默认 `speed=1.15`，清晰快速、钩子前置。相同参数不等于已验证听感一致。
- 禁止单镜加速来解决时间冲突；改写、拆句、移窗、拆镜或延长镜头只是待批准方案。批准脚本/时间线变更不自动批准媒体重生。
- 单行错误或局部漂移只标记受影响区间待处理，不整批作废。只改旁白不重生画面或对白原声；实际失效的时间元数据需回填并复查。

## 局部诊断与修复（v1.0.1）

1. 记录脚本行 ID、音频文件/母轨区间、批次、版本、实际听检/测量证据。区分 ASR 疑点、文本映射错误、无损切片边界错误和真实合成缺陷；无法确认写“未核验”，不扩张成整集失效。
2. 若只需修正标注或重切边界，在已批准的局部编辑范围内处理并复查；不得截掉实际说错的词来伪造通过，不改变原始录音。
3. 确需补录时先展示受影响行、上下文、保留文件、完整参数锁、输出数量、尝试上限、费用风险及停止条件。默认一次授权仅覆盖列明产物一次追加尝试，不包含重做其他行或整批。
4. 经明确授权，使用相同 voice_id、profile/参考音频与完整参数生成受影响行；为保持语气可使用必要上下文，但不得增加未批准台词。最小不可分割修复区间若必须包含邻句，应先将这些邻句列入授权，不自动扩展。
5. 如不能继续原 session，记录真实修复 batch/session ID 和父母轨，而非伪称同批。修复清单逐项记录：原文件及区间、替代文件及区间、脚本行/原文哈希、原批次、修复批次、音色锁、授权、检查结果、批准状态。新母轨若由不同真实批次组成，必须保留逐段来源和新文件哈希，不能覆盖原批次身份。
6. 对替代段执行逐字校验、实际时长测量及与保留片段的听感/参数一致性检查。检查前后衔接和受影响的全局 0.20s 间隔；未通过或未核验则保留为候选，不替换批准版。无法维持锁定音色或无法可靠接合时暂停并说明，不自动整批重做。

## 何时可提出整批重做

仅限已证实的整批共享音色/参数错误、不可分离且无法局部修复的母轨缺陷，或用户明确要求整集更换旁白音色。先说明为何局部方案不可行、哪些合格片段仍保留、全量行数/产物数、费用及停止条件；获得明确覆盖整批的授权才执行。选音色或单镜返工批准不能代替该授权。旧音频不删除，未批准新批次不替换现行版。

## 停止与交接

遵循主文件的累计上限：同一问题最多初次生成加两次追加尝试，跨批次/模型不清零。目标达到、次数/预算/时间用尽、用户暂停/取消、外部阻塞、无实质改善或需扩大范围时停止，报告已有结果与未解决项。不得以重新授权机械重启达到上限的同一问题。

旁白及检查资料交接后结束本 Skill；保留缺陷的待审交接不等于通过检查。本表既不要求成片，也不授权最终混音、字幕烧录、BGM/音效或导出 QC。
