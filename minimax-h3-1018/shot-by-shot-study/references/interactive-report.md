# 交互式报告：确认后生成可运行页面

本参考仅在同步拉片 MP4 完成后的用户选项卡获得肯定选择，或用户明确只要 HTML 时执行。默认流程先完成 MP4，不提前构建可选交互报告，也不让其依赖或验收阻塞 MP4。MP4 使用的 HTML/CSS 面板渲染不是交互报告，可作为视频制作步骤正常执行。

复用已有原片、分镜台账、标注、关键帧与质量记录，不重做已完成分析或 MP4。未选择或明确拒绝时，HTML 不属于缺失交付。用户确认需要后立即开始本节，不再询问是否开始。

“交互式报告”指运行 HTML/CSS/JavaScript 的页面，至少包含真实视频播放器、关键帧、镜头表、播放同步高亮、当前镜头自动跟随滚动和点击镜头跳转。Markdown 表格、画布文字节点、HTML 代码块、截图均不是这个交付。

## 使用现成渲染器

先检查随包实现、实际数据、执行与文件写入能力、依赖和预览能力。分别记录实现存在、环境可运行、文件已生成、交互已验证；不要未经检查就笼统说“不能生成”，也不把用户确认当作突破宿主限制的权限。

数据测量、视觉标注与校验完成且用户确认 HTML 后，在获准的项目工作目录运行：

```bash
node "$SKILL_ROOT/scripts/build-report.mjs" shots.json \
  --state analysis-state.json --video "$VIDEO_INPUT" \
  --frames frames --track track.json --out interactive-report
```

输出 `interactive-report/index.html`、原视频副本、frames/、shots.json、analysis-state.json 和 checks.json。样式及交互脚本内联；视频和图片使用包内相对路径。交付整个文件夹或其 ZIP，不能只上传 HTML 而丢掉原片和图片。此命令只做渲染打包，不会重新测量视频或核验素材身份。

跟随滚动扩展来自 `scripts/report-follow.js` 和 `report-follow.css`，由构建器内联到原报告中。原播放器用视频时间定位镜头并更新高亮；扩展在当前镜头改变时只滚动镜头列表，不推走整个页面。提供“自动跟随当前镜头”开关，关闭后用户可自由浏览。快切/拖动进度时即时定位，避免缓动队列落后于播放。

## 在 Design 中展示

先核查当前工具与预览容器。已检查的 Design 3.0.15 画布写入工具提供 text、table、media，text 用于 Markdown；不要把完整 HTML 写成 text 并声称能够执行脚本。

优先把报告放在项目可访问目录，通过平台真正的 HTML 预览或内置浏览器打开。若只有浏览器支持网页 URL，可在同一工作环境启动仅本机可访问的静态文件服务，并用其真实地址打开；不要假设不同主机的 localhost 指向同一个环境。使用 Design 的 browser 工具前，遵循该工具的前置技能要求；本技能不替代浏览器操作规则。

本地预览推荐使用随包服务（支持视频跳转所需的 HTTP Range）：

```bash
node "$SKILL_ROOT/scripts/serve-report.mjs" interactive-report
```

打开命令实际打印的 127.0.0.1 地址。服务仅绑定本机；仅在预览期间运行，结束后停止。不要用不支持 Range 的简易服务代替并假定拖动进度一定可用。

如果画布只支持 Markdown，就在画布放“交互式报告入口 + 摘要”，报告本体在浏览器中运行。不能把 .html URL 当作 image/video/audio 类型的媒体节点写入。没有可用预览时提供完整报告包，注明需要解压后在浏览器打开 index.html；不能称“已在画布交互展示”。

某些 WebView 禁止 JavaScript 或媒体，不能靠改节点名称解决。使用实际支持脚本的视频页面；不要关闭应用安全保护。如果页面读取原片失败，先核验包内文件、相对路径、预览服务及编码，自动修复有证据的问题；不得默认让用户再次选择已知原片。仅在确实无法自动绑定且用户明确接受手工恢复时，才使用“选择视频”入口。浏览器不支持视频编码时，在获准能力与用户约束范围内转换为可播放格式，保留时间基准并重新验收。

## 自动构建与绑定

按 [automatic-html.md](automatic-html.md) 完成真实文件写入、原片绑定、关键帧复用或补抽、启动预览、浏览器打开及验收。随包构建器会直接设置播放器的相对素材地址；正常加载不能依赖文件选择事件。若从已有 Markdown 源码恢复，须去除代码围栏、改掉必须手选文件的初始化，并交付可运行文件，而不是再次交付源码。

## 必须实际验证

1. 页面中存在播放器与关键帧，视频可加载和播放，图片没有缺失。
2. 播放跨过至少两个真实切点，当前镜号、文字、高亮随画面切换。
3. 定位到列表初始可见范围以外的镜头，确认列表滚动且播放器仍可见。
4. 点击镜头行（不要点关键帧图；图片用于大图预览），确认视频跳到该镜起点。
5. 向前和向后拖动视频进度、查看片尾，验证反向同步和末镜高亮。
6. 关闭跟随开关可自由浏览；重新开启能回到当前镜头。筛选隐藏当前镜头时不高亮错误行，清除筛选后恢复跟随。

脚本成功生成 HTML 不能替代上述验收；在 checks.json 补记实际结果。只能静态检查时明确“已生成，交互未实测”。静态报告仅可作为用户明确选择的交付或带说明的未完成替代。

交互 HTML 与同步视频是两种产物：HTML 可点击跳转，MP4 是已烧录画面/文字动画，不可点击镜头表。用户确认 HTML 后不能只给 MP4；视频交付也不能只给 HTML。

## 阻塞与恢复

用户选择拒绝时记录 `skipped_by_user`，不执行构建。未回答记录 `awaiting_user`，不推定同意。用户确认后若文件写入、依赖、执行或预览确实受阻，保留已完成 MP4 并记录具体条件；构建受阻为 `blocked`，实际文件生成但未验收为 `created_unverified`，交互通过后为 `verified`。

不要默认让用户复制 Markdown 中的源码另存为 HTML。只有用户明确接受这种替代交付时才提供，并标注源码而非已生成或已验收的报告。恢复时复用相同原片与分析版本的确认和成功产物，只补齐未完成项。
