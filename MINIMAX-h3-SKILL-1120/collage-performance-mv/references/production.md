# 制作规范

> 执行规则：视频质量默认由用户查看确认，用户通过即可采用或完成交付。本文的视听核验、逐帧检查、质量阈值与自动修复方法仅供用户明确要求排查/测试时使用，不作为默认生成或继续制作的前置条件。制作参数、素材约束与文件交付步骤仍执行。

## 音乐数据

保留原始混音音乐，获取真实时长、采样率与声道。口型驱动默认使用出镜规划选定时间范围的原始混音片段，保留伴奏与人声，不默认人声分离。分析用PCM/分离缓存与驱动音频分别标记用途，不能混用；截取规则与时码映射见[表演与唇同步](character-performance.md)。歌词取用户提供或实际生成内容，不依据提示臆造已唱出的词；转写/对齐后抽听纠错。

`music-map.json` 记录 audio_asset、duration_s、selected_range_s、bpm_estimate、beat_times_s、downbeat_times_s、sections、lyric_cues、analysis_method、confidence。空缺值用 null/空列表，不能编造数据。confidence 区分 measured/manual/estimated。

恒定 BPM 可按 `offset + beat_index * 60 / BPM` 建网格，但 offset/BPM 必须核对真实音频。变速音乐用事件列表。音量峰值适合驱动光晕，不能直接冒充强拍或音素。

自写 STFT/谱通量检测时先用已知时刻的短音脉冲校准时间原点，明确窗口起点/中心与滤波延迟。实测发现未校准检测可在自报约 6ms 局部误差时仍整体提前约 76ms。限定搜索窗内的最近峰误差不代表真实音画偏差；需对照原始波形瞬态与导出帧分别核验。句级转写也不能直接当逐字对齐，句内均分只能标 estimated。

### 随包分析工具

平台已有 Node 和 ffmpeg 时可直接复用，无需安装 librosa/scipy。先用当前环境实际可执行路径替换下面的命令名：

```sh
ffmpeg -i source.mp3 -ac 1 -ar 22050 -f f32le mono.f32
node scripts/analyze-beats.mjs mono.f32 22050 beats.json
```

脚本接收小端 Float32 单声道 PCM，分析 4–1200 秒区间；输出 70–180 BPM 内的恒定速度候选网格、局部波形瞬态与强度。保留截取区间的 source offset，合成时加回。它不证明音乐强拍语义，也不能处理任意变速或保证半速/倍速选择正确，需检查实际音乐段落。输出中的网格偏差仍是诊断值，最终同步要比较视频帧与原始音频。已用已知节拍脉冲完成时间原点校准；这不替代每首音乐的检查。

## 镜头与合成

进入镜头制作前，先按 [制作板规范](production-boards.md) 验收项目情绪板、主唱卡及用户选择需要的伴舞卡；未选择伴舞时不将伴舞卡作为制作门槛。原始照片和海报只作为来源；已完整的制作板可校验后复用，不完整的必须补齐。

视频生成前先完成覆盖全片的出镜分镜与视频需求清单，区分新生成、复用和无需视频；不得把全部人声段当作默认生成队列。只为选定主唱演唱视频截取混音驱动，伴舞与主唱静态贴图无需口型任务。先检查形式交替、主要唱段主唱存在感及累计表演覆盖，再提交小样；这不是新增人工确认关卡。

每镜字段：video_request_id、generation_needed、vocal_present、lip_sync_required、source_audio_range、shot_id、in/out、music cue、dominant_mode、new_visual_information、assets、composition、character_function、internal_action、cutout_transform、anchor、mask、z_order、graphic_response、mouth/lyrics、transition。视觉变化按 [视觉导演规范](visual-direction.md) 检查，角色动作和口型按 [角色表演规范](character-performance.md) 检查。

另记 character_form（collage/video/none）与最终帧区间，按视觉导演规范生成 character-form-summary：计划/实际拼图与视频帧数、秒数、各自占人物出镜时长的比例、无人物时长与检查结果。同时记录全片 performance/static_collage/other 主导类型和表演覆盖汇总；默认全片人物真实表演片段累计至少60%，主唱不设独立形式配额，静态拼贴不设10%或单次1–2秒硬限，用户覆盖值写入brief；主唱视频抠像后仍记 video，只有伴舞时记 none。主唱在含其声部声乐的每个视频使用区间绑定对应原始混音并交用户查看口型；器乐段舞蹈记口型不适用，照片动画单独记拼贴，不因MP4扩展名误记连续表演。

段落有视觉任务：建立身份/母题→动作和内容累积→高潮释放→结尾回收。默认以角色演唱和舞蹈推进，场景/物件及拼贴图形作短暂辅助，不机械轮换四类镜头。角色脸/发型/服装/标志物保持一致。多视图卡先分离主体或生成单视角，不在成片反复移动整张拼板。主唱、伴舞与场景分层。优先用已核验支持参考引导表演的 MiniMax H3 制作角色内部动作，用户指定且能力相符的模型优先，首次视频提交前取得用户720P/1080P选择；只需人物层时以均匀纯色背景生成并动态检查抠像，分镜明确保留棚景时才使用受控摄影棚背景，由代码控制剪辑、必要的空间编排、少量歌词及最终合成；只有用户明确选择 code_only 时禁用视频模型。

代码动画用唯一 `renderAt(t)` 或等价绝对时间函数：预览以 audio.currentTime 为主时钟，离线逐帧用 n/fps，seek 后从 t 重算，不靠前一帧累积。视频素材记录 timeline_in/out、source_in/out、source_fps、timebase 及对应的音频区间；逐帧等待目标源帧和同时间遮罩解码就绪再合成，不把异步 seek 后的旧帧导出。演唱素材默认 `source_t = source_in + (t - timeline_in)`，循环或重映射时仍须保持实际歌词口型对齐；外部贴图运动独立变化。RGB 与 matte 的帧率、起点和长度一致，并在浅色和深色底上核对边缘。资产可离线读取；本机路径不是远程媒体 URL。

口型记录演唱者 ID、实际音频区间、生成/驱动方法与验收证据。代码嘴形路线还需真实字词/音素 cue、嘴形资源与过渡；音频驱动视频工具未提供音素时如实标注，并提供对应原音轨供用户查看，不能虚构 cue。风格化 viseme 可简化但说明粒度；音量张闭嘴只是节奏嘴部动画。歌词图形 cue 与口型 cue 分开：一个按可读/强调策略排版，一个跟真实发音。未做口型不能称 lip-sync。

MP4 保持比例不拉伸，音乐与视频用同一区间，短预览选乐句终点；淡出须记录。不能每镜重复叠加同一音乐。除用户要求外静音非主音轨。

## 合成清晰度与纹理控制

在shot-plan/asset-manifest记录景别、源人物区域有效像素、最终人物显示尺寸与缩放关系。主唱以半身/近景/面部演唱片源为主，全身只少量使用；不要从全身视频裁脸再大幅放大。图层缩放从原始高质量片源按最终尺寸一次采样，避免先缩成小贴图再放大；RGB与matte同尺寸、同帧同步，羽化只作用于轮廓，不模糊整个人物。避免全身层过小后失去脸部和动作细节，也不为铺满画面超过有效源像素过度放大。

默认关闭最终画面的噪点/颗粒叠加，保留背景和相纸上的轻微纸纹；不在人物脸、眼睛、嘴唇、头发和歌词上加噪。避免重复有损中间转码、低码率导出与过强锐化/降噪，按实际目标分辨率输出，不能把高码率或上采样描述成细节恢复。源片确实不清晰时，优先调整景别或显示尺寸；改变用户选定的原生生成分辨率须先取得其选择。清晰度与颗粒效果交由用户观看确认，不新增自动逐帧验收。

## 用户验收与交付准备

生成或合成任务成功后确认有真实输出文件、正确素材引用和可访问的项目预览预览。提供视频给用户查看，简短询问“这版是否通过，还是需要修改？”。以用户意见为质量验收依据，按SKILL.md记录版本、范围和通过/修改状态。用户通过即可进入后续制作或完成交付。

默认不执行自动口型、节拍、动作、动态边缘、逐帧遮挡评分、盲测及复现重渲染，也不因这些检查未运行阻塞用户已通过的素材。保留原混音、人物层级、正确时码、指定清晰度、至少60%表演及形式穿插的制作要求；它们用于规划和合成，不变成额外自动验收关卡。用户指出问题后只诊断对应区间，不自动重做全部素材。

## 可移交的合成工程

保持运行入口期望的目录层级，不能把嵌套源码扁平复制后仍声称可运行。交付渲染入口、场景代码、图片/透明帧或 RGB+matte、唯一音轨、节拍/歌词数据、依赖清单及最短运行命令。清单引用交付目录内的相对路径；平台资源另记真实 ID。系统字体或架构相关 FFmpeg 二进制注明替换方式，不宣称跨平台开箱即用。

仅用户要求复现或排障时，从交付目录选含人物与歌词的短段重渲染。复现不触发生成模型。原始模型视频与中间结果可另作归档，但合成必需资产不能只留在临时目录。记录 latest_final、latest_boards、source_entry 与项目预览最终节点，旧版与最新版分开。
