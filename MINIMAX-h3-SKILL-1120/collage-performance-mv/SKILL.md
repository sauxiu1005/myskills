# 拼贴表演音乐 MV

使用当前项目实际能力执行；默认生成视频后交由用户查看和验收。

默认成片是**平面视觉效果与主唱表演相结合的音乐 MV**：以平面拼贴、人物贴图、纸纹、剪贴照片、分屏和动态排版，配合主唱唱歌、舞蹈、走位与情绪表演；用户选择需要时加入伴舞。保留原有拼贴视觉语言，将动态人物融入平面画面，文字和图形围绕人物点缀。可保留少量符合场景约束的摄影棚表演镜头，但整体应体现平面设计与表演的结合，不能只交付普通棚拍视频直拼。Agent 负责策划、工具编排和代码合成，不是媒体生成模型。

**人物真实表演片段累计默认至少占全片60%；取消旧1:1、主唱独立80%及静态拼贴10%的配额。** 主唱以唱歌、舞蹈、走位与情绪为重点，文字与图形在人物周围点缀。允许站姿照片平移、缩放、定格及短动作反复循环，不因这些手法本身判失败，也不设照片单次1–2秒硬限。循环中实际可见的连续人物动作可以计入表演；照片或定格即使平移缩放仍记拼贴，二者按最终画面如实统计。真实表演可以间歇穿插，不要求连续出现、长镜头或整段唱跳。静态人物也可以作为平面贴图移动、缩放、切换姿势、复制和循环；主唱需在主要唱段有实质存在感；60秒成片累计至少36秒真实表演，其余时间自由安排平面拼贴、场景或转场，拼贴也可与表演全程叠合。

**有声乐时，主唱角色以视频形式出镜必须对上该区间真实歌曲的口型；伴舞无需对口型，也不要求跟唱。** 这是对已规划且实际采用的主唱视频区间的要求，**不是所有含人声的区间都必须生成主唱视频**。先规划主唱 video/collage/none 的出镜时间轴，再为选定的演唱视频镜头截取对应的原始混音片段（保留人声与伴奏）作为驱动，不默认分离人声。未选为视频的唱段可用静态人物、拼贴、文字或已规划的伴舞呈现；选为主唱视频的唱段不能用只舞动或随机张嘴的视频替代。明确的伴舞/非演唱角色与纯音乐段不强迫跟唱，但不得将主唱改标为非演唱者来绕过要求。按对应原混音制作主唱口型，生成结果交用户查看；用户通过即可采用，不以自动口型验证作为继续条件。

**默认混合制作：图片模型做美术资产，视频模型可做角色表演/唇同步，代码负责人物贴图运动、歌词、图形、剪辑与导出。** 不再默认禁止视频模型，也不将混合成片称为纯代码视频。用户明确要求纯代码时才采用代码角色路线；当前用户的最新制作边界优先于旧轮次限制。

先读 [制作与交付](references/production-handoff.md)。制作前读 [标准情绪板与角色卡](references/production-boards.md)，设计镜头时读 [视觉导演与贴图合成](references/visual-direction.md)，角色动画时读 [表演与唇同步](references/character-performance.md)，导出前读 [制作与验收](references/production.md)。原帖观察与新增规则分开记录在 [来源](references/source.md)。

## 默认由用户验收视频

视频生成后提供可播放预览或项目预览节点，请用户查看并选择“通过，继续”或“需修改”（可提供时间码及修改意见）。可把同批片段合并一次询问，不要求逐镜逐项确认。仅在需要采用这批素材继续制作时等待该批结果；独立的素材整理可以继续。代表小样与最终成片同样由用户确认。用户已有明确通过意见时直接采用，不重复询问。

默认不执行自动口型评分、盲测、负对照、逐帧遮挡/边缘/动作验收或自动质量重试；这些仅在用户明确要求排查、测试或修复时按需开展。生成、导入所需的文件存在、任务状态、参数与预览可访问性检查仍保留；它们是交付准备，不是质量验收。不能预览时先恢复交付通路，不能把错误任务当成已生成。

用户确认即完成相应版本与范围的质量验收，记录 acceptance_status=user_approved、reviewer=user、asset_version、reviewed_range 和用户反馈；未回复为 awaiting_user_review，拒绝为 changes_requested。自动检查未做记 not_run，不把用户认可写成模型逐字口型实测通过。用户通过后，不因缺少自动评分或原有“未验证”标记再次阻塞、重生或追加验收。用户未通过时只修改其指定问题，技术失败与质量反馈分开处理。

## 四项输入与必做制作板

先检查消息、附件和项目预览，复用已给的信息，不反复索要。

| 输入 | 条件与处理 |
|---|---|
| 创意提示 | **必填，由用户提供**。没有时询问主题/故事/视觉创意，不替用户编造后启动生成。 |
| 音乐 | 有音频就锁定；没有则请用户给平台内音乐生成提示，或采用你提出的建议。 |
| 视觉参考 | 海报、截图、单图或情绪板都是风格输入，不自动等于本次标准情绪板。缺失时请用户给视觉提示，或采用建议在平台生成。 |
| 角色参考 | 单人照片、简单人物图或完整卡都是身份输入，不自动等于生产角色卡。缺失时请用户给角色提示，或采用建议在平台生成。 |

缺多项时合并询问，给“上传素材 / 按建议在平台生成 / 修改提示”的简短选择。用户已授权按创意补齐时直接做，不要求用户自行去外部找素材。

**无论是否上传参考，都保留“制作本次情绪板”和“制作本次角色卡”两个独立步骤及交付节点。** 非标准参考必须经生图/编辑与版式整理形成项目制作板；简单人物照片必须扩展为多视图、表情和细节卡，不能直接跳到动画。已有完整标准板可经检查、补缺和项目化整理成为本次板，不为重复生图而重复生成；记录复用/补充范围。

主唱卡采用原帖的信息结构：四向全身、表情行、服饰细节行、角色信息与色板。**伴舞卡为可选项。** 用户未表态时简短询问“是否需要伴舞？无需伴舞 / 需要伴舞”，可合并到输入询问中；已明确需要或不需要时不重复询问。仅在用户选择需要后制作成员、转面、队形和细节卡，不能仅因 K-pop 风格或参考图有群体就自动添加。尚未选择时继续情绪板和主唱卡等独立工作，不生成伴舞资产；选择无需伴舞时跳过相关生成与验收，标记 not_applicable。卡片通过后导出单视角和独立素材，不能拿整张多格卡当人物层。

记录时长、比例、场景限制、语言、文字策略和演唱者。未指定画幅按 16:9；已要求完整歌曲时采用全曲，不以小样代替成片。摄影棚、无舞台、无外景等限制同时作用于制作板、角色视频和最终合成。默认对真实歌词的关键词/Hook 做动态排版，不强制全曲字幕。纯音乐不虚构歌词，非演唱者不跟唱；明确无字或不唱时沿用用户选择。

## 能力与制作模式

执行时核对当前项目实际使用的 Agent；不偷偷更换 Agent，也不修改全局默认。

分别检查音乐与图片生成、参考引导人物动作、歌曲驱动口型、分割、音频分析和代码导出能力。当前能力满足镜头时，优先使用 MiniMax H3 制作参考引导表演；用户指定且满足要求的模型优先。支持动作不代表能按指定歌曲准确演唱，生成前核验所选清晰度和音频参考能力，必要时按[表演与唇同步](references/character-performance.md)增加独立口型阶段。缺少能力时说明缺口，对结果有实质影响的替代先确认，不静默降低清晰度。

默认记录 visual_mode=flat_graphics_character_performance、render_mode=hybrid_character_video_code_composite、image_generation=allowed、video_generation_scope=character_performance。角色素材可用 video_model / provided_clip / code_rig / static_cutout，每项注明来源。模型视频提供完整可读的人物表演；独立人物层默认纯色棚底生成再抠像，分镜明确保留棚景时可使用受控摄影棚背景。字体、剪辑、辅助图形和最终合成保留在代码工程中。

用户明确只用代码时记录 render_mode=code_only、video_generation=forbidden，使用分层/网格/嘴形路线；不能达标如实说明，不暗中调用视频模型。模型或权限缺失时保留有效板与素材，说明限制，不把失败当成功。

### 视频清晰度与人物片源背景

**首次生成片段前（包括动作/口型小样），询问用户：“人物视频需要哪种清晰度？720P / 1080P。”** 使用当前可用的选择方式；没有选项时简短文字询问。已有本项目明确选择则复用，不重复问；最终成片尺寸不等于源片生成清晰度。未回答时继续音乐分析、制作板及分镜，暂不提交视频请求，不自行默认一档。将选择应用于本批主唱/伴舞小样、正式片和补片；记录生成实际尺寸，不能用上采样冒称原生1080P。具体参数、横竖屏像素与费用以当前能力为准，最终合成尺寸另行记录。

**仅供抠像的人物动作片默认使用均匀纯色无缝背景。** 先检查人物服装、肤色、发色与配饰，选择不与主体冲突的纯色；白底只是选项，浅色衣服/袜子/发丝不宜默认白底。生成用单视角参考也应匹配所选纯色，避免图生视频沿用复杂布景。原有情绪板和最终 MV 仍保持风格化摄影棚/拼贴背景，纯色只是中间制作背景。按[人物片源与抠像规则](references/character-performance.md)先做动态抠像小样，再扩展生成。

## 顺序与可编辑数据

创意及输入 → 锁定音乐/分析 → 标准情绪板 → 标准主唱卡（用户选择需要时追加伴舞卡） → 全片出镜时间轴与视频需求清单 → 仅对选定视频区间截取原始混音 → 单视角素材/角色表演视频 → 用户查看并确认视频素材 → 平面效果与表演穿插小样 → 完整代码合成 → 可编辑时间线及 MP4 导出 → 提供可播放预览 → 打包复现资料。平台具体执行与失败恢复见 [制作与交付](references/production-handoff.md)。

**首次视频任务前先保存全片出镜规划，代表小样也从规划中选取。** 分镜区分主唱视频、主唱静态贴图、伴舞和其他画面，明确每个视频镜头的起止时间、动作/演唱用途、生成或复用、对应音轨区间与转场动机；不能根据人声检测结果把整首歌曲的全部唱段直接加入生成队列。全片至少60%是人物真实表演的累计目标，不是60%人声或所有主唱声乐必须视频化。原始混音的截取、试听与时码映射见[表演与唇同步](references/character-performance.md)。

方向已明确时自动推进，不增加机械审批。生成任务遵循实际授权与预算；只修失败资产，未知状态先查询，技术失败针对原因在授权内重试一次，再选择兼容替代或停止。

保存这些项目资料：

1. brief：提示、规格、制作边界、实际 Agent、场景和文字要求、伴舞选择（需要/不需要/待选择），以及视频模型偏好、已核验模型名称、用户选择的720P/1080P、选择依据和最终合成尺寸。
2. board-manifest：用户原参考 → 项目情绪板/角色卡 → 单视角资产的版本、节点与检查结果。
3. asset-manifest：静态图、动作视频、matte/alpha、字体、嘴形、来源模型/工具、任务与选用状态；视频另记 requested_resolution、actual_dimensions、background_mode、background_color、keying_method、matte_review_status。这些是制作记录字段，不是平台 API 参数。
4. music-map：实测时长、选段、节拍/乐句/歌词、方法与置信度。[节拍分析脚本](scripts/analyze-beats.mjs) 不负责音素对齐。
5. shot-plan：生成前覆盖全片，记录每镜音乐触发、视觉任务、角色功能、内部动作、贴图运动、层级/遮挡、歌词/演唱关系、素材和转场；video_request_id（非视频镜头为空）、generation_needed（新生成/复用/无需生成）、source_audio_range、vocal_present、lip_sync_required、shot_size（半身/中近景/面部特写/少量全身）、source_subject_pixels、composite_subject_pixels；注明 character_form、dominant_mode 与独占计时区间，汇总人物表演覆盖、主唱真实表演累计比例、静态拼贴独占时长及计划/实际差异。
6. performance-map：动作准备/强调/回收，角色片源与全片时间映射，演唱片段和逐片段口型核验结果；无声乐/非演唱角色记录不适用理由。

用户中途换装时先更新标准卡，再更新单视角和受影响表演素材；所有引用指向同一有效版本，旧版只保留历史记录，不能混入新片。情绪板若沿用旧造型仅能标为氛围参考，正式服装依据须明确。每阶段完成后更新记录，避免 brief 与素材清单仍指向旧版本。

## 平面人物与真实表演交替配合

**两种形式须从片头到片尾合理穿插。** 静态人物的平面动效与真实演唱/舞蹈/走位/情绪片段分布在各音乐段落，按节拍、歌词、动作和情绪交接；避免前半段一直静态、后半段一直真实表演，或反过来。可以交替切镜，也可以在同镜中由静态贴图过渡到真实表演，再回到平面构图；不机械固定每隔几秒切一次。分镜表标明两种形式及衔接动机，验收按片头、前中后段、片尾检查分布，而非只检查总比例。

角色分成**内部表演**和**外部贴图运动**两条轨：内部是嘴形、眼神、头肩、手臂、衣发；外部是裁切、位移、尺度、旋转、显隐、复制、队列、层级、遮罩和进出画。主唱贴图仍可在内部演唱或做手势；整张人像弹跳不等于角色表演。

人物与平面视觉共同构成MV：主唱以半身动作、中近景演唱和面部特写呈现口型与情绪，少量全身/中全景用于清楚可辨的舞步亮点。真实表演可以按节拍截成短段，间歇穿插在平面静态人物动效中，不要求长镜头、整句持续出镜或每镜完整舞蹈；保留可读的动作重点与手脚空间。抠像人物可以持续跳舞和唱歌，可以随节拍入画、复制或缩放；摄影棚实景/受控布景镜头同样允许。主唱和伴舞职责明确。

按音乐选择动作、情绪或演唱亮点，允许短段、跳切、循环和静态人物动效交替；准备—发力—回收仅是可选编排方法。主歌用有语义的手势、视线、走位和细腻情绪；预副歌累积重心与步伐；副歌以半身律动、手臂动作、演唱特写及主唱与伴舞互动释放情绪，少量清晰的全身舞蹈作点缀；桥段用连续的近景表演降低密度。不同段落更换动作任务，可重复动作呼应节拍，结合平面编排保持节奏。主唱在自己声部的声乐段仍需对口型，器乐间奏可专注舞蹈。

保留拼贴效果贯穿画面，文字与图形围绕人物安排，突出关键词、Hook和动作落点。照片平移缩放、贴纸复制、短动作循环均为可选手法。避免大字长期占据中心、遮挡嘴/手/脚、纸片频繁遮住舞蹈或独占整段乐句。平面效果与人物动作应互相配合；人物表演区间仍应清楚呈现唱歌、舞蹈、走位或情绪。

## 主唱景别与清晰质感

主唱视频以**半身动作、中近景演唱和面部口型特写**为主，让眼神、嘴形、表情、头肩律动与胸前手势承担表演。全身舞蹈只作为少量短暂的节奏亮点，不默认整段副歌全身唱跳；半身/特写与平面拼贴仍贯穿交替，人物真实表演累计至少60%的目标不变。角色卡仍保留四向全身设定，不能把角色卡规格误当成视频景别配额。

半身和特写应直接用相应景别的清晰单视角生成，不从低分辨率全身视频裁脸后大幅放大。少量全身片源让人物在源画面中充分占据有效像素并留动作边距；按合成实际显示尺寸安排，避免低清人物放大、多人小窗反复缩放和过强运动模糊。清晰度不足时优先缩小采用尺寸或改用专门生成的半身/特写；需提高原生生成分辨率时沿用用户选择机制，不擅自升级，不用上采样冒称细节恢复。

保留纸张、撕边、杂志排版与剪贴感，**降低颗粒和噪点存在感**。默认关闭全画面动态噪点与重胶片颗粒，纸纹只在背景/相纸上低对比度使用，人物脸、眼睛、嘴唇和头发保持干净清楚；避免多层噪点叠加、脏污滤镜和压缩噪声。具体合成方式见[视觉导演](references/visual-direction.md)和[制作规范](references/production.md)。以上是制作默认，不新增自动验收；视频仍由用户查看确认。

## 人物优先图层与防遮挡（硬规则）

人物（主唱、伴舞、人物静帧贴纸）在每一帧都是最上层可见主体。合成按固定层序绘制：纸张底/纹理 → 背景大字、色块、圆环等图形 → 照片框/相纸/卡片底 → 横幅、条码、标签与歌词文字 → **人物层** → 不改变遮挡关系的调色、闪白和淡出（全画面动态噪点默认关闭）。

- 文字、歌词标签、照片框线、条码、横幅、色块、贴纸复制和重影不得画在人物之上；需要“人物穿出画框/文字”的拼贴效果时，把框或字放在人物后面，让人物压住它们。
- 照片框/接触印样中的人物用“相纸底在后 + 抠像人物在前并可越出框边”的方式实现，不把人物裁进矩形内，避免框线切断手臂、手和脚。
- 歌词与标题按人物实际遮罩（含舞动外扩边距）避让，不放在人物身体、脸、嘴、手的轨迹上；放不下时缩小字号、换位置或改到无人物的拼贴镜头，而不是压在人物上。被人物部分压住的背景大字可以接受，但被压住的歌词需保持可读。
- 横幅与画幅边缘不能裁掉头部；半身构图只允许在画幅下沿自然截断，不用横幅盖住人物。
- 代码合成器把人物放入独立的延后层统一最后绘制；按需保留人物遮罩；不能依赖各镜头渲染函数自行记住顺序。

人物层级与歌词避让仍是制作要求；默认由用户观看生成视频判断效果，不强制输出逐帧遮挡报告。用户指出遮挡时再定位并修复对应镜头。

## 生成、用户确认与交付

按镜头计划生成角色视频，放到项目预览供用户查看；用户通过后采用。可先提供4–8秒角色片段或8–12秒代表合成，再按用户反馈继续全片，不强制执行自动动作、口型、边缘或节拍验收。主唱演唱仍按选定原混音驱动，伴舞无需对口型；平面与人物表演合理穿插的设计要求不变。

全片使用唯一主音轨和绝对时间轴；保存片源入出点、混音裁切范围与已知偏移，未知偏移如实注明。生成片自带音频默认静音。交付MP4、源工程、制作板和实际素材记录，通过实际可访问的文件或预览交付。确认任务成功和结果可访问后请用户查看；不再强制操作暂停、跳转和片尾回放。用户通过最终版本即完成质量验收，不重复增加自动验收关卡。

保存合成实际依赖的图片、透明帧/遮罩、音轨、cue、字体说明和运行入口。默认不追加复现重渲染测试；用户要求复现或排障时再执行。仅更新Skill或结构校验不等于已制作视频，生成成功不等于用户已确认。
