# 综艺花字视频制作

制作一支 10 秒、经典中国综艺后期风格（综艺花字）的动态设计短片：多层描边胖圆体字在笑点上弹性入场，
按情绪搭配装饰符号（放射线爆炸框、汗滴、闪光、印章）和打击音效，底层是用用户照片或视频做成的“素材感”画面。
目标是高端商业水准，绝不能像模板。

本 Skill 不预设故事、品牌名、文案和配色——全部由用户自述要求和上传素材决定。画幅由用户从五种比例中选择。

严格按 9 个步骤推进。Step 1、2、3 结束时请用户确认（在耗费较大的渲染工作之前）；之后的步骤连续执行，
除非用户要求逐步审阅。

## 固定技术规格（所有比例通用）
- 30 fps，精确 10.000 秒（300 帧），H.264 MP4（yuv420p），立体声 AAC 48 kHz。
- 音频母带 −14 LUFS 综合响度（±0.1），真峰值 ≤ −1 dBTP，以最终 MP4 解码后的实测为准。
- 每一帧都只由时间 t 决定：随机数固定种子，物理效果用闭式计算，不用实时时钟、不用状态触发的 CSS 过渡。
- 素材仅限 CC0 / 公有领域 / OFL / Apache / 可免费商用、用户自有上传或自行生成的内容。
  除非用户拥有，不使用真实商标。每项来源和授权写入 CREDITS.md。

画幅选项（开始制作前用户必须选定其一）：

| 比例 | 像素 | 常见用途 |
|---|---|---|
| 9:16 | 1080×1920 | 抖音 / Reels / Shorts |
| 16:9 | 1920×1080 | B站 / YouTube 横屏 |
| 1:1 | 1080×1080 | 信息流方图 |
| 3:4 | 1080×1440 | 小红书 |
| 4:3 | 1440×1080 | 传统电视 / 横屏信息流 |

## STEP 1：收集需求并锁定画幅
- 请用户自述要求，所有创意位置留空，按用户的话填写：主体 / 故事、品牌或节目名、花字文案、配色、情绪、目标平台。
- 读取用户上传的视频或照片：主体、构图、可用裁切、脸/眼睛位置、画质。
- 以选择题形式给出五种比例并等待回答，不要默认竖屏。
- 如果需求较少，提出 2–3 个简明方向（故事走向 + 文案 + 配色）供用户选择。
- 产出：简短需求单（主体、故事、文案清单、配色、比例、平台），请用户确认。

## STEP 2：创意方案与情绪弧线
- 一个清晰的想法：0.5 秒内出现开场钩子（空画面或黑场不超过 0.3 秒）→ 逐步升级 → 在全片 60–75% 处放置唯一且明确的高潮 →
  结尾定格 0.8–1.2 秒并保留微动作。
- 忙与静要有对比，能量跟随音乐。
- 产出：用 3–5 句话说明情绪弧线，请用户确认。

## STEP 3：节拍表与唯一的提示表（cue sheet）
- 把每个风格特征对应到具体时间点（以下为角色示例，文案来自用户）：
  三层描边标题 → 弹性 pop 句子 → 歪斜手写风的小声吐槽 + 汗滴 → 弹跳问号 + 搓碟音 →
  放射线爆炸框 + 速度线 + 闪白中的高潮大字 → 夸赞句 + 闪光 → 结尾认证印章。
- 花字比对应的声音/画面节点晚 2–3 帧出现。
- 写出唯一的机器可读提示表（如 cue_sheet.json）：每条包含 id、起止帧、文案、花字样式、装饰、音效名、镜头动作（推近、晃动）。
- 经验教训：画面渲染和音频生成都必须从这个文件读取全部时间，绝不能在代码里另写一套时间——之前的制作就因此导致画面与声音不同步。
- 产出：节拍表（时间码 / 文案 / 画面 / 音效 / 对应风格特征），请用户确认。

## STEP 4：搭建花字视觉系统与关键帧
- 字体：使用可核实开源授权（OFL/Apache）的粗圆体 CJK 展示字体。检查文案中每个字和标点都有字形，不能出现豆腐块或静默回退。
  非开源授权的系统字体不符合规格——之前的制作曾因此被标为不合格。
- 三层字体结构：渐变填充 + 粗白描边 + 彩色外描边和/或偏移投影。
- 情绪匹配：吐槽/小声 → 歪斜手写风；惊讶 → 放射线爆炸框；尴尬 → 汗滴；夸赞 → 闪光；认可 → 印章。
- 底层画面：用户照片/视频做缓慢 Ken Burns 推拉、带种子的轻微手持晃动，在笑点处快速推近。
  尽量使用多个裁切或多张图片；只用一张图会显得呆板。
- 按比例排版：约 5% 安全边距；针对所选比例重新构图（竖屏上下堆叠、横屏左右布局），不要把竖屏排版直接缩放。花字不要挡住主体的脸。
- 在提示表时间点渲染 6–10 张静帧并亲自查看。动画前修正任何拥挤、默认感、贴边被裁或普通的地方。

## STEP 5：编排动效
- Pop 入场：约 8 帧内缩放 0 → 1.15 → 1.0，带轻微旋转；逐字弹跳，每字错开 2 帧（按单字实现，不能整行一起动——曾被漏做，结果显得像模板）。
- 预备动作、过冲、跟随，撞击时挤压拉伸；驻留时轻微摆动保持活性。
- 退场由元素带动（弹出、滑走、爆开），不用淡入淡出。
- 低分辨率预览，逐帧检查最快的动作，去掉无意义的空档。

## STEP 6：配乐与音效
- 弹跳感综艺配乐：拨弦、贝斯、拍手；选择让主要卡点落在节拍上的速度。
- 音效（合成或 CC0）：boing、pop、叮、滑哨、搓碟、嗖、盖章声。
- 所有音效时间都从同一个提示表读取。检查画面卡点与声音起音对齐（花字晚 2–3 帧）。

## STEP 7：全分辨率渲染与编码
- 以所选分辨率渲染全部 300 帧，快速动作适当加运动模糊。
- 编码为 H.264 + AAC 立体声 48 kHz 的 video.mp4。
- 检测核对：时长 10.000 秒、300 帧、分辨率、30 fps、有音轨。

## STEP 8：响度母带与合规检查
- 母带到 −14 LUFS / ≤ −1 dBTP，然后测量最终 MP4 本身（看分析的输入值，而不是标准化器预测的输出值）。
  AAC 编码会改变响度和峰值；保持视频流直接复制，只用小幅增益反复调整，峰值上限取 −1.5 到 −2 dBTP 留余量。
- 检查：无黑帧、无豆腐块/回退字体、边缘无裁切、细线无闪烁、渐变无色带、CJK 标点正确、文案与确认的需求完全一致。
- 核实每项素材和字体授权，写出 CREDITS.md。

## STEP 9：交付与自评
- 将 video.mp4、REPORT.md、CREDITS.md 作为一个影片对象保存到项目中（成片、制作报告、授权说明）。
- REPORT.md：两句话概念；时间码节拍表；每个风格特征如何实现；技术路线；实测数据（时长、帧数、分辨率、帧率、声道/采样率、LUFS、真峰值）；
  诚实的 1–10 分自评（风格还原、创意惊喜、动效工艺、设计与字体、质感、声音与卡点、技术）以及三大不足。
- 保持诚实：列出 Step 3–8 中任何未实现的内容。没有实测或视觉检查支撑，就不能声称某项要求已达成。
- 请用户审阅成片，尤其是高潮时刻和结尾定格。

## 失败处理
- 字体缺字或授权无法核实 → 换成已核实开源授权的圆体并重新渲染。
- 编码后响度不达标 → 只调整音频增益，视频流直接复制，重新测量最终文件。
- 从隐藏工作目录交付失败 → 先把文件复制到可见的工作区文件夹。
- 用户素材太弱（模糊、主体太小）→ 告知用户，并提供风格化插画场景作为替代。
