# Design 平台适配

## 加载与能力发现

技能以单根目录安装：`isometric-miniature-world-animation/SKILL.md`（英文运行文件）、`SKILL.cn.md`（中文运行文件）、`meta.yaml`、`references/`、`assets/`、`vendor/`。仅复制 SKILL.md 会丢失源码参考。用户本地技能目录为 `~/Movies/Hub/skills/`。

仅制作技能时交付包；用户要求导入/更新时，再经当前平台真实的本地技能导入入口操作，核对名称、版本与内容。不要把本地技能目录写入视为 Design 已加载，也不创建未经验证的展示样片。

执行作品前从实际工具文档/界面确认：项目目录与文件能力、Node/运行时、WebGL 浏览器、允许的截图或渲染路线、FFmpeg/ffprobe、素材上传、视频节点和工程附件。工具名、参数、资源 ID 和导出入口以当前环境为准，不猜内部 API 或操作数据库。

用户指定国内/海外版时沿用目标平台。云端与本机不默认共享路径；本地绝对路径不是云端可访问 URL。只读源码、设计分镜不需要为了平台连接而停下。

## 制作阶段

1. 在作品项目建独立目录，按需复制参考模块。记录 `skillRoot/projectRoot`、所用库版本与字体。
2. 用当前允许的浏览器/代码执行能力验证 WebGL、字体与代表帧。独立无头浏览器只有在宿主允许时启动；不得连接用户已有浏览器调试端口来绕过限制。
3. 临时帧和缓存放在平台不会自动收录的位置，先用一张测试帧确认行为，再做整段渲染。
4. 低分辨率预览与最终视频使用同一工程；用户反馈映射到时间码和对象 ID，不重置已接受的其他设计。
5. 通过正式生成工具补素材时记录实际任务、模型、资源与状态；默认等轴画面由代码生成，不因“做动画”自动提交文生视频任务。

## 画布交付

先对本地最终 MP4 做完整解码与关键帧检查，再使用目标项目正式上传或导入入口。记录上传返回的资源与最终版本；状态未知先查询，避免重复提交。

若当前平台实际支持“剪辑→导出到画布”，可以把已完成视频放到时间线0秒、原速原比例导出；不要再次叠加已经混入的音乐。这条路径只在当前界面/文档验证存在时使用。

验收对象是最终画布节点：检查播放时画面与时间推进，暂停后恢复，中段跳转到正确画面，以及片尾行为。仅资源库有缩略图、链接能下载或剪辑器可播放，不足以证明画布节点可播放。

每个失败步骤最多进行两次有原因和改动的重试。正式通道仍受阻时保留已完成文件，报告具体失败与恢复条件，不重生成已经可用的画面来碰运气。

## 源码入口和最终说明

提供实际存在的成片入口和源码入口。若平台返回可编辑代码工程链接，通过正式界面确认项目身份与版本，再标为“打开可编辑工程”。只有视频节点不能算代码工程；只有 ZIP 时标为“下载可编辑源码包”。不猜链接，不为取得链接自动公开发布。

平台不能承载代码工程时，源码包应含所有实际使用的项目文件、依赖锁定/安装说明、字体和声音许可、运行与导出命令。不要打包凭据、无关用户文件、缓存或 node_modules；库安装在目标环境验证后记录。合法字体随包可移植，许可不允许分发时提供准确获取说明。

最终报告简短列出：创意与文字、实际规格、成片、源码、已验证事项和限制。状态可用 `passed/failed/blocked/not-tested`，如 `canvas_playback=not-tested`。未连接平台时明确说已完成本地文件或技能包，尚未完成 Design 导入/播放测试。
