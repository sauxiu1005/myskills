# 明快的背景环境与整片配色

## 参考版本与依据

默认遵循 [原案例](https://vincentwei1021.github.io/mg-styles-15/?lang=zh#03-isometric) 的 ISOPOLIS 日间粉彩微缩世界：浅紫渐变空间、白色圆润云团、薄荷绿地块、桃色与天蓝建筑、浅色分层地台、细等轴点阵和柔和悬浮投影。它是贯穿视频的环境设计，不是只给片尾换一张背景。

依据随包原始提示词 `vendor/mg-styles-15/prompts/03-isometric.md` 的 Creative seed，以及 `demos/03-isometric/js/world.js` 的 `PAL`、`bgU`、云团与环境灯光实现；`main.js` 决定版本。以下配色比例、替代色板与主题迁移是本技能的设计建议，不冒充原片参数。

- 默认采用非 v5 日间机制；`main.js` 中 `v5=1` 且未指定 `day5=1` 会启用 `night5.js`。不要为复用标题或渲染代码而无意启用夜景。
- `PAL.bgTop/bgMid/bgLow` 的浅紫值只是声明；实际背景 shader 的关键参数是 `voidK`、`voidOn` 到 `bgU.uTop/uMid/uLow` 等 uniforms 的传递。不能只改未使用的色值就声称背景已更新。
- 背景浮动方块虽有 `cubeEnd` 数据，但当前 `bgCubes = [].map(...)` 实际禁用它们。不要把彩色漂浮方块当作原片必备元素；原片真正使用的是圆润云团、点阵、光波及岛屿投影。

## 色彩组织

默认保持明亮、清爽、柔和而有色彩差异的棚拍感。用户可以换色相；保留浅背景、亮主体、少量深色焦点的层级。用户明确选择夜景或暗色品牌时才覆盖这个默认值，不能因为“重庆”“科技”“机房”而自行推断为深蓝夜景。

| 色彩角色 | 原源码日间取值 | 使用方式 |
| --- | --- | --- |
| 生长阶段背景，上/中/下 | `voidK`: `#EDE9F9 / #E0DBF5 / #D5CEF0` | 开场与生长段也保持明亮，避免灰黑底 |
| 激活后背景，上/中/下 | `voidOn`: `#E4D8FF / #C5B2FC / #A58CF0` | 用柔和色波丰富饱和度，保留主体背后的浅色光区 |
| 地块与植物 | `#94DFBD / #B7ECD6` | 清晰、可爱的绿地和叶簇，按用途分层 |
| 主体辅助色 | `#FFC4AC / #A8D2FF / #D9D1FA / #FFE6A1` | 桃、蓝、浅紫、奶油黄穿插，避免楼群一片灰蓝 |
| 台面与浅色主体 | `#FBFAFF / #F4F1FD` | 保持大面清爽；侧面用同色系略深颜色体现厚度 |
| 道路、水面、深色焦点 | `#8781D0 / #8CC6FF / #2C2960` | 道路与江水分开；深色用于字标、窗格或少量主角体块 |

这些是源码输入色值，最终像素受灯光、材质、曝光与色彩管理影响。必须看实际渲染，不能凭 HEX 或亮度数字宣布视觉合格。

换配色时可采用本技能建议的“晴空薄荷”：背景上/中/下 `#F2F9FF / #DCEEF8 / #C9E5EA`，台面 `#FFF8EE`，绿地 `#A7DFBB`，水面 `#8CCDE5`，建筑 `#F5C3AA / #B8D5EF / #E1D3EF`，点缀 `#F29C86`，文字深色 `#344C70`。这是一组替代方案，不是原片实测色板。默认仍采用原片日间粉彩；用户说换配色时才按主题替换。

浅色背景与留白构成最大的画面区域，主体由奶油白和两三组粉彩构成，小面积珊瑚、青绿或深紫组织焦点。不要机械限定比例，也不要通过整体降饱和得到灰蒙蒙画面。地台、山体、楼体和背景不能同属一块暗色。

## 环境元素与光照

- **背景空间**：连续的浅色渐变，不加写实地平线、压暗边角或深色天空幕布；地面点阵低对比、细且稳定，沿同一等轴平面延伸。缩小播放时不能形成摩尔纹或抢字。
- **云与空气感**：室外默认在留白处布置少量白色圆润云团，缓慢横移；开场、生长、运行和片尾都有环境连续性。云保持在标题与地标之外；轻雾只能局部点到为止，不能用灰雾覆盖全城。办公室和机房优先用场外云团或抽象留白，不能把云塞进房间。
- **地台与周边**：使用浅色分层地台、柔和倒角和带颜色的侧面，添加符合主题的绿地、树簇、水面、步道。山城台地可浅石色与薄荷色交替，不堆成深棕或深灰高墙。
- **主体层次**：地标、普通建筑、绿地、道路与水面在明度和色相上可分；保留真实主题的轮廓，但允许用粉彩材质重绘。河面可用天蓝或浅青配少量细涟漪，桥与列车用适量暖色引导视线。
- **光照**：柔和暖主光、浅冷色环境补光，暗面保留颜色与结构。接触阴影只加强落地和缝隙；浮岛影柔且透明，不能铺成大块黑斑。先调材质与补光，再适度调整曝光，避免把白面和标题提到过曝。
- **环境动作**：云缓漂、叶簇微动、水纹、车辆或小船等按主题选用；主体与环境共享节奏，环境动作不能成为新的主角。原片色波/点阵脉冲可少量复用，不强制每个主题加入科技光效。

## 写入简报与实施

在 `brief.json.style.environment` 记录 `mode`、`background_stages`、`elements`、`palette_roles` 与用户覆盖项；在 treatment 中说明开场、生长、运行、片尾的环境连续性。字段是可扩展的本地约定，不是 Design API。

替换配色必须检查背景 shader、底台、地形、建筑材质、植物、水面、雾、光源、AO/阴影与后期的实际控制点。若从已有暗色工程派生，逐项清除沿用的暗背景、深色环境补光和夜景调色；只提高曝光或只改天空色不能解决整体沉闷。

修改环境时保留已确认的标题内容和排版、等轴投影、主体辨识特征及动作逻辑。字体需要随新背景调整明暗对比，但不借配色修改擅自移动标题或改写文字。

## 实际画面验收

并排查看开场已有主体时、生长中、运行高潮、片尾的真实渲染与原片日间参考；必要时检查淡入/色波中的中间帧。检查的是整片风格，而非只看封面：

1. 背景保持明快，主体与地台可清楚分离，暗色没有吞掉大片画面；云和留白仍能提供空气感。
2. 建筑、地形、植物、水面有明确色彩层次，暗面细节可读；不存在满城灰蓝、厚重黑影、脏 AO 或过曝白块。
3. 环境元素在运镜中不穿过标题和关键地标、不突然出现消失；点阵与水纹在最终播放尺寸下稳定。
4. 片头到片尾色彩方向一致；若有材质激活，变化从浅色到丰富粉彩，不无意跳进夜景。用户明确要求的暗色版本以其选择为准。

不满足时先定位材质、灯光或背景控制点，再修正并复看受影响时段；不要用增加装饰数量或全局饱和度掩盖层级问题。没有制作视频时仅报告技能已更新，不报告这些视觉检查已经通过。
