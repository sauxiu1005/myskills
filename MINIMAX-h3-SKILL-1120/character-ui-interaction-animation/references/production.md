# 制作与渲染

## 工程与依赖

工程与安装目录分开。作品包含 `brief.md`、`storyboard.md`、`layout.json`、`timeline.json`、`assets-manifest.json`，以及 `assets/`、`ui/`、`scene/`、`sound/`、`build/`、`preview/`、`frames/`、`delivery/`。

执行模型为当前任务编写 UI、场景和声音代码。先发现 Blender 版本与后端、Python、Node、FFmpeg/ffprobe、字体和截图能力，不硬性假设 Blender 5/Puppeteer/NVIDIA 已安装。Blender API 按实际版本验证。

浏览器截图遵守宿主约束；允许独立自动化时可使用 Puppeteer/Playwright，否则使用正式浏览器工具/平台导出。没有允许的截图能力就记录缺项，不启动调试端口绕过限制。

## UI 与内部作品时间

逻辑布局尺寸固定，纹理按镜头需要约 2–3× 输出，倍率不改变按钮坐标。静态底图与动态文字、控件、画布分离。关键文字用实际字体，检查中文缺字。

`drawState(filmFrame)` 应可在任意帧重建状态，不依赖先播放前面帧。明确事件顺序、操作前后态及连续参数。用固定随机种子。

区分电影时间 `t_film` 与软件作品时间 `t_comp`：电影到 8 秒时播放头可以倒带到作品 0 秒。作品画布从实际播放头位置计算，不直接跟电影时间走。PR 片段和 CAD 参数也必须随相应控件联动。

先输出初态、反馈态、片尾和随机跳转的 UI 图确认状态一致。

## 面板、角色和坐标

板面局部 X 向右、Y 向上、Z 为法线。W/H 为逻辑尺寸，s 为像素到世界比例：

`X=(u-W/2)*s; Y=(H/2-v)*s; Z=surface_height`

再乘面板世界矩阵，面板倾斜/掉落后接触点仍跟随。角色根位置需要减去当前姿态脚底/手掌的世界偏移，不能把根节点直接放在按钮上。

界面采用贴近平面的浅浮雕控件。独立面板保留薄边、裁切纹理、匹配 UV 和碰撞代理；按钮顶面、滑块把手与播放头仅轻微高于界面，以小倒角、柔和接触阴影和状态高亮交代体积。厚度可从控件逻辑短边的约 2%–5% 起步，再按最终镜头调整；这是起点，不是固定比例。避免按钮像厚积木、滑块像竖墙、播放头像高杆，或厚侧面抢过图标和文字。

按钮使用短按压行程，默认不超过可见凸起厚度，不穿透底板；反馈主要依靠轻压回弹、选中态、颜色和作品变化。滑块与播放头沿界面平面移动。角色通过俯身、蹲下、手掌触碰或脚踩完成接触，不为迁就手高而把控件拔高。碰撞代理可以简化，但实际接触必须对应可见表面。控件变薄后重新计算手脚落点、约束偏移和遮挡，相机投影不改变逻辑布局。

已有模型检查骨骼/材质后复用。简单吉祥物可用参数体块、倒角和基础控制器；复杂角色需要实际网格、UV、绑定与变形检查。2.5D 用透明部件与受控视角，明确不能支持任意转身。不能只移动整张 PNG 代替所承诺的肢体动作。

## 运动、相机与照明

路径使用可编辑贝塞尔/关键帧，接触有明确约束。位移、旋转和压缩伸展可用不同缓动；手脚接触时稳定，滑行在释放后发生。

相机先交代全貌，再以中远景为主适度跟随角色，接触和结果处留停顿，最后收束。跟拍保留适当距离，使角色、操作目标和界面反馈尽量同框；关键操作可短暂靠近，随后回到能交代工作区的景别，避免持续贴脸或角色遮住大部分界面。

通过侧向位移、随跳跃适度升降、前后视差与加减速形成张力，不仅放大角色或轻微缩放。相机位置与观察目标分别控制，运动方向留出空间，跳跃时能看见落点；结果出现时及时调整构图并稳定停留。角色可从画面高度约20%–35%的主体跟拍构图起步，但按动作、画幅和界面可读性调整，不设固定近景时长或机械占比。

检查角色完整轮廓、跃起极值、相机快移与面板边缘，以及当前控件与反馈是否可读。不能为了拉远而让动作看不清，也不能靠推近镜头制造张力。竖版重新排舞台，不粗暴裁切。

UI 自发光保持可读性。玻璃出现灯具白块时检查反射可见性、粗糙度、镜面和曝光；用当前版本支持的方法调整，不照搬参考片数值。角色在最终色彩管理下比对原图，不只比材质色值。景深/运动模糊不遮掩关键操作。

## 渲染与修补

先做最难动作的小样。12秒可从约18张代表帧开始，再覆盖每个关键接触前后各一帧及极值；复杂动作加密。看图通过后输出低清连续视频检查节奏和穿模。

根据实际测试选择 Cycles/Eevee、GPU/CPU和采样，不承诺参考作者耗时。30fps×12秒=360帧，Blender 1–360，最后采样时刻为359/30秒，12秒整是片段结束边界而非第361张图。

正式帧与预览分目录，记录工程、资产和时间线哈希/版本及范围。局部修改重渲受影响片段并检查接缝，考虑运动模糊时间邻域。分辨率或色彩管理改变时统一整个序列，不能混用旧帧。

## 可编辑 Blender 工程交付

- 必须保存并交付与最终成片对应的实际 `.blend`，用户打开即可修改角色建模，无需先运行生成脚本。脚本作为重建辅助保留。
- 角色、界面、控件、相机和灯光按集合组织并清晰命名。角色主要部件可单独选择，网格可进入编辑模式；保留适用的材质、UV、修改器和控制器。简单 IP 可继续使用简单网格与基础控制器，不为交付强加复杂绑定。
- 保留细分、倒角等有助于修改的非破坏性设置；为渲染必须应用或合并时，保留有明确名称的可编辑基础版本，并在渲染中隐藏，避免重复出镜。不要将角色仅作为一张贴图、不可编辑缓存或整个场景合并网格交付。
- 可打包的纹理等依赖写入 `.blend`；图像序列及其他外部依赖用相对路径完整放入工程 ZIP。包括实际使用的字体或其可重建说明、音轨、UI 源码、时间轴及必要脚本。不能把缺少纹理序列、必须重新生成后才能打开正常场景的轻量包当作唯一完整工程。
- 附简短项目说明：Blender 版本、`.blend` 路径、角色集合/主要对象、如何修改形状和材质、动画控制位置，以及哪些重建命令会覆盖手工修改。保存方便观察角色的视口，不改动最终动画来凑展示姿态。
- 从交付包解压到不同目录打开检查，验证相对依赖可解析；在副本中对角色局部网格或建模修改器做一次小修改，保存并重开确认，再渲染一张代表帧。记录实际验证范围，不把 ZIP 存在或脚本可运行等同于模型可编辑。
