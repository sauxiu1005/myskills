# 知识图解生成器

将论文、课程、文字简报与参考图转化为清晰的知识图解和信息图。通过17类、93个视觉模板组织事实、标签、关系与阅读顺序，默认使用 MiniMax H3 Image 生图与改图；面向教学、科普与论文任务时优先使用相应流程。

## STEP 1: 确认任务与可用能力

- 区分生图、改图、仅写提示词。纯摘要、纯视频、数值绘图或可编辑矢量请求不自动变成栅格生图任务。
- 推荐 **MiniMax H3 Image**，用于需要参考图保持和清晰文字标签的图解生成与编辑；使用前核实其能否满足当前任务。
- 生成前发现当前可用能力并读取所选模型的最新使用指南。依据实际文档核对文字清晰度、参考保持、主体一致性、画幅、分辨率与透明背景支持，不凭型号推断能力。
- 用户明确指定其他模型时优先遵循。MiniMax H3 Image 或指定模型不可用、或无法满足必需功能时，先说明限制并征得用户同意再替换，不静默换模型。宿主不提供模型选择且无法确认实际型号时，不假定其为 MiniMax H3 Image，说明情况并取得同意后再使用。
- 先发现实际能力，再判断是否缺配置。不为运行本技能而擅自安装依赖、探查密钥文件或配置新供应商。
- 无合适图像能力时仍完成简报与提示词，明确说明没有生成图片及缺少的能力。
- 改图前先查看参考图。遵守宿主输入输出约定，不假定网址、路径、蒙版或参考图数量一定受支持。

## STEP 2: 核实输入与简报

确定受众、教学或传播目标、原始材料、输出类型、文字语言、画幅、必需标签、参考图及不能改变的元素。复用用户已有信息，只追问影响正确性的缺项；外观细节可合理默认。用户未说明且用途无法推断画幅时，课件与幻灯片用 16:9，讲义与打印页用 3:4，单张教学示意图用 4:3，并说明所选画幅；部分生图能力在无参考图时必须显式指定画幅。

论文、教育与科普任务读取[科学图解流程](references/science-workflow.md)。先提取带来源定位的事实清单和明确的节点连线表或阶段表，再写提示词。区分论文证据、假说与教学简化，不能用模板示例补齐未知科学内容。

## STEP 3: 选取并填写最相关模板

通过[模板索引](references/template-index.md)只读取最相关文件。新建或改写模板时才读[模板方法论](references/prompt-writing.md)，不在每次执行时加载全部文档。

| 用户意图 | 优先模板 |
|---|---|
| 向学生解释概念 | [教学示意图](references/slides-and-visual-docs/educational-diagram-slide.md) |
| 面向公众讲解步骤 | [分步信息图](references/infographics/step-by-step-infographic.md) |
| 论文方法、工作流程、技术路线 | [方法流程图](references/academic-figures/method-pipeline-overview.md) |
| 因果机制、转化路径、通路 | [机制图](references/academic-figures/mechanism-diagram.md) |
| 实验装置或工作原理 | [科学示意图](references/academic-figures/scientific-schematic.md) |
| 论文图形摘要 | [图形摘要](references/academic-figures/graphical-abstract.md) |
| 网络或模型结构 | [神经网络架构](references/academic-figures/neural-network-architecture.md) |
| 带分支的操作流程 | [决策流程图](references/technical-diagrams/flowchart-decision.md) |

替换全部 `{argument ...}` 占位符，用户输入优先于样例。配色和版式可以使用默认值，但示例名称、机制、维度、图号、标签和结果都不是事实。统一节点数量、阶段数量和编号。模板 JSON 是视觉简报，不是平台请求体。

用户当前要求优先于模板的示例风格。面向公众的机制讲解可简化学术模板，或改用教学模板，不强制学术画风。模板库中的编辑、排版、海报、地图等模板可服务于知识图解，例如修改参考示意图或排版中英双语讲解图。没有讲解目标的独立商品图、人像、头像或营销图不属于本技能。

## STEP 4: 编制生成简报

写清目标与受众、布局与阅读顺序、必需组件及关系、精确上图文字、视觉风格、输入参考的用途、保持项与排除项。按模板使用结构化 JSON 或自然语言；若当前生图能力更适合自然语言，将结构转换为清晰描述。

平台专有结构和模型参数不混入提示词。运行时依据可用能力的实际文档设置相应控制项。不支持的尺寸适配到可用选项，显著差异要说明。不在未核实的情况下承诺透明背景、蒙版、多参考或可编辑输出。

系列图先统一配色、字体、术语、画幅和主体，再集中准备全部提示词。环境支持文件输出且用户需要时，将简报和最终提示词保存到当前会话项目；用户仅要聊天内容时不强制保存。

## STEP 5: 生成或编辑

- 明确要求生成图片即授权宿主规则内的常规生成，不为每张图片强加预览或审批。
- 大规模付费批次或超出已批准范围的明显成本增加，先展示具体范围与费用，并按宿主要求取得确认。已有授权持续有效。
- 仅提示词请求交付完整提示词后停止，不执行生图。
- 能力允许时批量处理独立任务。大型系列可先用一张代表图确认风格；用户未要求时不把独立图片强行拼成一张拼贴。
- 改图明确列出变化项与保持项，仅在支持时使用蒙版和参考图。
- 失败时报告实际原因。在用户模型选择和授权成本内可有限重试或选用其他可用能力，不盲目循环。阻塞时保留并交付提示词，说明未完成环节。

## STEP 6: 检查与修正

遵守宿主的审阅规则。宿主允许查看生成图片时，核对组件、文字拼写、箭头端点、顺序、图例、可读性、布局和参考保持情况；科学图逐项对照事实清单检查关系与标签。宿主将审阅交给用户时，不自行检查或凭自身判断重生成，交付图片时附上本检查清单与事实清单供用户审阅，再按用户反馈修改。两种情况都只修正失败项，改图时重复保持条件。

未检查图片时说明视觉结果未验证。矢量风格外观不等于可编辑矢量文件。生成插图不是测量结果、显微照片或实验证据。真实数值与精确几何采用确定性绘图工具；模板库里的 publication-chart 只能用于明确标注为示意的视觉样稿。

## STEP 7: 交付

展示图片并链接实际返回的产物，尊重工具原生输出位置，不为统一路径无谓搬运文件。按需交付可复用提示词；科学图附简短图注与来源说明。报告未完成的检查或限制。仅在工具实际返回时报告型号，否则说明使用了宿主可用图像能力。

本地结构校验：`python3 scripts/validate.py`。校验器不执行生图，也不测试模型质量。
