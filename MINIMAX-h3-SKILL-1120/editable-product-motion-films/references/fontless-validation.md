# 1.0.1 字体瘦身验证报告

## 变更
- 移除 44 个 WOFF 副本，保留 42 个唯一字体的目录、固定版本下载地址、大小、SHA-256 和许可证。
- 改为按需下载到技能外部缓存；新建模板、添加字体、HTML 分享导出均使用缓存解析路径。
- 字体获取在写入项目之前完成；失败不静默替换字体。缓存经过验证后复制进项目，作品仍自包含。
- 更新中英文说明、版本号、第三方说明和 vendor 校验清单。

## 实测通过
- 全部 42 个字体通过真实网络下载，并与原包 SHA-256 一致。
- 离线缓存模式下全部 10 个模板创建成功，复制映射中的资源均存在。
- 离线缓存模式下 27 个字体家族添加成功，字体内容一致。
- HTML 分享页导出成功，字体和 OFL/版权文件齐全。
- whiteboard 的单文件预览与源码 ZIP 生成成功，预览嵌入字体 data URI。
- 空缓存、损坏缓存的离线请求明确失败，并未创建半成品项目；非法字体名被拒绝。
- 无头 Chrome 成功渲染 whiteboard 的 2 秒帧（1920×1080），中文字体正常。
- 技能包中不存在 WOFF/WOFF2/TTF/OTF 文件。

## 触发与流程检查
入口描述及触发范围未变。正例：制作产品宣传片 / 把产品 UI 做成可编辑动效视频 / Create an editable product launch film。反例：只写一句广告标题 / 制作真人剧情短片 / Download Maya。
流程：新产品资料 → 新建模板时获取所需字体 → 方向、分镜和制作 → 单文件预览或分享页携带字体 → 源码交付。缓存缺失且无法联网时明确停止相关步骤，修复后重试。

## 边界
首次获取字体需要联网；可通过 om fonts fetch 预先缓存后离线使用。没有执行完整长片导出或外部平台导入验收；此次验证覆盖字体获取、模板创建、字体添加、两种打包路径和代表模板渲染。不保证任意网络下首次下载成功。未运行市场仓库 CI（当前工作目录不存在对应仓库或脚本）。
