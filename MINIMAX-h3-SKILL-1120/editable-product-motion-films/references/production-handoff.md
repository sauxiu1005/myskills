# 制作与交付

本文件定义可编辑动效工程的依赖、素材组织、声音路线、文件交付与版本修订。`om` 命令及 HTML 属性属于随包引擎；执行前核验实际环境与媒体能力。

## 1. 环境准备

技能目录（skillRoot）是本技能被加载的实际位置；作品目录（projectRoot）是当前会话的项目工作目录。不在技能目录里制作作品，也不修改随包模板。

```sh
node <skillRoot>/scripts/setup-tools.mjs --link <projectRoot>/film   # 查找并链接 ffmpeg / ffprobe / Chrome，不下载
node <skillRoot>/scripts/om.mjs doctor
```

- Node 22+：优先使用 PATH 中的版本；不在 PATH 时使用宿主提供的运行时，只对当前进程追加 PATH，不改用户全局配置。
- FFmpeg 与 ffprobe：`setup-tools.mjs` 会在 PATH、常见包管理目录和宿主运行时目录中查找（例如宿主 Python 自带的 imageio-ffmpeg 可执行文件），并链接到 `<film>/.tools/bin`；`om.mjs` 从作品目录内运行时自动把它放进 PATH，也可用 `OM_TOOLS_DIR` 指定。
- 浏览器：随包渲染器启动本机 Chrome / Chromium / Edge（可用 `OM_CHROME` 指定）。不连接用户已打开浏览器的调试端口。
- 缺少工具时不自行安装。说明缺什么、影响哪些环节（`still`、`check`、单文件预览只需浏览器；`render`、`sound`、`qa` 需要 ffmpeg 与 ffprobe），请用户同意安装方式后再继续；用户不同意时可先交付方向关键帧、动画预览和源码，成片标记为受阻。
- 在 `design-state.json` 记录 skillRoot、projectRoot、Node、浏览器、ffmpeg/ffprobe 来源和采用的路线。

## 2. 作品目录组织

每支宣传片是一个作品目录（Composition），用作品名建立独立目录。该对象收纳直接表达这支片子的依据与产物：

| 成员用途（role） | 内容 | 形式 |
|---|---|---|
| 创作方案 | 规格、方向卡、treatment、节拍表、事实与素材出处 | 可阅读与批注的项目文档 |
| 方向关键帧 | A/B/C 三个方向各一张实际渲染帧 | 图片，每张一个成员，role 可重复 |
| 关键帧 | 代表段或全片的 hook / hero / 最密帧 / 片尾 | 图片 |
| 动画预览 | `bundle-preview.mjs` 生成的单文件 HTML，项目预览内可播放、暂停、拖动 | 文件（HTML） |
| 成片 | 最终 MP4（或用户要求的其他格式） | 视频 |
| 可编辑源码包 | 作品源码 ZIP：index.html、vendor、assets、treatment、记录 | 文件（ZIP） |
| 配乐 / 旁白 / 字幕 | 单独交付或可复用时才单列 | 音频 / 文本 |

- 竖版、横版、静音循环等需要并存的交付变体分别保存独立文件，放在同一作品目录中，用 role 区分（如“竖版成片”）。
- 具有独立身份并会被多个作品复用的组成部分（如品牌吉祥物、长期复用的产品三维模型）建立各自的作品目录，本片通过引用使用，不重复收纳。
- 用户上传或项目已有的素材留在原目录中，本片只引用；复制到 `film/assets/` 的只是制作副本。

## 3. 素材进出

- **查找已有素材**：用户提到产品、Logo、截图或之前的作品时，先在项目中搜索，再考虑网络搜索或生成。
- **素材优先级**：用户已有资产 → 已授权的官方资料 → 确有必要的平台生成素材。Logo、产品 UI、数值和关键文字保持精确，由代码叠加，不交给生成模型绘制。
- **平台生成素材**：只为作品真正需要的照片质感、场景或人物生成；先做少量代表素材再扩展。生成结果作为制作文件 放进本片作品（role 如“生成素材”），再取得本地文件复制到 `film/assets/`。记录任务、模型、提示词和使用区间；生成成功不等于内容已被用户接受。
- **改字体、时间、布局时复用已有素材**，不重新付费生成。
- **网络图片**只在用户要求或确实缺少外部参考时检索，保留来源与授权说明。

## 声音路线

沿用用户明确要求。普通宣传片默认音乐加音效、无旁白；用户原声、外部音乐、静音循环都是独立有效路线。会产生费用的平台生成（音乐、语音）在方案中说明后再执行，费用确认由用户在应用内完成。

### A. 随包本地配乐（默认，无额外费用）

在 composition 中定义 `OM.music({bpm, ...})`、`OM.sfx`，或编写 ABC `om-score`，按 [sound](sound.md) 执行 `sound`。`!mark:<id>!` 与 `scene:<id>` 名称一致。场景时长改动后重算音乐与落点。`render` 只在存在 `<audio id="om-sound">` 时自动刷新 OM 混音，首次需先运行 `sound`。真实乐器采样包是可选下载，未安装时使用合成音色并如实说明；不为普通任务自动下载。

### B. 用户音乐或平台生成音乐

保留原文件与授权信息，用真实音频分析得到长度、节拍和段落。平台生成音乐时，提示中写明纯音乐/人声、时长、情绪和段落，但不承诺秒级落点；以实际结果的分析为准，估计的 BPM 明确标记。

不要把外部母带命名为 `assets/sound.wav` 或 `om-sound` 后运行自动作曲，否则会被覆盖。将音乐、音效与旁白混为 `assets/final-mix.wav`，移除旧 `om-sound` 标签，使用独立音轨：

```html
<audio id="design-mix" src="assets/final-mix.wav"
       data-start="0" data-duration="30" data-volume="1"></audio>
```

时长替换为实测值。此分支不执行 `om sound`；`render --silent` 只抑制提示，**不会删除实际音轨**。确认其他 audio/video 不会重复发声。

### C. 旁白与现有真人素材

使用平台语音合成（从音色库选择或按需设计音色）、用户录音或本机 `om voice`。先得到最终音轨，再建立词级或句级时间表；自动识别的专名、数字和中文断词要复核。只有实际生成了词轴才说词级同步。保留用户原声，不自动克隆或替换声音；声音克隆只在用户明确提供授权录音并提出要求时进行。`om voice` 可能触发额外模型下载，先说明再执行。

### D. 静音

不运行 sound，不保留自动播放音轨；必要时 `sound --off` 去除 OM 混音标签，并检查其他音频与视频原声。透明叠加层通常不含音轨。

频谱、响度、峰值和静音检测只证明技术指标，不代表音乐品质已被认可；听感以用户反馈为准。

## 项目预览交付

1. **导出**：`om render` 生成 MP4（H.264 / yuv420p，有声音时 AAC，faststart）。用 ffprobe 读取尺寸、时长、帧率与音轨等客观参数，与交付规格对照；不对画面内容做验收式审片。
2. **打包预览与源码**：

   ```sh
   node <skillRoot>/scripts/bundle-preview.mjs <film> --out <film>/out/preview.html --zip <film>/out/source.zip
   ```

   预览把所有本地脚本、字体、图片、音视频内联为一个 HTML，项目预览可直接播放；超过约 45MB 时用 `--no-audio` 或压缩素材。原始 `index.html` 依赖引擎注入，不能代替预览上传。
3. **放入作品目录**：把成片、动画预览、源码包（及适用的字幕、配乐）作为项目文件交付，按第 2 节 role 命名；创作方案保存为同目录文本文档。文件名称描述内容，如“新品发布宣传片成片”，不用文件名或版本号。
4. **以工具结果为准**：交付返回完成后记录 文件路径、哈希与版本；结果未知时检查是否已有有效文件，不重复导出。返回受阻时保留本地成果，说明具体原因与恢复条件，不宣称已完成项目预览交付。
5. **必须提供可编辑工程入口**：按下节启动并验证本机工程，每次交付回复的最后都在对话中给出可点击的“打开可编辑工程”链接；源码包作为“下载源码包”另列。

## 可编辑工程入口

可编辑工程就是随包 Studio：在本机回环地址上提供实时预览、变量面板（标题、数字、颜色、停留时长）、点选画面留评论、撤销和导出，直接读写项目工作目录里的 `film/index.html`。

```sh
node <skillRoot>/scripts/open-project.mjs <projectRoot>/film          # 复用已在运行的 Studio，或在后台启动
node <skillRoot>/scripts/open-project.mjs <projectRoot>/film --stop   # 用户要求关闭时
```

1. **只用验证通过的链接**：脚本输出 `verified: true` 表示该地址确实是本作品的 Studio（项目根目录一致），不只是端口有响应；默认端口被其他程序占用时会自动换端口，以输出的 `url` 为准。记录 url、pid 与验证结果。
2. **最终回复直接呈现**：`[打开可编辑工程](实际 url)`，写在正文里，不放进代码块，不输出占位符。紧跟一句说明：这是本机链接，工程服务运行时可用；打不开时告诉我“重新打开工程”，我会重启同一个工程（端口可能变化）。
3. **同时给出源码位置**：`[打开源码文件夹](file:///…/film/)`（绝对路径，空格等字符按 URL 编码），以及项目预览上的“可编辑源码包”。三者用途分开说明，下载包不能称为“打开工程”。
4. **用户在工程里改过之后**：用户在 Studio 改了变量或留了评论，说“改好了/看评论”时，先运行一次 `om inbox` 读取真实评论并按定点修改处理，再重新导出、打包，把成片、预览与源码包作为新版本交付到项目预览；Studio 里的修改不会自动更新项目预览上的成片。
5. **链接是交付的必需项**：`verified: false` 时读日志尾部，先 `--stop` 再按原因修复并重启，最多两次；仍失败则按受阻说明（交付尚未完成），给出原因、恢复条件、源码文件夹链接和源码包，不编造链接，不为获得链接公开部署。
6. 每个作品只保留一个 Studio 进程；开始新作品或用户要求时关闭旧的，不让无关服务长期占用端口。

## 修改与版本

- 同一成片的修改、重渲染沿用原文件 建立新版本（成片、动画预览、源码包分别更新），不新建平行资源；创作方案以局部修改更新。
- 用户指定或当前采用的版本是修改基础。用户要求保留对比的候选版本时，以候选方式保存，不替换当前采用版本。
- 修改前保存源码快照（直接编辑文件不一定进入 `.om/history`）。

## 失败与恢复

每项失败最多两次有明确原因和改动的重试。已导出可用文件就复用，不反复转码、重生成或重建项目。平台能力返回不可用或拒绝时记录原始错误，不说成用户拒绝。生成任务失败时不自行重新提交，说明情况，由用户决定是否重试。
