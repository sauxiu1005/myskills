# 定点修改与检查

## 接收反馈

聊天里的时间码、项目预览上的批注或选中对象、用户截图都可作为反馈。记录：成片文件 与版本、时间点或范围、scene、data-om-id（未知为 null）、原话、预期修改。项目预览像素坐标不是源码对象 ID；先按时间码在源码中定位对应 scene 与对象，再修改。

可编辑工程（本机 Studio，见 [可编辑工程入口](production-handoff.md#可编辑工程入口)）里的评论与变量修改也是反馈来源。用户提到在工程里改过或留了评论时，运行一次 `om inbox` 读取，用 `look <id>` 取对应帧，处理后 `done <id> --note` 回复。只有真实 Studio 评论才用这些命令；不创建假 inbox，不持续等待。

## 最小修改

1. 以用户指定或当前采用的版本为基础，保存上一版源码快照与对应成片版本。
2. 可编辑变量优先 `om set`；保留对象 ID 与已被接受的画面。
3. 改颜色、文字不重写整片。改停留时间则顺延依赖事件，同步音乐、字幕、后续场景与总时长；用户要求固定总长时在授权范围内重新分配停留。
4. 重新运行 `om check`，重新导出、打包，把成片、动画预览、源码包作为各自 Resource 的新版本交付。
5. 回复具体变化，如“结果卡停留 1.2 秒改为 2 秒，后续顺延 0.8 秒”，请用户在项目预览查看新版本。

## 检查的范围

| 层次 | 做什么 | 说明 |
|---|---|---|
| 工程构建 | `om check`：脚本错误、缺素材、字体、变量、随机跳转与顺播一致、文字越界/遮挡/低对比 | 属于制作本身：errors 必须修复；warnings 按设计意图判断，有意遮挡用依据标记，不用标记掩盖错误 |
| 客观参数 | ffprobe 读取尺寸、时长、帧率、编码、音轨；`ffmpeg -v error -i final.mp4 -f null -` 解码无错 | 对照交付规格，记录 SHA256 |
| 平台交付 | 交付结果返回的 Resource / Version 与作品目录成员 | 以工具结果为准，未返回成功不算交付 |
| 工程入口 | `open-project.mjs` 输出 `verified: true`，且项目根目录为本作品 | 端口有响应或源码包下载成功不能代替 |
| 内容与审美 | 由用户在项目预览审阅 | 不对自己渲染的成片做验收式审片，不依据自检结论自行重做；用户提出问题后按反馈修改 |

`om qa`（单帧闪现、停滞、硬切、运动曲线、循环接缝）只在用户要求排查或针对用户指出的问题时使用，提示结果按叙事判断，不为全绿删掉有意义的停留。横竖版本分别重排布局，不裁切；透明输出说明实际格式（ProRes 4444 / WebM），不把普通 MP4 说成透明视频。

## 技能包验收用例

- 新产品发布：给真实产品资料，30 秒、中文、16:9、音乐无旁白。应产生产品对应的三方向关键帧与代码动画，而非改名模板；成片、动画预览、源码包进入同一作品目录。
- 现有音乐：用户提供 20 秒音轨。应保留音乐、按实测重新定节拍，不执行自动作曲覆盖母带。
- 定点修改：“第 8 秒标题太小，其他不改”。应定位该版本该对象，局部修改，并以原文件 新版本交付。
- 静音循环：8 秒竖版，无声音。应真正移除音轨，首尾回到同一画面。
- 工程入口：最终回复有可点击的“打开可编辑工程”，指向已验证的本作品 Studio；用户在其中改完变量后说“改好了”，应重新导出并以新版本交付。Studio 起不来时只给源码文件夹与源码包，并说明入口不可用。
- 缺少 ffprobe：应说明影响，请用户同意安装方式；未同意前交付方向帧、预览与源码，成片标记受阻。
- 平台受阻：本地 MP4 已导出，项目预览交付返回不可用。应保留本地成果、有限重试、如实说明未完成项。

这些是未来行为验收任务，不是已经完成的测试。技能结构检查、引擎烟测与 Design 平台实测分别报告。
