# 交付与审阅清单

成图好不好由用户判断。本文件说明交付时附什么、怎么给用户列一份好核对的清单，
以及用户指出问题后怎么定向修。

**不要自己给生成结果打分，也不要自作主张重新生成。** 每次重生成都是用户的花费，
要不要重做由用户决定。

## 1. 交付与内部记录

默认交付成图，简短说明关键保留点，并请用户确认或指出需要修改的地方。不逐条讲解图片编号、画布归属和绑定术语。

完整绑定表、画幅依据和按用户原话拆出的核对清单保存为内部制作记录。用户要求详细依据或复杂问题确实需要逐项核对时，再展示相关部分。以下清单供组织依据与响应反馈使用，不表示助手可以主动验收自己生成的内容。

## 2. 怎么写核对清单

清单按**用户的原话**拆，不按"整体好不好看"拆。一次整体印象里混着七八个独立判断，
任何一条错了都会被"整体不错"盖过去。

例：用户要"十六格、每格一个年份、每格都是同一只猫"——这是三条独立的核对项：

- [ ] 一共 16 格，4 行 4 列
- [ ] 每格下方的年份依次是「2010」到「2025」
- [ ] 每一格里都是 Picture 2–16 的那只猫（花色、体型对得上）

每条只写一个看得见的点，用户扫一眼就能打勾或指出问题。

### 各角色可以列的核对点

按绑定表里实际出现的角色挑相关的列，不要全部照搬。

- **身份**：脸型轮廓、发型与发色、体型、年龄感、标志性特征（眼镜、痣、耳饰、动物花色）
- **衣物与产品**：版型、颜色是否准确、材质反光、扣子/拉链/口袋数量与位置、图案内容、
  logo 与标签位置、穿在正确的人身上
- **场景**：主光方向、地面/墙面材质、关键陈设、时间与天气
- **风格**：笔触/颗粒/纹理、色彩倾向、媒质是否是用户要的（要照片却出插画）
- **姿态与构图**：景别、主体位置、朝向与视线、裁切位置
- **版式**：格数与行列、每格放的是哪张照片、标题和文字原文是否一字不差、装饰元素
- **全局**：没有多余的文字或 logo（除非用户要了）、没有参考图里不存在的多余主体

## 3. 用户指出问题后

| 用户反馈 | 判断 | 动作 |
| --- | --- | --- |
| 全部满意 | 交付完成 | 结束，或问用户要不要做下一张 |
| 一项不对 | 单点问题 | 只改提示词里这一项的描述，绑定表其余部分不动；先告诉用户打算怎么改，同意后再重生成 |
| 两项以上同类问题 | 绑定有歧义 | 改绑定表（例如风格图误绑成了身份图），把改动给用户看，同意后再重生成 |
| 改过措辞后同一问题又出现 | 绑定错了，不是措辞问题 | 同上，改绑定表，不要继续堆形容词 |
| 某项看不出对不对 | 被遮挡、太小或角度太偏 | 建议换一个能看清它的构图或角度，而不是继续改描述 |
| 用户觉得方向不对 | 需求没对齐 | 回到第一步，问清要合成什么、每张图代表什么、什么不能改 |

**不要用改措辞来掩盖绑定错误。** 同一个问题反复出现，说明是绑定表错了，不是提示词写得不够好。

## 4. 实例

参考图：Picture 1 夜晚街道、Picture 2 女性半身、Picture 3 红大衣平铺。绑定表见绑定模式 4.1。

交付时附上的核对清单：

- [ ] 背景是 Picture 1 的雨后街道：湿地面反光、左侧暖色店招
- [ ] 人物是 Picture 2 的女生：脸型、齐肩直发、年龄感一致
- [ ] 她穿 Picture 3 的红色羊毛大衣：翻领、四颗黄铜扣、下摆过膝

用户反馈："衣服没问题，但人不太像，头发变短了。"

→ 只有身份一项不对，属于单点问题。告诉用户：把身份行从"她就是 Picture 2 中的女生"
改成更具体的可见特征（"脸型与 Picture 2 相同、齐肩黑色直发、同样的年龄感"），
其余绑定不动；用户同意后再重生成。

第二轮用户说"发型还是看不清，被领子挡住了"——这不是措辞问题，是构图挡住了。
建议改成半侧身、头发从领口外垂下的构图，用户同意后再生成。
