# 素材预检

提交前逐项过一遍。物理检查在提交前做只花一秒，出图后才发现要重新生成。

## 内部检查数量，必要时说明

所选图像模型的参考图上限须在使用前核实，由助手在提交前内部核对。只有用户询问、实际超限或当前选择受上限影响时，才解释张数与取舍。不要把技术限制作为默认开场，不默认解释版式图占用名额。

## 1. 预检清单

| # | 检查项 | H3 Image 要求 | 不满足时怎么办 |
| --- | --- | --- | --- |
| 1 | 参考图张数 | 以当前能力文档为准 | 超过当前上限时先告诉用户这个上限，再按第 3 节一起定取舍；只使用对目标有帮助的素材，不要求凑满数量 |
| 2 | 单边像素下限 | 每边 ≥ 128px | 太小则请用户提供更大尺寸的原图，或改用不依赖细节的角色（场景、氛围） |
| 3 | 长短边比 | ≤ 4:1 | 更极端的长条图会被拒收；先和用户商量裁成 4:1 以内，且这类图不适合当身份或产品来源 |
| 4 | 单边像素上限 | ≤ 8192px | 超出会被自动等比缩小，一般无需处理 |
| 5 | 透明通道 | 慎用 | 带透明通道的图做身份来源容易出现抠图硬边；先合成到纯色底 |
| 6 | 重复与失效 | — | 同一张图传两次没有意义；传不上去的图要单独告诉用户，不要当作没有这张图 |
| 7 | 引用顺序 | 与绑定表一致 | 顺序错位会让提示词里的 Picture N 指向错误内容，等同于绑定全错 |
| 8 | 叫法统一 | 提示词里只用 Picture N | 混用"参考图 N""图 N"或文件名时统一改成 Picture N |

## 2. 常见提交问题

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| 提交被拒，提示缺少画幅 | 没有提供任何参考图时，画幅必须显式给出 | 补一个明确的画幅比例再提交 |
| 提交被拒，提示参考图尺寸或比例不合格 | 某张图小于 128px 或长短边比超过 4:1 | 找出那一张告诉用户，换图或裁切后再提交 |
| 提交被拒，提示参考图数量超出上限 | 超过当前上限 | 告诉用户超出了几张，按第 3 节重新取舍后提交 |
| 只有部分变体成功 | 某个变体失败 | 已成功的部分照常交付，失败的那项单独说明，用户要求时再重试 |

## 3. 数量取舍的做法

超出当前上限时：

1. 先告诉用户超出了多少。
2. 按"用场是否可替代"排序，不可替代的先留：身份来源、版式骨架、决定画幅的那张排前面；
   某一张内容图通常可以被另一张内容图替代，排在后面。版式图也可以用文字写出网格来替代（见绑定模式 1.6）。
3. 给出取舍方案，让用户确认保留哪几张、舍弃哪几张。

不要自己悄悄丢掉最后几张——用户会以为它们都参与了生成。

不以用满16张为目标，也不为了减少张数而删去用户明确要求的素材。

## 4. 画幅继承的注意事项

未显式指定画幅时，成图继承 Picture 1 最接近的支持比例。这意味着：

- Picture 1 的形状就是最终交付的形状，需要提前确认（见绑定模式第 2 节）。
- 如果 Picture 1 的形状不符合用户预期，换一张作 Picture 1，而不是事后再裁切。
- 想要特定画幅时，直接显式给出，不要依赖继承。H3 Image 支持 1:1、4:3、3:4、16:9、9:16、
  3:2、2:3、21:9，以及 3:1、1:3 的超宽/超长画幅（适合横向长卷手账或竖向长条拼贴）。
