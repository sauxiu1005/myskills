# 制作与验收

涉及字体授权、精确源稿、效果图、印刷或手册交付时读取。选择与用户用途相称的检查，不建立与任务无关的审计负担。

Step 4、Step 10、Step 14 定稿后必须完成对应的 Illustrator 可编辑 `.ai`；执行 [Illustrator 定稿源文件规范](illustrator-source-handoffs.md)。本页的通用交换格式和工具故障处理不能替代该要求。

## 文件组织与状态

可按项目大小组织为 `brief/`、`identity/`、`typography/`、`graphics/`、`applications/`、`manual/`、`source/`、`licenses/`、`proof/`。只创建实际需要的目录。

使用稳定资产 ID 与版本，记录来源、衍生关系、用途、授权、文件格式及验证状态。避免依赖某次会话的绝对路径；打包文件之间优先使用相对路径。

状态应可核对：

- `planned`：尚未制作。
- `draft`：探索/未确定设计。
- `generated`：文件已存在，尚未完成相应验证。
- `verified`：完成已记录的打开、结构或视觉检查。
- `blocked`：有具体未解决条件。

另用项目决策记录区分用户确认和授权自主决定。`verified` 不代表用户已采用，也不代表商标或商业许可获批。

## 字体与第三方资产

查字体作者、字体厂商或官方仓库的许可文本；保留获取地址、版本/日期、许可证文件及适用范围。至少区分桌面设计、网页/应用嵌入、电子出版、转曲、修改和再次分发；只核对项目真正需要的用途。

开放字体也必须看具体条款，例如保留版权/许可证、保留字体名称的修改限制等。付费字体需要用户已有许可或另行购买，设计任务本身不授权购买。未核实的许可标为 `unverified`，给出已核实替代方案或提醒补充。

包中附字体二进制文件前确认分发许可；不许可时只交字体清单、获取链接及适当转曲文件。保留需要后续编辑的文字层；不能声称转曲能替代所有授权义务。

参考图片、模板和产品模型也记录来源与使用范围。参考可用于内部分析，不等于可直接对外再分发。授权不明的资产不要隐藏在交付包内。

## 画板与图层

建议的语义图层，可按软件与项目调整：

| 类型 | 内容 | 导出规则 |
| --- | --- | --- |
| Background | 背景色与底纹 | 正常导出 |
| Artwork | Logo、图形、Icon | 正常导出，保留路径或对象结构 |
| Typography | 可编辑标题与正文 | 正常导出；转曲版作为独立副本或明确替代层 |
| Images | 链接/嵌入图片 | 正常导出；打包时验证链接 |
| Specification | 正式规范图解及说明 | 规范页正常导出；纯 Logo 导出不带这些内容 |
| Guides | 网格、安全区、构图辅助线 | 默认隐藏/不打印，必要时锁定 |
| Production Notes | 制作参数、输出备注 | 独立管理，避免混入成品 |

不用为了“多图层”把整张扁平图片复制到不同层。路径、文字、裁切、链接、画板和分组应符合后续编辑需要。字体转曲和可编辑文字不能同时可见而发生重影。可变字体需验证实际字重/轴设置，不能只靠字体家族名称推断外观。

透明版不应含白色矩形背景；反白版需确保图形填色正确。Logo 纯稿导出应与手册规范页分开。图形构造说明可以是解释模型，不要虚构不存在的精密数学起源。

## 原生应用与可移植交付

先验证应用是否可连接及是否能执行最小操作，再投入依赖它的批量建档。读取用户指定路径和可用工具，不写死 Illustrator 年份、macOS 版本或插件标识。

只在应用/格式真正支持时承诺原生文件。`.ai`、`.fig`、`.indd` 等文件需要相应真实数据结构和验证；SVG/PDF 是不同交付类型。`.jsx` 等脚本需注明是否执行成功、保存位置和已知限制。转换结果需检查图层、文字与外观，不以“文件能打开”作为全部验收。

应用失败时进行一次有依据的诊断；只有连接状态变化、修复完成或新证据支持时再试。若无法修复，交付已完成设计和可用格式，保留清晰的待办；不建议用户盲目开放全部权限、关闭系统保护或修改应用签名文件。

## 效果图提示词骨架

这是供项目生成时填写的内容结构，不是固定视觉风格：

> 为 [品牌/业务线] 制作 [物料/产品清单] 的 [整体/单品] 概念效果图。以引用的 [Logo、图形、字标、配色] 为身份基准。产品为 [形状、比例、尺寸依据]，使用 [材料、表面、合理工艺]。版面采用已设计的 [标志位置、文案层级、图形密度]。场景与光线为 [环境、背景、光向、阴影]，拍摄构图为 [视角、画幅、主体关系]。保持身份资产、产品结构与文字一致；允许变化的是 [具体范围]。预期输出为 [用途/比例/分辨率]。

有已有图片时引用正确文件并先查看。纯文字提示无法保证精确重现 Logo；精确资产优先通过可编辑矢量/排版对象应用到设计中，位图生成或编辑遵循当前图像工具的规则。导出后检查，不因提示词写了“保持一致”就假定成功。

## 色彩、输出与印刷

数字资产注明色彩空间与尺寸；显示用文件通常采用适合屏幕的色彩配置，但以实际工作流为准。印刷前询问成品尺寸、刀模、承印材质、印刷方式、色彩配置、出血和专色要求。没有印厂参数时可做概念版，不能宣称已达到生产条件。

文字对比度验证针对具体组合与字号。涉及 WCAG、PDF/X 等标准时查官方当前适用要求，注明实际检查对象与范围；不要只因使用了某个软件或导出选项就宣称合规。

## 手册排版与视觉检查

先做内容地图，再决定页数和版式。采用一致的网格、边距、标题层级、页码与图注，但允许封面、图形页和应用页根据内容变化。说明文字服务使用者，不把执行脚本、插件错误等技术细节写成品牌主张。

输出 PDF 或其他阅读版后逐页渲染检查；必要时同时检查可搜索文字、目录、链接、字体嵌入和透明效果。修复溢出、截字、错误换行、低清图片和辅助线误导出。抽查无法代替对整册明显缺页/版式问题的检查。

## 最终交付核对

1. 范围：约定文件齐全；不适用、暂定、阻塞项目有理由。
2. 身份：名称拼写、Logo 版本、字形、配色和符号在各资产一致。
3. 可用性：文件真实存在，可打开；源文件结构与声明一致。
4. 权利：实际使用的字体和第三方资产有相称的许可依据。
5. 视觉：标志单色/小尺寸、图形一致性、应用和手册渲染已检查。
6. 交接：必要链接和资源可找到；说明哪些已转曲、哪些可编辑、哪些需要另行获取字体。

交付包只包含该项目需要的资源。不要加入其他客户素材、系统日志、临时缓存或未授权字体。若包含自动建档脚本，提供简短的运行方式和执行状态，不把运行责任掩藏在“已完成”之下。
