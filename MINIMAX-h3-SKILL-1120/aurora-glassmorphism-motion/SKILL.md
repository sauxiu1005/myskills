# 弥散渐变 / 玻璃拟态动态短片

把品牌、产品、网站或 App 做成一支弥散渐变 / 玻璃拟态（Liquid Glass）风格的动态设计短片：缓慢漂移的模糊彩色光斑、
有真实厚度的磨砂玻璃 UI 卡片，以及一枚液态玻璃透镜——它会明显折射下方的界面和文字，最后收成 Logo。画面、动画、配乐和音效
全部由代码生成（WebGL + Canvas，Python 音频），用无头 Chrome 逐帧确定性渲染，再用 ffmpeg 编码。本 Skill 从 `mg-styles-15`
（12-aurora-glass 风格，MIT）拆分而来，并加入了实际制作中总结的玻璃技法。

附带资源（路径相对本 Skill 目录）：
- `references/style-prompt.md` — 完整制作提示词（Style / Output / 技术路线 / Creative seed / Signature features /
  How to work / Rules / Craft checklist / Deliver）。
- `references/glass-craft-notes.md` — **必读**：让玻璃感明显的做法、排版规则、色带修复、声音，以及被客户否掉的做法。
- `references/rubric.md` — 独立评审提示词，用于「评审 → 修改」一轮。
- `references/oriel-treatment.md`、`references/oriel-production-report.md` — 完整案例（虚构 AI 助手「Oriel」，英文 UI）：
  已确认的创意方案与最终制作报告。
- `toolkit/` — 渲染器与源码：`harness/render.mjs`（确定性 HTML→视频，页面暴露 `window.renderAt(t)`，`--mkv` 输出无损母版）、
  `harness/preview.html`、`lib/audio`（mgaudio + CC0 采样，`ambient` 配方 `flavor='glass'`）、`demos/12-aurora-glass/`（原片
  Aurora）、`demos/oriel/`（改进版：UI 渲染进 WebGL、真实折射透镜、玻璃卡片着色器）、`assets/`（颗粒纹理、字体说明）、
  `package.json`、`requirements.txt`。
- `scripts/encode_final.sh`（防色带交付编码）、`scripts/band_metric.py`、`scripts/check_audio.py`、`scripts/sheet.sh`（联系表）。

## 步骤 1：需求

收集：品牌或产品（真实品牌只能用用户自有 Logo / 素材，否则虚构品牌名）、产品做什么、画面文案与 UI 语言、配色倾向、Logo（如有）。
缺失时主动提议（虚构品牌、名字由来、口号、UI 文案）。确认规格：画幅（默认 1920×1080；竖屏 1080×1920）、时长（询问时建议 6–30 秒，默认 10 秒，见下文）、是否要配乐音效（默认要）。

自定义时长：参考源码和节拍表按 10 秒搭建，所以要按比例重排节拍，而不是把动作拉慢。开场钩子仍在 0.5 秒内，透镜划过文字放在约
55–75% 处，结尾停留 ≥ 1.2 秒。短于约 6 秒时，卡片来不及落定透镜就要出场；超过 10 秒时，要增加内容段落（更多界面状态、第二次
透镜划过、功能展示等），不要整体放慢；超过约 30 秒这种风格会显得单调，建议拆成几支。渲染时用渲染器的时长参数，配乐长度也按同一份
节拍表设置。

配色规则：深色底上用 2–3 个相邻色（紫蓝青，或橙粉红）。撞色会显脏。

## 步骤 2：创意方案确认

读取 `references/style-prompt.md` 和 `references/glass-craft-notes.md`。通用部分全部保留，绝不删除 `Signature features`。
只改写 `Creative seed`（品牌、故事、文案、配色、声音），画幅变化时改 `Output`。写成创意方案文档并呈现：
- 两句话概念和虚构品牌（名字、口号、Logo 构想——最好让透镜最后变成 Logo）；
- 逐字的 UI 文案表（拼写、标点准确）；
- 带时间码的节拍表：0.5 秒内的钩子（第一帧极光就在流动、高光掠过卡片边缘）、卡片带视差和轻微倾斜入场、一道光扫、透镜在画面内
  诞生并在约 55–75% 处划过文字、卡片后退、透镜收成 Logo、结尾锁定版停留 ≥ 1.2 秒；
- 配色色值、字体（Inter / Manrope 等 OFL 字体）、声音方向。

排版：安静的两栏布局，卡片互不重叠，四周留 ≥ 5% 安全边距。除非用户要求，不加叙事噱头（光流、光束投射等）——玻璃透镜就是主角。
等用户确认后再开始搭建。

## 步骤 3：主视觉与关键帧确认

在做动画、配乐和整片渲染之前，先让用户看到成片的样子。交给编码子 agent，材料、环境搭建和约束与步骤 4 相同，但要求它搭建真实工程后
**只渲染静帧**——不渲染整片，不做音频。静帧由最终渲染器通过 `window.renderAt(t)` 以全分辨率、最终画质输出，用户确认的画面就是之后会动起来的画面：
- 1 张主视觉：高光时刻（透镜停在文字上，约在全片 65–75% 处），要有海报级完成度；
- 4–6 张关键帧，覆盖节拍表：开场钩子、卡片入场、卡片全部到位与扫光、透镜经过第一段文字、卡片后退与透镜收缩、结尾定格。

呈现时说明每张静帧的时间点和画面内容、几何检查结果（卡片重叠、离边距离、透镜离边距离），以及子 agent 如实看到的不足（如折射显乱、
配色偏平、Logo 细节）。可以提出改法，但只改用户选中的项。在这一步改动成本最低——把画面修改一轮收齐，重渲受影响的静帧，
等用户确认后再进入步骤 4。记下工程位置，供步骤 4 使用。

## 步骤 4：制作（委派编码子 agent）

在步骤 3 已确认的工程上继续（新开子任务，并注明以该工程为来源），保持已确认的画面、排版和文案。交给编码子 agent 的完整内容：完整改写后的提示词、已确认的创意方案、玻璃技法笔记，以及本 Skill `toolkit/` 的绝对路径，以 `demos/oriel/`
为主要参考实现（`demos/12-aurora-glass/` 为次要参考）。要求：
- 把 `toolkit/` 复制到其工作目录（页面从工具包根目录起服务，`/assets/...`、`/node_modules/...` 是根相对路径），执行
  `npm install` 和 `pip install -r requirements.txt`。Chrome 不在默认路径时，找到本机已安装的 Chrome 可执行文件，
  渲染前把 `MG_CHROME` 设为该路径。
- 用确定性的 `window.renderAt(t)` 搭建页面；把极光 + UI 卡片 + 文字渲染进同一个 WebGL 合成层，让透镜真正折射界面和文字
  （仅靠 CSS `backdrop-filter` 做不到）。
- 按技法笔记实现玻璃卡片和透镜配方；透镜和所有卡片都保持在画面内。
- 用 mgaudio `ambient` 配方（`flavor='glass'`）写 `audio.py`，与画面共用同一份 `cues.json`。
- 在已确认的静帧基础上加动画和声音；动画完成后在已确认的时间点复查画面，确保没有走样；再用 `--mkv` 渲染无损母版，用 `scripts/encode_final.sh` 编码交付。

需传达的约束：每帧是时间 t 的纯函数（带种子随机，不用实时时钟或状态触发的 CSS 过渡）；只用 CC0/OFL/可商用素材并写入
CREDITS.md；不用真实商标；画面文字与确认稿逐字一致；母带 −14 LUFS、真峰值 ≤ −1 dBTP，手机外放模拟下各音效可闻；文件 ≤ 50 MB。
交付前检查：时长与帧数、分辨率、帧率、音频、无黑帧、无回退字体、逐帧几何审计（卡片 0 重叠、离边距离、字标区域干净）、透镜划过时
的全分辨率帧（文字被放大弯曲且中心可读）、暗部提亮 3–7 倍查色带。交付 MP4 和报告（节拍表、各风格特征如何实现、检查数据、如实写出的弱点）。

## 步骤 5：独立评审与交付

制作方自评通常比实际高 2–3 分。展示前先用 `references/rubric.md` 对成片做一次独立评审（风格还原、创意亮点、动效、排版、质感；
以及透镜是否明显折射文字、卡片是否读得出玻璃、有无重叠 / 贴边 / 色带）。把成片、报告以及评审分数和问题如实告诉用户。

## 步骤 6：修改

通过同一编码子任务，在同一支成片上出新版本；先备份上一版源码。只改用户要求的部分和明确的缺陷，保留用户已认可的内容（排版、文案、
节拍）。如果用户的要求与技法笔记冲突（例如让卡片叠压），简短说明取舍，然后按用户的意思做。

## 说明
- 同一份提示词每次做出的片子都不同，通常需要一到两轮评审修改。
- 彻底消除色带需要 10-bit H.264，部分设备无法播放；切换前先问用户。
- 竖屏 1080×1920：两栏改为上下排列，透镜路径仍要经过文字，重新检查安全边距。
