# 确定性实现与渲染

## 架构

推荐 HTML/CSS/SVG：文字和布局可控，路径用于图表和图标；Canvas 2D 也可实现。选项目现有能力，简单场景无需引入 3D。交付可离线加载的资源，字体加载完成后再渲染。

scene 配置包括 width、height、fps、duration、colors、font、states、events、cursor、audio。保持一个主 rounded rectangle / DOM 容器，内部图层分为 artwork、labels、controls、chart、palette、toast。主容器不随状态销毁；内部图层可以分开建立，并以独立显隐轨道控制。

seek(t) = layout(t) + content(t) + cursor(t) + camera(t)，每次调用都完整赋值。禁止 CSS transition、自动播放 CSS 动画、累积 dt、依赖上次调用的状态、未固定种子的随机数。每次重设 display、visibility、opacity、filter、transform、文字及尺寸，不能先测量上一帧隐藏元素再恢复显示。优先从布局数据计算；必须测量时先恢复本帧所需的布局状态，再求宽度。requestAnimationFrame 可用于交互预览，但只负责传入 t，不能成为导出的时间源。

## 布局分区与预加载

- 图标、正文、数值、单位/徽标与按钮使用独立区域。按已加载字体的最长文案、最大位数和条件徽标求宽度，再分配可伸缩轨道；边距包含描边与运动余量，不照抄某一案例的像素间距。
- 同一布局函数供轨道、填充、滑钮、光标抓取点和越界限位复用；越界反馈可拉伸容器，但不得侵入数字或操作区。改文字位置时同时重算徽标与按钮的可用空间。
- 数值由两位变三位、开关新增徽标、中英文变化、尺寸收缩与拖动越界，作为布局设计的边界条件。标签选中块画在文字下方；透明浮层不能仅靠 z-index 防止下层文字透出，按状态使用裁切或有序退场。
- 初始品牌图或少量文字不能保证后续字体已加载。显式预加载所有使用的字体、字重与文字脚本，待字体和图像解码完成后才测量与截帧。来源受限时沿用获准字体或明确说明替代，打包相应许可。
- 详见 [refinement-and-handoff.md](refinement-and-handoff.md)；这些是设计与代码约束，不构成自动对成片做视觉验收的授权。

## 弹簧与直接操控

本包 assets/motion-core.mjs 提供欠阻尼和临界阻尼闭式 step、多个目标变化叠加的 springTrack、给定初始速度的 releaseSpring、双端零速度插值。以秒为单位，omega 的单位是 rad/s。

多个目标阶跃 q0→q1→q2 的轨道：

x(t) = q0 + Σ (qi − q(i−1)) × step(t−ti)

不能每次进入新状态就把弹簧从零重启。跟随光标拖拽时用直接位置计算，不要让弹簧造成明显跟手延迟；松手根据当前 x 与速度 v 切入 releaseSpring。

标签/开关：分别计算 left(t)、right(t)，领先端更早或更快、尾端稍后跟上。反向移动时交换领先端；约束 right−left 为正，圆角 ≤ min(width,height)/2。拖过边界可使用 L×(1−exp(−d/L)) 的有限拉伸，松手回弹。数值合法范围与视觉形变分离，音量值仍限制在 0–1。

## 内容清晰与形态承接

主容器尺寸真实变化，不通过 scaleX/scaleY 压扁整张播放器。位置、宽高、圆角、阴影独立求值。正文在局部坐标中重排，颜色线性插值需限制合法范围，alpha 也限制 0–1。

旧内容先淡出，容器开始形变，新内容延迟进入。旧/新文案拥有各自的可见区间，必要时容器 overflow hidden。数字可用逐列滚动并裁切，不能让两套完整大数字长期叠着显示。图表先创建固定采样点，再按统一参数插值；不能在不同节点数的路径之间盲目 morph。tooltip 的锚点由相同曲线函数算出。

光标是视频内绘制的矢量层，不用系统鼠标来录屏。轨迹与点击、拖拽、hover 同一时间轴。图标也使用路径，不依赖平台 emoji。

## 画幅与相机

默认按参考 1:1；若用户要 16:9 则重排安全区域，而非拉伸成片或裁掉图表。所有输出尺寸保持偶数。相机缩放只能是额外克制的画面控制，不掩盖主形变。文字发糊时优先检查真实渲染分辨率、设备像素比、字体加载和非整数变换；不要把 will-change 的有无当作清晰度保证。

## 导出

优先平台已验证的确定性渲染器。备用流程需要 Node、Playwright/Chromium 和 FFmpeg 在实际执行环境可用；主机已安装不代表应用沙箱内已安装。先检查再决定如何补齐。

浏览器加载 HTML，等待 document.fonts.ready 和资源解码。viewport 与输出像素一致，deviceScaleFactor=1。对每一帧 i 调用 await page.evaluate(t => window.seek(t), i/fps)，随后截图固定画面区域。确认 seek 已完成 DOM 更新。一个 14 秒、60 fps 视频只导出 i=0…839，不再附加 t=14 的重复帧。

FFmpeg 图像序列编码例（替换实际路径）：

```sh
ffmpeg -framerate 60 -i frames/%06d.png -c:v libx264 -crf 18 -pix_fmt yuv420p -movflags +faststart silent.mp4
```

运动模糊可先关闭；确认几何和时序后，快速运动帧在自身快门窗口内取 4 个子样本，合成一帧。建议 180° 快门，曝光时间 = 0.5/fps；线性色彩空间平均后转回输出色彩空间更准确。循环片子越界采样需 wrap。不要用跨相邻成品帧的 tmix 默认滑动平均替代帧内采样，否则会把文字和接缝拖花。若文字不参与模糊，需先明确这是视觉取舍。

音轨裁成目标长度，以事件表安排 click/scrub/success 音效；音乐的拍点必须实际检测或人工校准。120 BPM、4/4、7 小节 = 14 秒只说明设计网格，不证明原曲节拍。检查 AAC 编码延迟、尾帧与播放设备的循环行为，不因容器时长多几十毫秒就强行篡改画面帧数。

## 技术验证与审阅边界

- 随机顺序调用 seek(8)、seek(2)、seek(8)，两次 8 秒输出必须一致。检查全部属性都重设。
- 仅在用户要求循环时，比较 t=0 与 t=T 的计算状态及边界附近速度，包括光标、透明度、颜色、阴影、图表、相机。不能只用 t%T 或 HTML 自动重播声称视频无缝；有意开合场可不循环，但应说明。
- 本例可在最后约 0.5 秒平滑归位并落稳，让开头与结尾都静止。零速度边界可用 smooth5 收尾。若需要始终运动则匹配位置和一阶导数。
- 首尾连续不等于把第 839 帧替换成第 0 帧；强行替换可能产生一帧跳变。
- 保存分层调试数据、逐拍与中点静帧供用户审阅；技术运行无错误、边界检测结果或缩略拼图，均不能证明图标不遮字或用户已接受画面。
- 不主动对自己生成、剪辑或渲染的画面做验收式质量分析，也不依据该分析自行追加修改。用户明确要求核查时，限于其时间段和问题：用原分辨率局部帧及布局数据分辨图标、文字、徽标、指针和转场关系，考虑裁切与有效透明度，不扩大为全片美术排查。
- 测量视频实际分辨率、帧率、帧数、时长、解码结果和音频峰值；这是文件与编码测试，不等于已试听、已看完全片或视觉无瑕疵。用户要求试听或核查循环时，再按范围执行。
- 交付报告写清实际做过的测试、容差、限制与待用户审阅内容；未试听或未全片渲染不得写“通过”。不要求末帧等于首帧来代替连续性；如存在可测微小栅格差异，说明测量而非伪称完全一致。
