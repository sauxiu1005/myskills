# 视觉审查（Visual Review）

审查是为了找出少数高影响问题并修正，不是给自己打分。不能无休止自评追分，不能把自己的检查称为"独立评审"，不能把没运行的测试写成通过。

## 1. 两个阶段

**A0. 角色姿态小样（制作前，一张）**：`tools/char_sheet.py` 出小样并按 `style-presets.md` §4 自查，修完直接继续，不额外等待审批。

**A. 风格关键帧先审（制作前，便宜）**：每个主要场景 1 张关键帧。看内容是否对应句意、角色/物体轮廓是否可认、构图与信息层级、文字是否可读。通过后再做动画或付费视频。

**B. 正式成片审查**：
- 联系表：每 0.5–1 秒一帧，标时间码与镜头号
- 连续帧：每个切点前后各 3 帧；最快动作的完整连续帧
- 原尺寸关键帧：5–8 张，在输出分辨率下看边缘、文字、细节

## 2. 检查项

| 项 | 看什么 |
|---|---|
| 语义对应 | 每拍画面是否表达了该句意思；不看字幕能否猜到大意 |
| 动作结果 | 起始→动作→结果是否都可见，结果有停顿 |
| 字幕/文字 | 可读、安全区内、不压主体、无缺字或替代字体；中文没有被画成空框（见 §6） |
| 重复构图 | 相邻镜头是否同景别同构图无新信息 |
| 遮挡 | 角色、标签、UI 互相遮挡；等距 y 排序错误 |
| 像素质量 | 边缘混色、抖色闪烁、噪点、非整数缩放、模糊 |
| 声画同步 | 关键事件与起音的误差（见 cue-sheet-and-audio §5）；未测写未测 |
| 旁白清晰度（0.4.7） | 按 cue-sheet-and-audio §6.1 实测：旁白区音乐比旁白低 ≥15 LU、空隙 ≥6 LU，音效峰值低 ≥6 dB；不达标不交付 |
| 输出参数 | ffprobe 实测分辨率、fps、帧数、时长、音轨 |

## 3. 问题记录格式

```
[时间码/帧] 现象 → 影响 → 具体修正（参数、帧数、像素、颜色）→ 验证方式
```
例：`[00:08.50 / f204] 第一本本子落下时门外人数没变 → 因果关系读不出 → 把"门外+2人"事件与 s3-stack-1 同帧 → 重渲 f200–f215 连续帧确认`

## 4. 节制

- 优先 3–5 个高影响问题；小瑕疵记录但不阻塞交付。
- 修改前保留当前版本（视频、工程、事件表）作为备份。
- 只有用户的任务需要时才实际重渲染；否则交付问题清单与修改方案。
- 报告分清：已运行的检查、只做了文本走查的、未做的。

## 5. 姿态、材质与语义动作验收（0.4.0）

技术校验通过不等于视觉通过。每镜至少看一张原尺寸关键帧，逐项回答"是/否 + 原因"：

| 项 | 通过标准 |
|---|---|
| 姿态 | 主动作有清楚的预备（压缩/蓄力）、动作、结果（落地压缩/停顿）；四肢不打结；被遮挡物（桌子、画框）不切掉下巴或头 |
| 材质 | 金属、木、砖、布、纸能互相区分；不是同一色块换色 |
| 语义动作 | 不看字幕能读出这句的动作（掉币、顶块、分出 10%、划掉"固定%"）；数字变化与动作同帧 |
| 群像 | 发色、衣色、身高、配饰至少两项不同；不能整排一模一样 |
| 角色身份（0.4.3） | 主角/配角按本次文案设计并在 `cues.json` 的 `cast` 中声明；没有用户要求、系列连续性或角色参考时，不出现旧示例人物（眼镜大头青年、芥末黄卫衣、同一骨架） |
| 角色美观（0.4.5） | 无特定要求时人物清爽讨喜：发型整洁有高光、额鼻下巴圆润短小、闭眼/颊色少量像素、肤色暗阶不大片铺；无胡茬、皱纹、凹陷侧脸等显老特征；用户指定年龄/外形/写实/怪诞或给参考时以用户为准（`style-presets.md` §5） |
| 角色造型（0.4.3） | 剪影一眼可认；每材质 2–3 阶；脸部少量像素读得出状态；无细碎尖发、巨大白眼镜、降采样糊边；新姿态是重画而不是旋转/缩放旧角色；比例自然 |
| 刘海与眉眼（0.4.6） | 刘海画成 4–6 组宽短像素簇、每组 2–3 色阶，额头留空；双眼与眉完整可见，不被发束遮挡；不出现满屏尖刺发束（像栅栏）；脸不是"平涂底色 + 细三角"的矢量动漫画法，要有像素簇明暗 |
| 主体尺度与线宽（0.4.6） | 主体（角色、晶体、门、建筑核心）占画面高度 ≥1/3，特写更大；主能量弧/光轨 2–4 逻辑像素宽，内核与外沿分阶分明，1 像素细线只做点缀 |
| 纵深与背景（0.4.6） | 至少一层前景遮挡或穿越（柱、碎石、粒子、建筑剪影）建立纵深；背景细节服务空间，不靠满屏随机碎点、无意义点阵或噪点凑"细节" |
| 是真动画（0.4.6） | 角色有真实的肢体动作与位移；整张图平移、缩放或局部晃动冒充动画判为不通过 |
| 文字 | 标签可读、在横幅/面板内、不压放射束、不被底部字幕压住 |
| 风格对照 | 有参考时，与参考并排：颗粒、底色、轮廓宽、头身比、切镜与特效节奏一致 |

先出方向关键帧或 ≤6 秒样片，通过后再做全片；画风被否定时不在原方向上继续加细节。

## 6. 字幕验收（0.4.4）

事故：0.4.3 及以前的 arcade-navy 模板把所有文字交给像素字体 Geneva，Geneva 没有中文字形，中文字幕只剩底部空框。技术校验（帧数、响度、解码）全部通过，没能发现问题。

| 项 | 通过标准 |
|---|---|
| 字形覆盖 | `python3 scripts/check_subtitles.py cues.json` 为 PASS；含中文的文本使用带中文字形的字体（默认 Hiragino Sans GB），英文才走像素字体 |
| 实帧可读 | 每句字幕至少取 1 张实际渲染关键帧（原尺寸底部条带），逐句对照原文读出，无空框、方块、缺字 |
| 不截字 | 字形画布按字体真实 bbox 与 ascent+descent 的并集开，顶部/降部/左右不被切；字不出底框 |
| 字号与网格 | 中文逻辑字号 12/16/22（字幕 16）无抗锯齿栅格化后最近邻放大到输出网格，字高 ≥42 输出像素；不用平滑缩放 |
| 换行与安全区 | 超宽自动换行：中文按字断行、句读不在行首、开括号不在行尾；英文按空格；字幕框左右各 ≥5% 安全边距、底部不贴边 |
| 清洁版 | `PIX_CLEAN=1` 时文字层完全为空（不留空字幕框、标签框），可用 UI 层像素数 = 0 验证 |
