# 风格预设与参考画风转译

## 0. 何时用

用户给出美术参考（视频、截图），或否定了当前画风时，先按 §2 拆看参考，再选或新建预设。预设只规定**画风、色调、动态语法**；故事、旁白、时间表照常来自语义节拍与 `cues.json`。

## 1. 预设 arcade-navy（街机海军蓝）

| 维度 | 规格 |
|---|---|
| 颗粒 | 逻辑 320×180 → 2× → 640×360 → ×3 = 1920×1080（参考约 240×180 ×4）；1 像素 ≈ 6 输出像素。这是本预设的默认画布，优先于 SKILL 中其他画风的 640×360 ×3 |
| 底色 | 近黑海军蓝 3 阶竖向分阶 + Bayer 抖色过渡；上部靛紫斜向点阵，下部靛紫透视网格地面 |
| 强调色 | 金黄（奖励、金币、横幅字）、青蓝（UI、经验条、速度线）、朱红（问号、划掉、长桌）；每帧强调色不超过两种为主 |
| 轮廓 | 角色与道具 1 逻辑像素墨色全封闭外轮廓（输出约 6px）；内部平涂 1–2 阶 |
| 角色 | **不预设角色**：主角与配角按本次文案设计（§4），人物、动物、物件均可，比例随角色需要。预设只规定画法：1 逻辑像素墨色闭合轮廓、每材质 2–3 阶、脸用少量像素、表情靠眉眼嘴的 1–2 像素变化；群像发色、衣色、身高、配饰至少两项不同。参考片里的眼镜大头青年只是示例（模板 `draw_zhou`，legacy），不是默认主角 |
| 景别 | 按文案在远/中/近/大特写之间硬切；特写重画不放大 |
| 场景 | 室内（深夜书桌、窗外城市）、会议长桌、蓝天街机舞台（渐变天+扫描线、白云黑边、绿山、红砖地、?块）、选卡界面、群像 |
| 文字 | 像素字 + 墨影；HUD 计数「金币图标 ×N」；横幅蓝底金边金字；关键数字用小型游戏内数字，字幕在底部 |

### 动态语法（参考逐帧拆出）

| 语法 | 参数 |
|---|---|
| 切镜 | 硬切为主；机位静止，不做推拉摇 |
| 速度线特写 | 横向遮幅 + 多层水平速度线以不同速度扫过；人物冲入 2–4 帧后定住；镜片闪光 6 帧扫过 |
| 放射束 | 金黄点阵 8–12 条，每 2 帧顺时针步进一档（不平滑旋转），近疏远密 |
| 横幅 | 4 帧硬弹入（冲到 125% 再回 100%），字在 ≥90% 时出现 |
| 跳顶块 | 蓄力压缩 3 帧 → 上升 8 帧 → 顶点撞块（块上弹 6 帧）→ 下落 6 帧 → 落地压缩 3 帧 → 可立刻再跳 |
| 金币 | 4 相旋转；从块顶弹出走抛物线；落定时计数器 +1 |
| 群像 | 举手与爱心从左到右每 3 帧出现一个 |
| 疑惑→信服 | 问号气泡轻跳 → 特写疑惑 → 感叹号 + 低头 |

### 语义转译示例（复利主题）

| 句意 | 画面 |
|---|---|
| 年轻最大的优势是时间 | 空钱包只掉 1 枚币、耸肩 → 特写举沙漏；顶部金币条极短、时间条满格 |
| 收益开始再生收益 | 3 块各出 1 枚（线性）→ ?块金字塔连锁 1→2→4→8 |
| 100→110→121 | 顶块后金币链分落单利/复利两堆；HUD 计数逐枚加；第 11 枚从复利堆自己跳出、发光 |
| 多出的 1 来自早先收益 | 审核员冒问号 → 10 枚利息各分出 10% 碎片合成发光 1 → 审核员低头 |
| 学习类似但非固定比率 | XP 条 + 习惯星 → 不规则砖柱台阶跳（平台、回落、跳升），虚线「固定%」被红叉划掉 |
| 选一项、练习、复盘、下一次 | 选卡只选吉他 → 每周点亮 → Practice/Review/Next 三块连跳 → 群像爱心 → 收尾横幅 |

## 2. 拆看参考（交付条件之一）

1. 读客观参数：分辨率、帧率、时长；估算逻辑像素（测眼睛、轮廓线、细线的块宽）。
2. 抽三类图：全片每 2 秒总览；用户点名片段每 1/6 秒连续帧（动作节奏）；关键原帧（取色与线宽）。
3. 写下：底色分阶、强调色、轮廓宽、头身比、眼睛画法、景别分布、切镜方式、特效形状与步进节奏、UI/字幕样式。
4. 只转译语法与手感，原创角色、场景与文案；不复制水印、原片文字、角色与标志。参考中的人物只学画法，不变成后续所有主题的固定模板。

## 3. 先样片后全片

- 画风有分歧或用户给了新参考时，**先做 1 张方向关键帧或 ≤6 秒有声样片**，并排放参考原片与结果，再继续全片。
- 样片取自正片时间表的一段（同一 `cues.json`、同一音轨同段截取），通过后直接成为正片的一部分，不白做。
- 本次教训：画风连续两次被否定（泛 16-bit RPG 讲解面板 → 泰拉式地形漫游），原因都是在没有对照参考的情况下推进整片。

## 4. 角色：按文案设计、在网格上手画（0.4.3）

**身份规则**
- 画风、动作语法、渲染能力可以复用；角色身份不自动复用。每个新主题按文案确定主角（人物、动物、物件均可）和配角。
- 只有三种情况继承已有角色：用户要求沿用；系列内容需要连续性；用户提供了角色参考。
- 模板里的眼镜大头青年 `draw_zhou`（以及 `A.hero` / `A.npc`）是 legacy 示例。代码路线下，只有 `cues.json` 的 `cast` 声明了 `"kind": "legacy_zhou"` 才能调用，否则直接报 `CastError`；新主题不得静默回落到它。
- 每个工程在 `cues.json` 写 `cast`：`{"lead": {"name": "橘猫", "kind": "sprite|custom", "module": "characters.cat"}}`，场景通过 `engine/cast.py` 的 `cast.load("lead")` 取角色。

**造型方法（实际逻辑网格上逐像素画，`engine/sprite.py`）**
1. 先剪影：在实际逻辑网格（如 320×180 小画布）上，只用轮廓色把外形画清楚；缩到原尺寸看仍认得出是谁、在做什么。
2. 再像素簇：按材质分区（头发、皮肤、衣服、毛、金属……），每种材质 2–3 阶（暗/中/亮），簇要成块，不留单像素噪点。
3. 轮廓阶梯受控：斜线和弧线按 1-1、2-1、2-2、3-1 等规则步进，不乱跳；闭合墨色轮廓 1 逻辑像素。
4. 脸用少量像素：眼 1–2 像素（闭眼 = 横线，睁眼 = 眼白 + 瞳孔），嘴 1–2 像素，眉 1 像素；不用巨大白眼镜代替五官。
5. 比例按角色需要：成人自然头身比、Q 版、动物、物件拟人都可以，不强制大头；同一角色跨镜保持剪影、配色、配饰。
6. 特写脸（0.4.6）：刘海画成 4–6 组宽短像素簇，每组 2–3 阶，额头留出空间，双眼与眉完整露出；构图偏一侧，给能量光轨或动作留出空间；眉眼表情要靠像素簇的明暗读出来，不靠平涂底色加细三角高光（会变成矢量动漫感）。
7. 禁止：细碎尖发、圆滑卡通矢量画完再降采样、旋转/缩放现成角色来凑新姿态（例如把站姿转 90° 当睡姿）——新姿态在网格上重画，表情差异用 `Sprite.variant` 做小改。

**角色姿态小样与自查（开工前一张）**
- `python3 tools/char_sheet.py characters.<角色>`：把 `POSES` 里的所有姿态按逻辑像素放大成一张带网格的小样，并打印每材质色阶数（>3 报警）和孤立像素。
- 自查项：剪影是否一眼可认；材质是否 2–3 阶；脸是否用少量像素读得出状态；有没有碎发、白眼镜、降采样糊边；与场景同尺寸放入一帧时比例是否自然。
- 自查不过就改网格再出一次；通过后直接推进已授权的制作。只有用户明确要求挑选角色时才暂停等待选择，不额外增加审批。

## 5. 默认人物美观（0.4.5）

事故：猫片主人第一版网格睡姿鼻尖、下巴过度凸出，下颌大片暗色，侧脸凹陷，被反馈"太丑、像老男人"。

**默认**（用户没给年龄、外形、写实/怪诞要求或角色参考时）：清爽、讨喜、精致的复古像素角色。
- 发型整洁、有设计：蓬松成块的短发或明确发型，3 阶（顶部高光、后脑阴影），边缘阶梯规整，不出细碎尖发。
- 轮廓舒展：额头、鼻尖、下巴走圆润的像素阶梯（1-1 / 2-1），鼻尖 1–2 像素微凸，下巴短小；侧脸不凹陷。
- 五官协调、少量像素：闭眼 = 2 像素短线；睁眼 = 眼白 + 瞳孔 2×2；颊色 1–2 像素放在眼下；不画胡茬、法令纹、眼袋、皱纹。
- 肤色明暗干净：亮/中/暗 3 阶，暗阶只用于颈下、发际等少数交界，不在下颌或脸颊铺大片阴影。
- 没有年龄设定的日常主题：年轻成年人的中性造型。

**优先级**：用户给的年龄、外形、写实或怪诞风格、角色参考优先于本节默认；系列角色沿用既有身份。美观不等于固定性别、肤色或年龄，老人、儿童、不同体型与肤色都可以画得好看；不把所有人年轻化。本节只定审美底线，不固定某一个主角，每个主题仍按 §4 设计新角色。

**画法建议**：只写填色矩阵，再用 `engine/sprite.py` 的 `outline(rows)` 按 4 邻接自动补 1 像素墨线；姿态变化用补丁（`Sprite.variant`）改眼、眉、嘴。

**自查（角色姿态小样 + 场景放大各看一次）**：
1. 第一眼年龄、气质与设定相符（默认读作年轻成年人，不显老）。
2. 无胡茬感、皱纹、凹陷侧脸、大鼻头、长下巴、大片深色下颌。
3. 头发成块、整齐、有高光，没有尖刺碎发。
4. 闭眼/睁眼、鼻尖、颊色、耳、颈各自读得出，且不靠大块深色。
5. 放进实际场景、按输出尺寸看，比例自然，和主角（如动物）风格统一。

# 附：参考学习记录

来源：用户提供的抖音短视频（本地文件 52.48 秒，960×720，30fps）。以下观察来自**用户**对全片每 2 秒画面的核对，本 Skill 编写时未对该视频做独立分析，也**未分析音轨节拍**；因此不得声称已做音频节拍验证。只学习方法，不复用其文案、角色或画面。

| 时间段 | 观察 | 学到的方法 |
|---|---|---|
| 0–4 秒 | 电脑近景→拉开看到纸堆与专家 | 尺度揭示 + 数量具象：把抽象工作量变成可数成果 |
| 4–8 秒 | 夜景屋顶与奖章 | 奖励与情绪停顿 |
| 8–12 秒 | 答辩转译为 RPG 战斗 UI，专家血条减少、人物消失 | 冲突游戏化；变化发生在动作之后（结果可见） |
| 12–16 秒 | 举起论文、获得奖励、专家递水果 | 奖励与反应，关系反转 |
| 16–20 秒 | 同位置机房设备转成灶台/冰箱/厨具 | 场景同构变形：同一位置逐物替换 |
| 20–24 秒 | 办公桌和电脑转成餐桌饭碗 | 同上，延续同一空间 |
| 24–28 秒 | AI 小机器人变厨师，传送带产出饭菜，观众头上出现爱心 | 身份角色化 + 过程产出 + 旁观者反应 |
| 28–32 秒 | 奖学金具象为金币计数、堆积与银行金库 | 数量增长 + 容器揭示 |
| 32–36 秒 | 俯视游戏画面拉开显示手持屏幕与手指 | 尺度揭示（屏幕内外） |
| 36–42 秒 | 导师对话框→人物选角卡（射手/辅助） | 身份角色化 |
| 42–46 秒 | 角色在俯视地图上协作推进 | 关系游戏化（协作） |
| 46–49 秒 | VICTORY、领奖台、MVP | 结尾收束 |

全片：主角（绿衣、眼镜）、机器人等重复角色、字幕位置、轮廓与 UI 风格保持一致；大量侧面构图，但每拍都有状态变化，不是单调横向跑跳。

### 局限

- 49–52.48 秒未在观察中描述。
- 镜头切点与音乐/旁白的对应关系未验证；每 2 秒抽帧可能漏掉短于 2 秒的变化。
- 该参考大量使用游戏 UI 隐喻是因为其文案主题适合；本 Skill 规定按文案选择修辞，不默认游戏化。
