# 应用路由（Application Routing）

有文案、歌词或旁白时，先按 `copy-to-scene.md` 完成语义节拍，再用本表为每拍选视角与路线。侧视构图可以用（很多好作品大量使用侧面构图）；问题是每类内容、每个节拍都套同一个横版跑跳。

## 2. 视角词表

| 视角 | 用途 | 规则 |
|---|---|---|
| 等距 2:1 | 城镇、关卡、机械结构、展台 | tile 宽:高 = 2:1（如 32×16）；线条按 2 像素横 1 像素纵步进；光源固定左上 |
| 俯视 3/4 | RPG 地图、地牢、农场 | 地面正投影，物体露正面；遮挡按 y 排序 |
| 剖面/剖视 | 地质、建筑、器官、机器 | 切面用统一的切割色 + 1px 边；内外层次 ≥3 层 |
| 局部放大（内容聚焦） | 分子、零件、细节 | 用带边框的放大框/圆形透镜，**框内按更大像素尺寸重绘**，不是放大原像素；连接线指向原位置 |
| 全景 | 建立空间、总结 | 结构完整、留出标签位 |
| 示意图/信息图 | 流程、因果、对比 | 箭头、编号、图例在同一网格；像素箭头带 1px 轮廓 |
| UI 层 | HUD、字幕、标签、卡片 | 可声明为独立层，字号以最终可读为准 |
| 侧视 | 平台跳跃、追逐、行进 | 仅在内容本身是横向运动时 |

## 3. 信息层级（讲解与 UI）

1. 主体画面（过程本身）
2. 一级标签：当前步骤名（大号像素字，屏幕上同时 ≤1 个）
3. 二级标签：部件/物质名（小号，指示线连到对象）
4. 字幕：旁白原文，底部安全区，独立层
5. 图例/编号/时间轴：角落，常驻但低对比

同屏新出现的信息每次只加 1 项；标签出现要与旁白提到它的时刻对齐（±6 帧）。

## 4. 事实与示意

- 讲解脚本中的数字、比例、年代、机制逐条列入"事实核查"清单，未核查的不写进画面。
- 示意动画（粒子数量、流速、比例）是示意，不是实测数据；画面或片尾注明"示意"。
- 不把示意图画成像真实数据图表的样子（坐标轴+刻度+数值）除非数据有来源。

## 5. 游戏制作支持的边界

- 视频、概念图、精灵表、UI kit 都是**素材或演示**，不是游戏。
- 可玩原型只在用户提出交互目标（操作、规则、胜负或体验目标）后制作，交付可运行文件与运行方式（例：浏览器打开 index.html，方向键移动）。
- 用户自己的游戏 IP、角色和 UI 规范必须来自用户素材。
