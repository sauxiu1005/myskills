# 风格与网格（Style & Grid）

## 1. 细节档位

| 档位 | 逻辑画布（16:9） | 输出 | 色数 | 角色高（全景/中景） | 适用 |
|---|---|---|---|---|---|
| **高细节现代像素（默认）** | 640×360 | ×3 → 1920×1080 | 32–64 | 40–72 px；特写重绘 120–240 px | 讲解、游戏、叙事、产品 |
| 密集高细节 | 960×540 | ×2 → 1920×1080 | 64–128 | 60–100 px | 等距城镇、复杂剖面、群像 |
| 低像素复古（仅用户明确要求） | 320×180 | ×6 → 1920×1080 | 8-bit ≤16；16-bit 16–32 | 16–48 px | 街机怀旧、8/16-bit 致敬 |

竖版：360×640 ×3 → 1080×1920，密集 540×960 ×2。方形按用途：540×540 ×2（1080²）或 360×360 ×3。
只做整数倍最近邻放大。这些是制作建议，不是模型原生参数。

## 2. 细节必须是真画出来的

- 提高逻辑分辨率后要真的画出更多结构：材质层次（木纹、石缝、瓦片、水面高光）、结构件（窗框、梁、管道）、表情（眉、眼、嘴至少 3 种状态）、可识别物体（工具、植物种类、标识）。
- **禁止把旧的低分辨率图放大当作新分辨率**：放大 2× 的 320×180 画面在 640×360 上每 2×2 块都单色，等于没提升。
- 密度自检：统计逻辑画面中"非单色 2×2 块"的比例。接近 0% 说明是放大冒充；这一比例**只证明没有简单放大，不代表美术质量**，数值高也可能只是噪点或抖色。另统计单帧实际用色数，与色板规模相符。
- 禁止用随机噪点、满屏抖色或无意义纹理凑密度；抖色只用于有目的的渐变与材质过渡。
- 不同镜头的角色像素尺寸可以不同：全景小人、特写重绘大头像各自按尺寸绘制，保持轮廓关键词、配色与特征一致，而不是同一精灵缩放。

- 密度是基础条件，不是质量指标：角色与场景是否一眼可认、视觉点子是否准确优先于加像素或加噪点（质量判断顺序见 copy-to-scene.md §6）。

## 3. 像素纪律（与档位无关）

- 像素簇：同色成团，避免孤立杂点和"枕头阴影"；高光是有意的小簇。
- 清晰边缘：无抗锯齿混色（可用手工 1px 中间色做选择性抗锯齿，但必须来自色板）。
- 受控抖色：仅大面积渐变或材质过渡，固定有序矩阵；运动物体不抖色。
- 轮廓：高细节档默认选择性轮廓（受光侧用深色阶替代黑线），小物件可用 1px 深色轮廓保证可读。
- 发光：硬边核心 + 1px 外圈，禁止全屏柔焦。

## 4. 色板

- 默认 32–64 色，复杂场景 64–128 色；以色阶 ramp 组织（每条 4–7 级），色相随明度偏移。
- 角色：轮廓/阴影/中间调/高光/发光核心/特效专用/UI 专用/切面色（剖面）。
- 色板文件 `palettes/*.json`：`colors[].hex/role/ramp`、`ramps`、`cycle_ranges`、`fx_colors`。默认高细节套：`atlas-daylight.json`（讲解）、`iso-meadow.json`（游戏场景）；低分辨率复古套：`dusk-arcade.json`、`neon-harbor.json`、`moss-shrine.json`。

## 5. 文字与 UI 层

- 文字以最终可读为第一优先：1080p 输出下中文字高 ≥ 36 输出像素（640×360 网格上 ≥12 px 像素字体；也可声明独立 UI/字幕层，以输出分辨率排像素字体或清晰字体）。
- 独立层要在风格圣经中声明，且边缘、配色与像素画协调；不让生成模型写中文。

## 6. 一致性设定表

```
名称：
轮廓关键词：（≤3 个）
尺寸：全景 __px / 中景 __px / 特写重绘 __px（逻辑像素）
色板索引：主色/次色/皮肤/轮廓/高光
关键特征（不可变）：
表情/姿态库：每个姿态帧数；方向数（4/8）
```
tileset 追加：tile 尺寸（等距 32×16 / 俯视 16×16 或 32×32）、拼接边规则、遮挡排序。

## 7. 风格圣经模板

```
档位：高细节现代像素 | 画布：640×360 ×3 | 24fps，姿态一拍二
色板：<名称>（48 色），特效色：…，UI 色：…，切面色：…
视角：<逐镜>   光源：左上   轮廓：选择性   抖色：仅天空/水体渐变
文字：<像素字体 12px 在网格 | 独立字幕层 40px>
禁止：模糊、全屏辉光、补帧、非整数缩放、放大旧图冒充细节、默认横版跑跳
```

## 8. 语义材质色槽与重照明

为服务叙事中的时间、天气或情绪变化，用**语义色槽**而不是直接写死颜色：

1. 绘制时每个像素记录的是"材质色槽"（如 `墙-暗/墙-中/墙-亮`、`叶-1…4`、`皮肤-阴/亮`、`字幕-底/字`），不是 HEX。
2. 每个场景状态（白天、黄昏、夜晚、雨天、紧张、温暖）定义一张 **色槽 → 色板索引** 映射表；切换状态只换映射表，几何不变。
3. 过渡：按事件表的 `palette` 事件逐步切换（每步 2–6 帧，可用有序抖色阈值做 2 级过渡），不做逐像素 RGB 插值，以免产生色板外颜色。
4. **局部光源**：只在真实存在的光源（灯笼、台灯、屏幕、火、窗光）周围定义 mask，mask 内把色槽沿各自 ramp 提亮 1–2 级或换到暖/冷 ramp；mask 边缘用 2 级抖色硬边，不做柔光。
5. **保留**：角色识别色（主角标志色、配饰）与字幕/UI 的文字对比度在所有映射中保持；夜景时可降低环境但不改主角标志色相。
6. 光源不存在时不随意闪全屏；全屏闪光只用于叙事上确有的强光事件（闪电、爆炸），且 1–2 帧。

色槽映射写在色板 JSON 的可选字段 `slot_maps`（`{状态名: {色槽: 索引}}`）中，或写在工程配置里；现有色板未包含此字段，需要时新增。
