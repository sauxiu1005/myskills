# 制作路线（Production Routing）

## 1. 两类结果必须区分

| | AI 近似像素 | 严格网格渲染 |
|---|---|---|
| 来源 | 图像/视频生成模型 | 程序逐帧绘制或代码动画 |
| 网格 | 近似；后期对齐后仍可能有混色、像素尺寸不一 | 每帧精确在逻辑网格上 |
| 帧数/时序 | 不可精确控制；提示词写"12fps"无法保证 | 精确到帧 |
| 适合 | 自然角色表演、复杂场景、有机运镜 | 精准特效、文字、Logo、循环、产品镜头 |
| 成本 | 付费生成 | 本地渲染，无生成费用 |

不得承诺提示词能保证像素网格、色数或帧数精确。

## 2. 平台可用能力（按领域动作描述，以运行时能力契约为准）

- 生成静帧：用于风格参考、角色设定、关键帧、场景底板；支持多参考图保持一致，部分模型支持透明背景（便于做精灵）。
- 生成分镜视频：单段时长受模型限制（常见 4–15 秒），支持参考图引导或首尾帧绑定；每段建议只承载一个镜头、一个主动作。
- 单条媒体变换：裁切、缩放（可指定最近邻）、调色、抽帧、叠加、混音、烧字幕。
- 视频拼接：按顺序首尾拼接多段。
- 时间线剪辑器：字幕、预览截帧、成片导出。
- 代码渲染：逐帧渲染像素动画、特效、像素文字、网格校验、MP4 编码与可编辑工程。
- 配乐与音效：器乐/芯片音乐风格配乐。
- 旁白：讲解类脚本确认后生成语音，以实测时长定镜头；字幕可由脚本直接生成或对旁白转写后排版。

**禁止用于像素素材**：视频增强/补帧（会插中间帧和中间色）、平滑超分（会抹掉硬边）。需要放大时用整数倍最近邻。

## 3. 路线判定

1. 镜头含精确文字、Logo、产品外形、帧级特效、无缝循环、讲解示意/剖面/信息图、tileset/精灵表/UI → **B 严格网格**。
2. 镜头是自然角色表演或复杂场景、可接受近似 → **A AI 近似**。
3. 两者兼有 → **C 混合**：AI 生成底板，后期网格对齐，再用代码叠加特效/文字/转场。
4. 精细像素电影感 / 游戏过场，需要真实角色表演、追逐、打斗，或用户否定了程序拼块人物 → **A**：先定 1 张美术方向关键帧并经用户认可，再用它作参考生成视频；不回落到 B 的程序人物。整张图平移缩放不算动画。
5. 用户只要求"像素风感觉"、预算低，且不属于第 4 条 → 优先 B（免费），必要时少量 A 做背景。

## 4. 路线 A 流程

1. 批量生成：美术方向关键帧 1 张（锁定角色、场景、光色、像素画法），必要时补角色设定或首尾帧。只描述静态。用户已提供认可的方向图时直接用它。
2. 用户确认静帧后，批量生成视频：每段承载一组连续节拍，写清起始状态、动作与结束状态，按所选模型的模型知识拆成它能稳定完成的镜头数（通常每 5 秒 2–3 镜）；方向图作画风/角色参考，镜头确实从它开始时才作首帧。段间在动作上硬切。段数少而饱满，角色更一致、成本更低。
   - 报价：能力契约若未列价格，不用付费任务探价；写明段数、单段时长与分辨率，实际金额以提交时的确认弹窗为准。
3. 网格对齐后期（每段）：最近邻缩小到逻辑画布（默认 640×360，不要缩到 320×180 导致细节丢失） → 量化到色板（不抖色或有序抖色）→ 整数倍最近邻放大。说明：会损失细节，脸部和细线可能崩，需用户审阅。
4. 帧节奏：可抽帧为一拍二（保留偶数帧并复制）制造像素感，但不能修复 AI 产生的形变。
5. 时长：分镜里短于模型最短单段时长的镜头，按最短时长生成后在剪辑中截取所需帧（费用按生成时长计，确认时写明）；不要为凑时长拉慢动作。

### 用户提供实拍或现有视频

把它当作动作、构图与节奏的参考：用参考引导的视频重绘生成像素风版本（路线 A），或抽关键帧重绘为像素静帧后再做首尾帧视频。只做"缩小+量化+放大"的结果等同马赛克滤镜，只能作为预览并明确说明，不能当作成片风格。

## 5. 路线 B 渲染简报要点

逻辑画布与放大倍数、fps 与姿态节奏、色板 JSON 路径、角色精灵规格（尺寸/色板索引/姿态帧数）、图层与视差系数、每镜时间表（帧号）、特效规格（来自 motion-and-vfx 附录特效库）、文字内容与字体要求、输出（MP4 + 工程 + 联系表）。要求渲染端自检：每帧颜色 ⊆ 色板、每个放大块内颜色一致、逻辑画面非单色 2×2 块比例（只证明不是放大旧图，不代表美术质量）、实际分辨率与帧数。

## 5b. 讲解类流程

旁白脚本 → 事实核查清单 → 分镜（逐镜视角与信息层）→ 用户确认 → 生成旁白并实测时长 → 按旁白定帧数 → 画面制作 → 字幕/标签层 → 混音。示意动画注明示意。

## 5c. 游戏制作支持

素材类（tileset、精灵表、UI kit）交付 PNG + 规格 JSON；演示视频明确是视频；可玩原型需用户给交互目标，交付可运行工程与运行方式。

## 6. 中文与精确文字

一律后期排版：位图/像素字体对齐逻辑网格（640×360 网格上中文 ≥12px 字高），或声明独立 UI/字幕层并以最终可读性定字号，或在代码渲染中直接绘制。不让生成模型写中文。

## 7. 预算与失败

- 付费生成次数在确认环节写明；不自动加候选、不无限重试。
- 失败或跑偏：说明问题与原因，给出一个修改方案（换首帧、简化动作、改走 B 路线），经同意后执行。
- 预算不足：降级为 B 路线或减少 A 镜头数，并说明对效果的影响。

## 8. 交付清单

- 成片 MP4（标注逻辑画布、放大倍数、fps）
- 可编辑工程（代码工程或剪辑工程）或素材包 + 逐帧时间表
- 限制说明：哪些镜头严格网格、哪些 AI 近似、哪些未测试

## 9. 快速模式与实测计时（0.4.0）

可运行模板：`templates/arcade-navy/`（参考画风预设；早期的 minimal 分阶段模板已在 0.5.0 移除）。arcade-navy 的 `render_range.py` 逐帧渲染后直接以 rawvideo 管道送入编码器，不落 PNG；全片且音轨已混好时直接复制音轨。

| 计时（本机实测，来源 `stages.json` 与渲染日志） | 数值 |

| minimal 各阶段：配音 9.3 / 事件表 0.0 / 混音 0.7 / 有声预览 36.2 / 审查素材 1.9 / 1080p 高清 65.1 / 技术校验 7.5 秒 | 合计约 121 秒（阶段耗时之和，不含排队与人工审看） |

提示词只能引导"像素风观感"，不能保证网格、色数或帧数精确；精确要求放到后期或代码渲染。生成图提示词只描述静态；视频提示词按镜头写起止状态、动作与运镜（每段可含所选模型能稳定完成的多个镜头）；剪辑与后期另写。

# 附：确定性渲染规则

目标：任意一帧都能单独、重复地渲染出完全相同的结果，便于逐帧审查、局部重渲染和声画对齐。

### 1. 原则

- **由帧号决定**：`render_frame(frame)`（Python）或 `renderAt(t)`（浏览器，t 由帧号换算）只依赖帧号、事件表和静态资源。
- **任意寻帧一致**：先渲第 300 帧再渲第 10 帧，与顺序渲染结果逐像素相同；禁止依赖上一帧的累积状态（粒子位置用"出生帧 + 种子"解析计算，而不是逐帧积分）。
- **种子随机**：随机数由 `hash(seed, event_id, particle_index, frame)` 得出；禁止 `Math.random()` / 未设种子的 `random`。
- **无墙钟**：不读当前时间、不依赖 requestAnimationFrame 节拍或渲染速度。
- **资源就绪再渲染**：字体、精灵表、色板加载完成后才开始第一帧（浏览器端等待字体加载完成的信号）。
- **像素输出**：在逻辑画布上绘制，最近邻整数放大；关闭图像平滑与文字抗锯齿（或渲染后阈值化到色板）；不启用运动模糊、多重采样或补帧。
- 所有落点读取 `cues.json`（见 cue-sheet-and-audio.md），不在代码里重复写数字。

### 2. 现有 Python 路线（默认，继续使用）

`templates/arcade-navy/` 使用 Python + Pillow + numpy + ffmpeg 渲染。新工作沿用这条路线即可。依赖缺失时优先改用平台上已经可用的路线，不强制安装新环境。

### 3. 建议接口（伪代码，**未在本 Skill 中实现**）

```python
## 建议接口，非已实现代码
def load(cues_path, palette_path, assets_dir) -> Ctx          # 读取事件表、色板、精灵，一次性
def render_frame(ctx, frame: int) -> IndexedImage             # 逻辑画布上的索引色帧，纯函数
def rng(seed: int, *keys) -> float                            # 由键哈希得到 [0,1) 的确定值
def active_events(ctx, frame) -> list[Event]                  # frame ∈ [ev.frame, ev.frame+dur)
def palette_at(ctx, frame) -> LUT                             # 语义色槽 → 当前色板（见 style-and-grid §8）
def upscale(img, k: int) -> RGBImage                          # 最近邻整数放大
def export(ctx, frames: range, out) -> None                   # 逐帧调用 render_frame，交给 ffmpeg
```

### 4. 可选：Canvas / 浏览器适配说明（不是完整渲染器）

需要浏览器渲染（例如复用网页 UI、Web 字体）时：页面暴露 `window.renderAt(t)`，内部 `frame = round(t × fps)` 后执行与上面相同的纯函数；画布关闭 `imageSmoothingEnabled`；用无头浏览器逐帧调用并截图，等字体就绪后开始；截图按帧号命名，再由 ffmpeg 编码。本 Skill 未提供该实现，也未测试；需要时按此说明编写实现。

### 5. 自检

- 抽 3 帧，乱序重渲染，与顺序渲染逐像素比较
- 每帧颜色 ⊆ 色板；放大块单色
- 实际分辨率、帧数、时长用 ffprobe 核对
