# 复古像素风视频

把文字变成像素视觉叙事。默认输入是文案——脚本、歌词或旁白——核心工艺是**文案编导**：把文字拆成语义节拍，为每拍找到合适的场景、隐喻与动作，让它发生一个能读懂的状态变化。像素纪律（清晰像素簇、硬边、受控色板、运动在逻辑网格上）和足以表现结构、材质、表情的分辨率是基础，但清晰的角色、可识别的场景和准确的视觉点子比盲目加像素或噪点更重要。适用于文案配画短片、歌词 MV、旁白叙事、知识讲解、游戏制作支持（场景、tileset、角色动作、UI、玩法演示视频）、产品片与氛围循环。把普通视频加马赛克不是风格，而是失败。

按需读取：
- [references/copy-to-scene.md](references/copy-to-scene.md) — **有文案/歌词/旁白时先读**：语义节拍表、视觉修辞库、动画分层、质量判断顺序
- [references/application-routing.md](references/application-routing.md) — 内容类型 → 视角、画布、色板规模、路线、交付物
- [references/style-and-grid.md](references/style-and-grid.md) — 细节档位、逻辑画布、色板、密度检查、文字层、一致性设定
- [references/motion-and-vfx.md](references/motion-and-vfx.md) — 姿态节奏、冲击、按视角的镜头、局部放大；附特效规格（触发/阶段/方向/寿命/遮挡/颜色/收尾）
- [references/production-routing.md](references/production-routing.md) — AI 近似与严格网格、旁白、后期、预算；附提示词模板（静帧、视频、讲解、游戏资产、剪辑）与确定性渲染规则
- [references/cue-sheet-and-audio.md](references/cue-sheet-and-audio.md) — 画面、字幕、音频共用的唯一事件表 `cues.json`；帧与采样换算；声音分层；同步报告
- [references/visual-review.md](references/visual-review.md) — 关键帧先审、联系表、问题记录格式、审查边界
- [references/style-presets.md](references/style-presets.md) — **用户给美术参考或否定画风时先读**：参考拆看、街机海军蓝预设（颗粒、配色、轮廓、硬切动态语法）、先样片后全片、§4 角色网格手画规则；附参考学习记录与来源借鉴范围
- `palettes/*.json` + `palettes/swatches.png` — 原创色板（50 色与 64 色默认套，另有 12–16 色复古套）
- `examples/` — `copy-driven-bakery.md` + `.storyboard.json` + `.cues.json`（文案 → 5 镜 → 共用事件表，默认流程示例）
- `templates/arcade-navy/` — 唯一可运行模板（320×180 ×6、套件 + 6 个示例场景、区间渲染直接管道编码 MP4），带角色入口：`engine/sprite.py`（网格手画角色）、`engine/cast.py`（读 `cues.json` 的 `cast`）、`characters/_TEMPLATE.py`、`tools/char_sheet.py`（角色姿态小样 + 自查）；示例片的眼镜青年 `draw_zhou` 为 legacy，需显式声明才可调用
- `scripts/check_storyboard.py` — 帧数求和、画布与旁白长度校验；`scripts/check_cues.py` — 事件表校验（id、镜头、整数帧、拟定/实测）；`scripts/check_subtitles.py` — 字幕字形覆盖（中文不会画成空框）；`scripts/render_swatches.py` — 重新生成 `palettes/swatches.png`

## STEP 0: 输入与默认值

**第一步先拿到主题或文案。** 用户没给文案、歌词、旁白或主题时，第一条消息只问这一件事：用大白话，附 2–3 个一句话示例（如"为什么要早睡""猫咪的一天"），并提供"只给主题、由我写文案"的选项；拿到之前不推进其他步骤。缺少**必需素材**时同样提问（真实产品、Logo、人物、品牌或用户自己的游戏 IP 必须由用户提供）。不让用户选画风——用户凭名称分不清画风。直接用下表的默认画风；只有用户提供参考图/视频或明确点名其他画风时才换。用户已给的信息不重复确认。默认值一次性说明：

| 项目 | 默认 |
|---|---|
| 画风 | **街机海军蓝**（`references/style-presets.md` §1、`templates/arcade-navy/`）：近黑海军蓝底、金黄高光、粗描边、硬切；**角色不预设**，按本次文案设计（STEP 3）；其他画风只在用户给参考或明确要求时使用；8/16-bit 低分辨率复古**仅在用户明确要求时**使用 |
| 逻辑画布 | 由画风决定：**街机海军蓝在 320×180 ×6 上绘制**（预设颗粒，`style-presets.md` §1）；其他高细节画风 640×360 ×3 → 1920×1080，细节密集 960×540 ×2；竖版 360×640 / 540×960；方形按用途 |
| 色板 | 32–64 色；复杂场景 64–128 色 |
| 视角 | 按节拍选择（侧面、等距、俯视、剖面、特写、全景、屏幕内外、UI） |
| 节奏 | 24fps 输出，姿态一拍二，冲击一拍一；切镜先服从句意，再对齐实测音频 |
| 时长 | 服从文案、旁白或歌曲；循环 8 秒 |

画布尺寸、色数与帧节奏是**制作建议**，不是任何图像或视频模型的原生参数。

## STEP 1: 文案编导（语义节拍）

按 `references/copy-to-scene.md` 执行。每拍写：原文、含义/情绪、视觉命题、场景与主体、隐喻/直述方式、起始状态→关键动作→结果状态、景别/构图、触发词或音频时间、转场与复用资产。**没有文案、只要展示片/封面/"秀一下画风"时：**先写一个 ≤10 秒、有起承转合的小故事（主角、目标、阻碍、反转、结果），再把它当文案拆拍；测试中没有故事的纯炫技片被否定。每拍必须有能读懂的变化；不能只堆关键词图标、静图配字幕或固定舞台。按语义从修辞库选择，不要所有主题都套游戏 UI。按句意选择连续变形或新场景，复用角色与视觉母题维持连续性。比喻保留原意；科普隐喻不得歪曲真实机制，需核查，不确定时改直述。有音频时按实测时间对齐切点；无音频只标拟定时间。

## STEP 2: 内容路由

按 `references/application-routing.md` 逐拍选视角、画布与路线。侧视可以用；每拍都套横版跑跳才是问题。**精细像素电影感 / 游戏过场，需要真实角色表演、追逐或打斗**（或用户否定了程序拼块人物）时：走路线 A，以已认可的美术方向关键帧作为画风与角色参考，不走代码路线；预算低也如此，改为如实说明付费次数。整张图平移缩放不算动画，不能当作镜头。要做可玩游戏，用户须提出交互目标，交付可运行版本与运行方式；视频不得宣称为可玩游戏。

## STEP 3: 风格圣经与角色表

写简短风格圣经（`references/style-and-grid.md`）：档位、画布、色板、细节规则、轮廓/抖色、光源、字幕与 UI 层，以及每个重复角色、道具、地点的一致性设定。重复角色在各拍保持轮廓、配色与配饰；特写按更大像素尺寸重绘，不放大。细节来自结构、材质、表情和可识别物体，不靠随机噪点或满屏抖色；非单色块比例只证明没有简单放大，不代表美术质量。**角色按本次文案设计，不沿用旧角色。** 画风、动作与渲染能力可以复用，角色身份不自动复用：新主题按文案确定主角（人物、动物、物件均可）与配角；只有用户要求沿用、系列内容需要连续性，或用户提供了角色参考时才继承身份。风格参考里的人物只提供画法（颗粒、轮廓、配色），不能变成固定模板；模板里的眼镜青年 `draw_zhou` 只是 legacy 示例，没有在 `cues.json` 的 `cast` 中声明 `kind: legacy_zhou` 时调用会直接报错，新主题不得静默回落到它。代码路线的角色在实际逻辑网格上逐像素手画（`references/style-presets.md` §4，`engine/sprite.py` + `characters/`），并在 `cast` 中显式声明；比例按角色需要，不强制大头。开工前用 `tools/char_sheet.py` 出一张角色姿态小样，按 §4 自查项检查并修掉问题后，直接推进已授权的制作；只有用户明确要求挑选角色时才暂停等待选择，不另加审批。

**默认人物要好看。** 用户没有给年龄、外形、写实/怪诞要求或角色参考时，人物默认是清爽、讨喜、精致的复古像素角色：发型整洁有设计，轮廓舒展，五官协调，肤色明暗干净；没有年龄设定的日常主题用年轻成年人的中性造型。用户的年龄、外形、风格要求或角色参考优先；美观不等于固定性别或肤色，也不把所有角色都画年轻。检查项见 `references/style-presets.md` §5。

用户提供美术参考或否定画风时，先拆看参考（`references/style-presets.md` §2），再出 1 张方向关键帧或取自正式时间表的 ≤6 秒有声样片，与参考并排对照，之后才做全片。

## STEP 4: 分镜

每镜一行：`序号、起止、时长、景别、语义主动作、角色反应、环境微动、特效、信息层、声音/旁白、参考关联`。动画按优先级：语义主动作 → 角色反应 → 环境微动 → 特效；关键结果留可读停顿。各镜时长以整数帧**严格求和**等于总长，并用 `scripts/check_storyboard.py` 校验 JSON 副本。确认后把分镜转成唯一事件表 `cues.json`（`references/cue-sheet-and-audio.md`），画面、字幕、音频都读它，并用 `scripts/check_cues.py --storyboard` 校验。讲解类列事实核查清单，示意动画注明示意。

## STEP 5: 付费前确认

在一条消息里呈现节拍表、风格圣经、分镜、路线和预计付费生成次数，等待确认。遵循用户预算与权限：不额外加付费候选，不自动重试；失败时报告并提出一个修正方案。

## STEP 6: 制作（按素材类型批量）

依据 `references/production-routing.md`：
- **A · AI 近似像素**：先锁定 1 张已认可的美术方向关键帧（只描述静态），再批量生成视频；关键帧作画风/角色参考，除非镜头确实从这张图开始，否则不作首帧。每段承载一组连续节拍，写清起始状态、动作与结束状态；按所选模型的模型知识拆成它能稳定完成的镜头数（通常每 5 秒 2–3 镜），段与段在动作上硬切。段数少而饱满，角色更一致、成本也更低。提示词**不能保证**网格、色数与帧节奏。
- **B · 严格网格代码渲染**：一次性写清画布、色板、资产、`cues.json`、特效与文字/UI 层的渲染简报，按它编写代码渲染工程；渲染遵循 `references/production-routing.md` 附录的确定性渲染规则（按帧寻址、种子随机、字体就绪、最近邻）。
- **C · 混合**：AI 底板后期网格对齐，同一网格上叠加代码渲染的特效、计数、标签与 UI。
- 旁白：脚本确认后生成语音，按实测时长对齐镜头。
- 像素素材禁止补帧、光流变速、平滑放大或运动模糊。

## STEP 7: 后期与组装

剪辑方案单独写：剪辑表、AI 素材网格对齐、中文与精确文字后期排版（网格像素字体，或声明独立字幕/UI 层并以可读性定字号）、旁白、音乐与选择性音效都从同一 `cues.json` 分层生成。中文字幕必须用带中文字形的字体（模板默认 Hiragino Sans GB 无抗锯齿 + 最近邻放大，英文保留像素字体），按真实 bbox 绘制、无空格中文自动换行、守安全边距；成片前用 `scripts/check_subtitles.py` 查缺字并逐句看实帧（`references/visual-review.md` §6）（`references/cue-sheet-and-audio.md` §4），**旁白优先混音**（`references/cue-sheet-and-audio.md` §6.1，硬性下限）：先把旁白归一并预限幅，再让音乐和音效相对旁白定电平，用旁白驱动的侧链闪避——说话时音乐比旁白低 ≥15 LU、空隙处仍低 ≥6 LU，音效峰值比旁白低 ≥6 dB；不得只对整条混音做一次响度归一来“调平”；实测各分轨与最终 AAC 音轨，任一项不达标不交付；整体响度遵循平台或用户要求（短视频默认 -14 LUFS、真峰值 ≤ -1.0 dBTP），可选 CRT 作为可移除的最后一层。

## STEP 8: 交付

先用关键帧审风格，成片再看联系表、切点/快速动作连续帧和原尺寸关键帧（`references/visual-review.md`）；只在任务需要时修少数高影响问题。视觉审看是交付条件：帧数、时长、色板等技术校验通过不等于画面通过，还要看姿态、材质与语义动作（`references/visual-review.md` §5）。只交付真实存在的成果：视频、可编辑工程、资产表或可运行版本，加 `cues.json`/时间表。说明哪些镜头严格网格或 AI 近似、时间是 `planned` 还是 `measured`（附同步报告）、哪些事实已核查、哪些未测试。
