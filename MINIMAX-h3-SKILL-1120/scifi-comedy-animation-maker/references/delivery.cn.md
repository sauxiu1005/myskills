# 制作准备与作品交付

## 边界

原版 STYLE、DIRECTOR、TECHNIQUE 决定制作内容。不会因为模型会写代码或某工具能导出MP4，就认为具备原风格的画面与表演。模型名称不是质量证明。

原仓库采用代码绘制与逐帧渲染。本 skill 不自动转为图生视频、几何示意片或幻灯片；用户明确选择不同路线时说明与原路线的差异及实际可编辑范围。

## 项目与环境

1. 定位实际 skillRoot 与目标 projectRoot，运行 `scripts/verify_bundle.py` 检查包的55个原文件。`scripts/init_project.py` 复制完整随包快照到新项目 `runtime/`；新作品写在 `film/`。
2. 确认执行环境能读取源码、参考图片、字体和音频，实际查看原风格帧后再制作。只有路径字符串不能证明素材可用。
3. 在实际执行端检查 Node、Python、FFmpeg、浏览器与字体。采用 TECHNIQUE 的依赖版本和项目内安装；没有随包的插件 setup、tools/fetch 或其他风格不能直接调用。项目目录和已验证兜底见 production.cn.md。
4. 原版默认声音工具不可用时，使用可用且获授权的TTS声音或用户录音。仍按每句ID取得独立音频、实测时长和口型数据；若工具输出多句合集，先剪辑和核听每句，再送入原版时间轴。不要把合集直接当一条角色音轨混入。有意静音的作品无需对白驱动口型数据，保留已确认的静音方案。

## 交付与验收

交付最终MP4、封面、适用时的SRT、TREATMENT、CREDITS、源码素材和可重建的 `build.sh`。核对文件可读，且对应已确认版本。

在预期播放器中验证播放、暂停恢复、中段跳转和片尾。源码ZIP标为可编辑源码包，不称在线编辑器；仅提供真实且已验证的工程链接。文件导出、播放检查和视觉验收分别报告。只维护技能时，成片检查记为未执行，不能借旧版本测试声称新版本已通过。应用安装、包导入和上传机制由宿主运行时负责，不作为此创作流程的必要步骤。
