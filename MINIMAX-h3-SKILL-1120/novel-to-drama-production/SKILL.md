# 小说改编与短剧制作

将小说改编到短剧成片的制作流程整合为一个技能。输入可以是小说正文、现有阶段 JSON，也可以是独立角色描述。支持完整流程和单阶段创作、诊断、修改；只要求一个阶段时，不自动扩展为全流程。完整制作请求应持续到实际渲染、视听验收和交付，调用当前可用的生成与剪辑工具。本技能提供流程和校验，不自带在线模型或媒体引擎；缺少能力时如实说明。执行本技能的对话模型不绑定特定厂商或版本。

## STEP 1：确定范围与项目状态

确定目标阶段、已有材料、已确认决策、当前项目和输出位置，复用此前回答。通过可用工具读取相关原文文档与已选画布素材，记录真实资源 ID 和版本。新建改编项目需要题材、总集数、单集时长，不凭书名脑补原文证据。优先使用用户项目目录，项目产物与技能运行文件分开保存。

首次执行先读 `references/integration.md` 与 `references/native-workflow.md`，了解路径映射、阶段交接和原生执行方式。优先使用当前项目、画布、文档、图片／视频生成、声音和剪辑工具，不以本地安装或配置外部生图服务为前提。上游要求 Node.js 18+；本整合包实际测试版本见 `VALIDATION.md`。

## STEP 2：完整加载对应流程

以下七个原始流程是本技能内部资料章节，不需要另装或嵌套调用其他 Skill。完整读取选中模块的 MODULE.md，再按需读取 pass、schema 和模板，然后创建数据。保留创作质量门、证据要求和修复循环。归档中的安装方式、服务配置、工具名称和逐步确认流程不能覆盖原生工作流与用户已有授权。角色出图按 `references/native-workflow.md` 执行，不走归档的 config/gen/confirm 命令。不能只读下面的表格就开始创作。

| 需求 | 完整流程 | 输出子目录 |
| --- | --- | --- |
| 改编大纲、已有大纲体检 | `references/upstream/skills/novel-outline/MODULE.md` | `outline/` |
| 拆角色、人物画像、形象和音色提示词 | `references/upstream/skills/novel-characters/MODULE.md` | `characters/` |
| 场景与叙事道具设定 | `references/upstream/skills/novel-art/MODULE.md` | `art/` |
| 分集剧本、场次、动作与台词节拍 | `references/upstream/skills/novel-script/MODULE.md` | `script/` |
| 开场站位、排座位、走位 | `references/upstream/skills/novel-staging/MODULE.md` | `staging/` |
| 分段、切镜、画面提示词与 H3 投产包 | `references/upstream/skills/novel-storyboard/MODULE.md` | `storyboard/` |
| 实际角色参考图、版本化图册 | `references/upstream/skills/character-refs/MODULE.md` | `character-refs/` |
| 逐镜视频生成、素材审阅与任务恢复 | `references/video-production.md` | `production/`、`video/` |
| 配音、系统内容、剪辑混音、字幕、渲染与成片验收 | `references/post-production.md` | `audio/`、`post/`、`delivery/` |

完整制作顺序：大纲 → 角色／美术／剧本迭代 → 开场站位 → 分镜和必要参考素材 → 逐镜视频 → 配音与系统内容 → 剪辑、混音、字幕 → 渲染 → 视听验收 → 画布交付。完整制作授权内实际生成或复用必要参考图；角色图也可以独立开始。用户已有兼容 JSON 时从相应阶段接续，不强制重做上游。

## STEP 3：执行与明确交接

有脚本运行环境时使用原始确定性 seed、merge、assemble 工具，不手工重算已有字段。无脚本环境时按 schema 交付阶段文稿与 JSON，人工复核证据、ID、覆盖与时长，并将自动校验明确标为未执行。角色、场景、道具 ID 跨阶段保持一致。校验时传入已有上游文件；因材料不足而跳过的检查必须说明。

- 大纲：保留原文证据；先确认结构取舍，再展开分集。梗概每批不超过 10 集。
- 角色：即使有大纲预填，也保留原文扫描和逐字引文检查。复核归并候选，用配套工具合成角色卡。
- 美术：保留可画锚点、实际需要的光照状态、尺度参照、无人场景和无手道具提示词。上游美术模块产出提示词；完整成片流程通过原生工作流实际生成或复用必要图片。
- 剧本：默认每批不超过 3 集，使用结构化节拍和计算时长，将写戏与机位设计分开。
- 站位：必须有 script.json。有场景图就实际认图，没有则标记推算草稿。报告导出的修改数据需要重新校验。用 blocking 命令生成走位句，逐字复制到分镜对应场景第一段；当前没有自动读取 staging.json 的功能。
- 分镜：validate/render 必须提供 script.json，保留节拍覆盖、时长和协议检查。分镜图提示词不等于已经出图。可选镜头配方门需要用户提供卡库目录，否则明确跳过。
- 角色图：区分用户陈述、推断与默认字段，结合已有授权复核输入与锚点。使用原生生图工具的真实结果和项目素材引用，原生版本记录与归档 CLI 的 asset.json 分开保存。派生图都参考同一张审核选定的正面全身锚点，面部细节按模块规则补充参考。保留版本与过期标记。只要提示词时不启动出图。

用户已经确认的决策和生成范围不重复询问；只补充尚缺的必需输入与重要创意决策。运行时检查当前可用的生成能力，不把归档文档中的模型名、速度、价格、额度或适配器当作当前保证。无法出图时交付准备好的输入并说明缺少什么，不声称图片已经完成。

## 图片默认设置与提示词质量

用户要求实际生图或图片编辑时，默认使用 **GPT Image 2、1K**，已有明确指定时遵从用户。适用于角色参考图及已授权生成的场景、道具和分镜图。准备图片提示词或修订画面质感前读取 `references/image-prompting.md`。通过当前工具核实准确模型标识及1K对应参数；GPT Image 2.5不能视为同一选择。模型、清晰度档位、质量选项和画幅分别设置，记录返回的原生尺寸，不把1K一律写成1024×1024。模型或档位不可用时说明限制并取得替代选择，不静默切换。

仅要求修改技能默认值或提示词规范时，只修改技能文件，不自动试生成、重做项目素材或继续项目制作；用户同时要求实际出图时才执行。

写实画面用材质差异、局部干湿、实际光源和克制的后期描述控制质感，不把写实规则强加给风格化项目。质感编辑保持人物身份、服装材质与场景几何，通过工具实际绑定参考。用户要求实际图片修订时，先查看代表图效果，再推广同一处理；保留旧版本并标记受影响的下游依赖，图片更新不等于既有视频自动更新。

## 后续视频生成的模型与清晰度

视频生成优先使用 **MiniMax H3**，因为短剧镜头需要参考人物的一致性、连续动作与原生对白。用户明确选择且满足已确认要求时优先遵从；制作前核实参考和声音能力。H3 不可用时选择具备同等能力的模型，输出会明显变化时先说明差异并取得决定。生成失败后在已授权预算内针对原因修正并重试一次，随后换用兼容的可用模型，不反复重复同一失败。

随包上游文档和脚本保留可选适配器以供复现，不构成模型推荐。只有用户明确要求对应模型时才展示或使用其他模型专属导出；默认投产包使用 H3，归档模块仅按需读取相关创作方法与质量校验部分。

每个新项目首次提交视频生成任务前，必须询问用户需要的**视频清晰度**，选项来自当前模型真实可用档位。收到明确答案后再生成；用户已在本项目指定过清晰度时直接沿用，不重复询问。等待答复期间可继续剧本、资产整理与分镜，不提交视频生成。图片清晰度、画幅和成片容器尺寸不能代替视频清晰度选择。选定模型或清晰度不可用时说明限制并询问替代，不擅自换模型或降档。实际生成尺寸、导出尺寸与后期放大分别记录。

## STEP 4：逐镜视频与成片后期

完整成片任务先完整读取 `references/video-production.md` 和 `references/post-production.md`。复用已选合格片段，记录实际任务ID、参考版本、输出尺寸和测得时长。任务等待中先恢复与查询，不能重复提交。审阅真实视频的人物、站位、道具动作与声音，在已有授权内有限、定向修复。

维护锁定且完整的画内对白、旁白、内心独白和系统台词清单。合格原声直接保留，缺失的独白／系统声音独立配音，避免同台词重复叠加。系统内容和人物反应在剧本／分镜阶段规划，后期用可编辑图层生成准确面板文字；实际查看其与脸、手、道具、字幕的遮挡关系。无系统剧情不添加系统UI。

原生剪辑能力足够时优先使用，否则调用实际可用的代码／媒体工具。保存可编辑时间线或重建文件，按可用素材分轨混音，同步核对后的字幕，先审代表小样再渲染全片。遵守用户片长和导出规格，按后期章节执行安全渲染、实际文件探测、完整解码与视听验收。提交任务、拼好提示词、未渲染时间线和未审阅导出都不能称为成片完成。

跨工具交接使用 `references/post-manifest.md` 与 `scripts/check-timeline.py`。该脚本检查时间线记录和必需台词覆盖，不代替媒体内容、口型或听辨验收；未执行检查明确记录。用户只要求单阶段或修改技能时仍按该范围结束。

## STEP 5：校验、修复与交付

执行模块校验，逐项修复并重跑相关检查。修改上游后，重新校验受影响的下游。无法解决的失败应如实解释，不静默修改时长目标或跳过质量门。修改用户素材时保留原稿。

统一命令入口原样转发原始 CLI 参数，不改变其含义：

```bash
node <skill-root>/scripts/drama.mjs list
node <skill-root>/scripts/drama.mjs novel-outline validate <outline.json>
node <skill-root>/scripts/drama.mjs novel-staging blocking <staging.json>
node <skill-root>/scripts/drama.mjs report --from <project-dir> --out <project-dir>/report.html
node <skill-root>/scripts/drama.mjs selftest
node <skill-root>/scripts/verify.mjs
```

具体参数以各模块文档为准，不假定所有命令支持同样参数。在项目输出目录执行项目命令，使相对图片路径与分镜质量门日志定位正确。

将阶段 JSON 和可读文稿保存到当前项目。成片任务另交付实际可播放视频、字幕、可编辑工程或重建文件、可取得的分轨声音、选用素材清单、后期报告与成片验收报告；后两份报告分别可点击，最终视频也须实际打开核验。**所有已生成的可读报告默认以标题明确、可点击的报告／文档卡片放到画布，按阶段归类并设置醒目的报告总览入口。** 这是阶段交付的一部分，不等到成片结束或用户追问；只保存在磁盘或聊天中列出路径不算画布交付。按 `references/native-workflow.md` 执行分类与链接核验。只展示本次任务实际产出的阶段，不为了凑齐目录扩展任务。即使已有综合报告，角色报告与站位报告也要保留独立入口；角色图片不能替代角色报告。核实真实节点／资源 ID，并逐个打开报告入口后再声明可查看。交付各阶段 JSON 和可读报告。脚本与文件交付可用时，站位以交互 HTML 为主交付；否则交付可编辑站位文稿，并说明交互功能不可用。报告合成器只组合大纲、角色、美术、剧本、分镜，站位和角色图册另外提供链接。分镜段目录与分镜报告同级，或显式指定图片路径。如实报告未过质量门、缺失图片和跳过项。默认报告界面中文，遵守各模块语言规则，区分界面语言和提示词／台词语言。

保留全部上游受版本控制的文件内容与 Apache-2.0 署名。来源和 SHA-256 见 `references/source-manifest.json`。只有根目录是技能入口；原始七份技能文件仅改名为 MODULE.md，字节内容没有修改。
