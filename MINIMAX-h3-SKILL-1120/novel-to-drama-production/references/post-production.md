# 后期、声音、系统内容与成片交付

用户要求完整短剧或成片时，本章是必经流程。已有视频可从此进入，复用合格素材；仅修改技能时不执行项目制作。本章指导调用当前可用的剪辑、配音、合成与文件工具，不假定随包包含生成模型、FFmpeg 可执行程序或已经可用的在线服务。

## 1. 后期方案与时间线

读取选用素材清单和锁定剧本，核对画幅、时长范围、语言、清晰度、字幕要求、原声与另配声音。沿用用户决定；没有硬性时长时记录合理目标，已有硬性范围则不得静默加长。原生剪辑工具可提供所需轨道与导出能力时优先使用；否则使用实际安装的 FFmpeg／代码合成。不要预设不存在的编辑 API。外部服务缺失时说明具体依赖，不伪造成片完成。

使用实际测得的素材时长建立粗剪，按剧情因果、眼神和动作接点取舍。把对白、系统和内心独白的时间从一开始留进时间线。统一帧率、像素比例、旋转元信息、色彩及采样率；不凭扩展名推断。画幅变化先规划构图与字幕安全区，禁止无意拉伸。慢动作仅在合适的非对白镜头使用，检查插帧变形；不能用整体减速损坏对白／口型来凑时长。

保存可编辑时间线：原生工程，或能重建剪辑的 JSON、脚本、字幕、面板素材和字体说明。每个引用指向确定的媒体版本；保留原文件，不在原素材上破坏性覆盖。需要跨工具交接时使用 [后期清单约定](post-manifest.md) 并运行随包时间线检查。该检查仅验证记录一致性，不替代媒体审阅。

## 2. 声音逐句落地

制作独立的“声音覆盖表”，从锁定剧本复制全部必需 cue ID 与准确文本，再逐一映射到时间线。至少区分：

| 类别 | 制作和核验 |
| --- | --- |
| 画内对白 | 已有合格原声直接使用；逐句核对人、词、口型、起止，避免再叠一份同台词 |
| 旁白／内心独白 | 为指定角色生成稳定音色的独立音频；按实际音长安排停顿，避免与重要对白互盖 |
| 系统声音 | 独立非画内声音轨，明确音色、语速和情绪；不是一律机器人音，也不是让角色嘴动代说 |
| 音效／环境声 | 与动作时间对齐，保持跨镜环境连续；控制新增脚步、呼吸等不必要声响 |
| 配乐 | 使用用户提供或可合法使用的音源；保留来源与许可说明，按对白闪避并处理进出点 |

系统类剧情同时确定“语音／面板／二者”以及主角可见、观众可见、主角反应时间。原文重要的任务、奖励、惩罚、数值与因果信息不得遗漏；剧本有意删改则在改编记录交代。无系统内容的故事不强行添加。系统台词通常在后期独立配音，但其内容、时间与反应必须在剧本和分镜中已经安排。

长句按语义分段配音，使用实际音频时长回填，不通过截断尾字挤入空档。漏句优先补音与调整留白；需要改剧情、超出硬性时长或删除关键句时提出具体取舍。ASR仅辅助定位；专名、数字和容易混淆的台词按剧本听辨复核。完整覆盖表须列出每条 cue 的实际声音来源、时间码、已听辨／待核验状态。不能仅凭音频文件存在标为通过。

## 3. 字幕与系统面板

字幕来自最终核对台词，按实际发声时间制作 SRT／ASS 或原生字幕轨。选择支持项目语言的字体，检查缺字、换行、字号、边距和对比；内心独白、系统与对白可用克制的样式区分。提供独立字幕文件；是否烧录遵从用户要求并记录。自动识别结果不是最终字幕。

面板文字、数字、计时和图标优先使用可编辑后期图层／SVG／HTML绘制，避免把必读信息交给生成模型画字。面板内容与 cue ID 对应，展示时长足够阅读；进出动画不能遮住关键反应。风格服从世界观和用户要求，不把某项目的固定色彩、姓名或UI套到全部故事。

逐镜选择安全位置，避开人物脸、手、关键道具、运动路径及字幕区；不能把全片面板固定右上角后假定安全。检查开始、中间、结束和切镜前后实际合成帧，必要时缩小、移位或改成独立插入镜头。记录面板时段、位置、文字版本和实际遮挡检查结论。视频参考图上的标注不要误烧进成片。

## 4. 混音与小样

原生对白、系统、内心独白／旁白、音乐和音效保持独立轨道或可重建分组。检查原生素材是否已有音乐和音效，避免叠加两套配乐；无法分离时用实际分离能力或定向重制，不谎称已取得纯对白。

统一采样率，处理底噪、跨段音色和响度突变，给音乐留对白闪避空间，避免削波。平台无指定时可用立体声约 -16 LUFS、真峰值不高于 -1.5 dBTP 作为起点，实际目标需适合内容／发行规格并经过测量，不能用固定增益宣称达标。导出后再测量，不以源轨分析替代成片分析。

先渲染代表性的小样，至少包含画内对白、系统／独白（若有）、字幕、面板和一个切镜；实际看片听音后修正。用户未要求人工审批则自主审阅并继续全片；不要增加固定确认关卡。若用户要求先看小样，按要求等待其选择。

## 5. 稳定渲染

导出规格记录容器、编码、尺寸、帧率、音频及字幕方式。常用交付可选 MP4/H.264/AAC；实际由用户和目标端决定。记录原生生成分辨率与导出／放大分辨率，不能把低分素材放大宣称为原生高清。

原生工具保存工程并取回真实导出资源。代码分支须先发现 ffmpeg／ffprobe 路径与可用编码器，生成项目专属重建脚本，不把示例命令当已执行。实现时遵守：

- 明确有限输出时长；循环背景／音频必须显式裁到片长，不能只靠输入结束碰运气。
- FFmpeg 使用 `-nostdin`，进程设超时；输出与错误日志写入本项目，检查返回码。滤镜图只保留实际使用的流，避免未消费的分支阻塞。
- 同一导出任务使用单写者锁，记录任务 ID 和拥有的进程。取消只终止本任务进程组；禁止宽泛 `pkill ffmpeg` 等误停其他项目。
- 写入同目录唯一临时文件（保留正确媒体扩展名或明确格式）；探测、完整解码检查成功后才原子替换正式文件。中断和失败不得覆盖旧的合格成片，清理时仅处理本任务临时文件。
- 读取真实 ffprobe 元信息，检查音视频轨、片长、尺寸、帧率和预期一致；完整解码以捕获尾部损坏，随后实际看片听音。示例探测是 `ffprobe -v error -show_format -show_streams -of json <file>`；完整解码可用 `ffmpeg -nostdin -v error -i <file> -f null -`，替换为实际路径并检查退出码。

## 6. 成片验收

先跑可用的自动检查，再完整观看并听完实际导出的视频，重点回看切点、字幕和面板出现区。能看图但不能播放声音时将听辨标为未执行，不能宣称完整验收。将以下结果记录到独立可读的成片验收报告：

1. **剧情覆盖**：场次、关键动作、所有必需对白／旁白／内心／系统 cue 都有对应；没有首尾截字、漏句、误配说话人或非预期抢话。
2. **视觉连续性**：人物身份与造型一致，视线轴线、方向、道具与动作接点成立；无无法接受的黑帧、冻结、形变和穿帮。
3. **字幕与界面**：专名、数字与台词准确，安全区和可读性通过；面板不挡脸、关键动作与字幕，不在切镜后错误残留。
4. **声音**：口型与对白同步，音色与音量稳定，无重复对白、意外静音、爆音、截尾；尾声淡出完整，旁白和音乐关系清楚。
5. **技术**：真实尺寸／帧率／编码／片长与导出要求一致，音视频结束合理对齐，全文件可解码；硬性时长无超界。
6. **交付**：选用版本、工程、素材依赖和报告匹配；上传后实际打开播放，检查拿到的是已验收文件，可用时核对哈希。

检查状态使用 pass／fail／not-run，附时间码、依据或检查工具输出位置。失败定向修复后只重跑受影响检查，修订导出后重新检查整体可解码性、规格和受影响段落。自动表格通过不等于人物审美、口型或听觉通过；未执行项明确列出。

## 7. 画布与最终交付

默认交付：可播放的成片、字幕、可编辑工程或重建脚本／清单、实际可分离的声音轨、媒体版本清单、后期报告与成片验收报告。只有混合音轨时如实说明，不能制造“独立原声轨”空文件。引用素材与依赖按工具允许方式随工程保留，凭证和本机隐私信息不得打入分享包。

在现有画布增加“视频素材”“声音与字幕”“成片”分组，把最终视频置于醒目的成片卡；报告按 [原生工作流](native-workflow.md) 加入索引，后期报告和成片验收报告分别可点击。卡片展示集号、版本、实际时长、尺寸及验收状态；旧版本明确标注，测试片和小样不能冒充最终片。逐一打开最终视频和报告入口，记录实际资源／节点 ID 与状态。

只有实际导出、关键检查通过且完成约定交付后才称“成片已完成”。有未通过或未执行检查时标注“待验收版本”及具体限制；缺少渲染工具或视频仍在生成时，只报告对应阶段完成。最终回复给出可播放成片／真实文件链接和可编辑材料入口，概括实际规格及遗留问题，不只交提示词或素材列表。
