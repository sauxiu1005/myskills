## 阶段交接

| 阶段 | 输入 | 关键输出／约束 |
| --- | --- | --- |
| outline | 正文、题材、集数、时长 | outline.json；大纲骨架取舍确认；14 道质量门 |
| characters | 正文，可选 outline.json | cast.json；原文逐字引文、归并、画像、英文形象和音色提示词 |
| art | 大纲／设定，可选 cast.json | art.json；场景和叙事道具；10 道质量门 |
| script | 通常 outline.json，可选 art/cast | script.json；节拍、对白、时长；10 道质量门 |
| staging | 必需 script.json，建议 art/outline/场景图 | staging.json + 可拖动 HTML + blocking 句；8 道质量门 |
| storyboard | 必需 script.json，可选 outline/cast/art | storyboard.json + 报告 + H3 投产包；其他模型专属导出仅在用户明确要求对应模型时启用；18 道门中镜头配方门可选 |
| character-refs | 角色描述／确认的设定、生成能力 | 原生版本记录 + 实际图片 + 图册；锚点、版本、过期标记；归档 CLI 另用 asset.json |
| video | 分镜、选用参考素材、真实生成工具 | 实际视频、任务与版本账本、媒体审阅；见 video-production.md |
| post | 选用视频、锁定台词与系统内容、后期能力 | 可编辑时间线、声音、字幕、面板、后期报告；见 post-production.md |
| delivery | 实际渲染结果及验收证据 | 可播放成片、工程／重建文件、验收报告和真实画布入口 |

上游 ID 不重编号。人物／场景／道具合并后，先修订源数据，再校验受影响阶段。JSON 不是假定兼容的：先核对对应 schema。上游缺失时按模块明确允许的直入流程处理，不能假称跨阶段检查已经完成。

站位 → 分镜是显式桥接：运行 blocking，按集号和场号把每场句子逐字交给第一段 blocking；后续段承接前段段末。报告内拖动后的数据需导出、保存并重新校验，浏览器中的临时状态不会自动回写项目 JSON。

## 已发现的上游差异

- README 的部分文字仍称多个阶段会出设定图／分镜图；当前各 MODULE.md 与脚本显示，实际图片生成由 character-refs 承担，其余对应阶段交付提示词并支持嵌入已有图片。
- 部分旧表格说单镜头上限 15 秒，但当前 storyboard 是段上限默认 15 秒、段内切镜默认 2–5 秒。按当前参数和校验器执行。
- 报告合成器只支持五个面板，不包含站位报告与角色图册；分别交付，不声称七个都已合入同页。
- shot-recipes 不是本仓库的第八个技能，也没有附带卡库。已有可选接口完整保留，用户没有卡库时明确跳过该门。
- 上游价格、额度、耗时和模型可用性是历史信息；实际生成前按当前环境核实，不能据此承诺。保留适配器不等于验证真实服务可用。

## 当前环境适配

执行细则见 [原生工作流](native-workflow.md)。文档、素材与图册保存到当前项目，画布展示按阶段组织。优先调用实际可用的文档、素材读取、图片／视频生成、声音、剪辑与导出工具；不照搬归档中的本地技能安装、CLI 嵌套代理、ComfyUI、外部 API 和 config.local.json 初次设置。

Node.js 18+ 可用时，确定性脚本无需 npm 安装。归档中的子代理流程不是运行前提；可以串行执行并保留相同中间文件与质量要求。无脚本环境时保存符合 schema 的 JSON 与文稿，区分人工审阅和未执行的自动校验。

原生角色图片使用 `character-refs/native-character-assets.json` 记录实际资源、锚点、版本与依赖，不伪造上游 CLI 的 PNG 标识、确认状态或视图结构。此记录由原生工作流管理，不传给上游 check/render；图册由当前文档或画布工具呈现。只有用户明确要求且具备对应运行环境时，才启用归档的外部服务适配器。

新增视频与后期章节负责把原始七阶段接续到成片，并非改写上游模块或假定上游自带渲染器。跨工具后期清单采用独立 drama-post/v1 格式，由 scripts/check-timeline.py 检查记录一致性；实际媒体与视听验收仍按后期章节执行。原五面板合成器不包含后期和成片验收报告，需另建可读报告并加入画布索引。

历史模型名、价格、耗时和额度都不是当前可用性保证。用户已选模型、画风和授权范围直接沿用。缺少必要能力时继续可完成部分，交付真实文稿与素材，并说明未完成项，不以原生工作流名义宣称完成了真实服务联调。

## 输出与恢复

项目中使用 outline/、characters/、art/、script/、staging/、storyboard/、character-refs/、production/、video/、audio/、post/、delivery/ 子目录。文件环境使用这些子目录；仅有项目文档工具时使用同名分组并记录真实文档／资源 ID。每阶段保留原始输入、工作 JSON、报告、校验结果；可读报告默认按原生工作流归入画布“制作报告”分组，提供报告总览和独立可点击入口。文件生成与画布交付分别核实，角色报告、站位报告不能只留在项目目录。已通过且上游未变的部分可以续跑，不重新全部生成。不要把人物／场景文件写入安装目录。

中英根入口语义一致；七份原始模块以其原始语言完整保存，没有用摘要或翻译替换。保留的 docs 中规划稿和迁移记录是历史资料，不自动执行其计划。
