# Design 平台适配

## 技能包与导入

完整 ZIP 只有一个 `match-cut-product-ads/` 根目录，包含 SKILL.md（英文/默认运行时）、SKILL.cn.md（中文运行时，结构与 SKILL.md 对齐）、meta.yaml、references、scripts、assets、examples 和 LICENSE。不含其他宿主的代理配置。`meta.yaml` 按 Design 技能元数据约定填写，字段是否被接受以当前导入器为准。单独复制 SKILL.md 会缺失后期工具。

只有用户要求安装到 Design 时才操作正式“我的 Skill / 本地创建 / 更新 Skill 包”等当前可见入口，核对名称和版本。制作 ZIP 不等于平台已导入；不猜私有 API 或修改平台数据库。

## 发现当前能力

实际制作先从当前能力说明或正式文档读取能力，使用 Design 提供的正式能力完成生成、导入和画布编辑；不通过模拟界面点击或私有接口绕过。将真实来源、时间、环境、目标项目、模型与操作写入 `capabilities.json`；未查明字段用 null/unknown。

| 环节 | 核实内容 | 缺能力时 |
|---|---|---|
| 项目/画布 | 目标项目、导入资源、创建/更新节点、播放入口 | 完成文件并明确待导入 |
| 图片 | 实际模型 ID、参考图、编辑、清晰度、原生宽高 | 复用已有图或提供提示词 |
| 视频 | 实际模型 ID、首帧/尾帧/参考支持、合法时长、比例、分辨率、音轨 | 提出满足需求的可用路线 |
| 声音 | 音乐、配音、音效的实际入口、语言、输出、费用 | 用户素材或明确替代 |
| 任务 | 提交、查询、下载、失败、取消、实际费用 | 记录任务状态与恢复点 |
| 文件 | 本地/云端运行环境、上传下载、真实 URL/资产 ID | 不将本地路径当云端引用 |
| 剪辑 | 时间线、帧级裁剪、多轨、文字、混音、导出规格 | 使用随包后期脚本 |

能力足够时继续执行，不要求用户手动代办工具能完成的步骤。没有连接时仍可策划，不能宣称获得实时模型列表或报价。此包不固定任何 Design 模型 ID 或 SDK 名称。

## 文件与任务记录

`project.json`、`capabilities.json`、`task-map.json` 是本技能记录格式，不是平台 API。复制 `assets/` 对应模板后按实际项目填写。

每项资产记录 logical_id、type、task_id、actual_model_id、prompt、input_assets、requested_parameters、source_size、output_path、asset_id、node_id、version、status、selected_range、cost。不得伪造 ID/链接；本地路径、云端地址、素材 ID 分开保存。

状态区分 planned / submitted / succeeded / selected / verified / failed。成功返回不代表画面合格。未知状态先查询；接口真实支持幂等参数才使用。一次有针对性的生成重试仍失败时保留合格素材和诊断，不无限重投。

## 原生剪辑与代码路线

原生路线：按真实源帧率设置入出点，把镜头映射到统一时间线 → 检查相邻切点 → 对齐构图/曝光 → 添加准确字幕、Logo 与片尾 → 配乐拍点和动作拟音 → 配音闪避/混音 → 按目标规格导出。原生时间线不支持必需的帧级控制时改用代码路线，不能声称已经达到无法测量的精度。

代码路线：按 `setup.md` 检查运行环境，取得实际可用的本地素材，按 `post.md` 渲染。云端生成结果需通过正式下载入口保存；本地输出需上传后才能成为平台资源。不要假定两个运行环境共享文件系统。

源视频带音乐或旁白时先决定保留哪个音轨，再混音，防止重复叠加。静帧预演、原生编辑工程和已合成视频分别标明。

## 画布交付

1. 检查导出视频解码、尺寸、总帧数、时长及声音。
2. 通过正式上传/导入入口取得真实资源，将成片放到指定项目画布，节点名称包含片名和版本。资源库有文件不等于画布上有节点。
3. 等待实际完成状态，在目标节点验证画面随时间推进和播放时长；可听审时检查声音。只见缩略图不能记为播放通过。
4. 若直接视频节点不工作且原生剪辑支持导出到画布，可复用成片在时间线 0 秒原速放置后导出，避免重复音乐。有明确原因时最多两次导入/播放恢复，持续失败交付本地文件及具体阻塞，不重新生成视频来修复上传问题。
5. 记录实际项目/资源/节点入口，提供配置和可交付素材包。原生可编辑时间线确实存在时才称“原生可编辑工程”；单个 MP4 节点不具备该含义，不为获得链接擅自公开发布。

`qa` 使用 passed / failed / pending / not_applicable。未实测模型、费用、画布或声音的项目保留未验证状态，离线包校验不能替代线上验证。


## Design 实战规则

以下规则来自本技能在 Design 上的实际交付修订，适用于每个项目：

- **版本与节点**：每次交付新建一个成片节点，名称含片名与版本（如「片名 vN — 修改要点」）；旧版本的节点、资源、`output/vN/` 和外部副本全部保留，不用新版本覆盖。检查图可放进同一节点或单独的 QA 节点。
- **单文件上限**：画布导入有单文件大小上限（实测 512 MiB）。ProRes 母版和大中间件留在本地/外部副本，画布放同内容的 H.264 预览，并在记录中写明“母版在本地”。
- **ID 回写**：导入后把真实资源 ID、版本 ID、节点 ID 写回 `montage.json`、`task-map.json`，再同步到用户指定的外部目录，并确认副本与项目内文件一致。不得编造 ID。
- **代码合成如实记录**：抠像旋转、背景滚动、产品动效、文字与混音等由代码完成的镜头记录为“代码合成”，不冒充模型新生成；没有付费生成时写明新增消耗为 0。复用旧任务的素材（含已弃用镜头的声音）要注明来源。
- **定向修改**：用户只要求改某一段时，只重做该段及受影响的后期；其余帧沿用原时间线，并用与上一版的逐帧差值证明未改（仅有重新编码噪声）。原音轨可无损复用，用流 MD5 一致来证明。用户说明不需要整片复审时，只检查修改段、切点、边界和规格，不重复整套 QA。
- **检查替代路线**：画布看图/看片服务可能间歇失败。失败时改用本地数值检查——帧差曲线、列/行中值阶跃（接缝）、主体边缘内外环带亮度（光晕/发毛）、轮廓偏差、位姿日志——并在记录中写明哪些项没有经过看图确认。不要因为服务失败就跳过检查或声称已目视通过。
- **精确规格**：视频按帧数截断，音频按采样数补齐/截断后再封装，导出后用实测帧数、`duration_ts` 与完整解码确认容器、视频、音频时长一致。图层叠加（文字等）的输入时长要长于成片，否则会少最后一帧。
- **响度**：两遍响度规范化的第二遍应为线性模式；若因真峰值目标无法满足而退回动态模式，先降低限制器阈值再重做。
- **听审**：没有实际听过的配乐与混音，在记录和节点属性中写“尚未人工听审”。
