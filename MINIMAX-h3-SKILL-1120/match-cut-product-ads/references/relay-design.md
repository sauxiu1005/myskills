# 产品体验、手势与视觉元素接力

在写分镜时使用；代表镜头生成后和成片审查时回看实际结果。目标是让观众从动作联系理解产品价值，而不只看到相似形状。使用 [relay-plan.json](../assets/relay-plan.json) 记录关键接力对；它是 Agent 维护的制作记录，不是模型 API，也不由现有后期脚本自动解析。

## 1. 从卖点建立动作联系

先用一句话写产品带来的体验，再找到能表达这种体验的现实动作。每组接力记录：

`现实动作 → 对应的产品操作或体验 → 共同手势/形状 → 画面可见的结果 → 与核心卖点的关系`

例：翻找纸质照片 → 在产品支持的输入方式下浏览照片 → 横向移动与矩形排列 → 找到目标照片。手势和形状可跨场景呼应，操作方式必须符合真实产品；若产品只能通过触控板操作，就不要为了手势相似画成手指触屏。纯形态展示可以记录材质或形态价值，不必硬造功能故事。

把产品事实、创意隐喻、概念设定分开写。功能事实引用官方来源或用户提供的资料；未核实的功能标为待确认。灯光、图形、超现实视觉可以表达感受，但不能据此断言产品硬件具有对应功能。无法说清接力如何服务卖点时，先换动作/场景或减少一组，不增加无关道具凑形状。

## 2. 明确观众跟随的运动点

每组指定一个主要锚点：指尖、笔尖、物体接触点、铰链或形状中心。再记录必要的次要锚点，例如产品边缘。无手镜头不强行添加手。

在计划中记录切出和切入两侧：

- 锚点位置：`[x%, y%]`，统一以各自成片画布左上角为原点。
- 主体尺度：以画面高度百分比表示；手势形状、可见手掌面、入画方向、接触对象。
- 动作阶段：接近、首次接触、施力、滑动、释放或静止；注明实际因果，不把悬空指尖当触碰。
- 方向与速度：以画面坐标描述位移，速度可用每秒画宽/画高百分比比较；有摄影机运动时同时记录锚点在画面中的最终轨迹。
- 接力方式：运动延续或双方静止；若有意换手/换人物，保持观众跟随的轨迹可读，不强制跨世界使用同一只手。

主锚点优先于整个物体中心。指尖是接力中心时，不能为了对齐物体中心反而把指尖移出匹配位置。用现有约 3% 画宽的位置、5% 尺度和约 25% 速度差作为诊断参考，结合正常速度观看判断；这些数字不是自动合格证明。

生成后检查**实际采用的切出帧和切入帧**，并查看两侧各至少 2–3 帧的运动趋势。记录源素材 ID、源帧率、切点帧号/时间码和检查图。只有静帧时速度写未验证；不能由提示词推定动态结果。对齐手势后重查产品、光照和背景裁切是否仍合理。

尾帧衍生下一镜首帧、共享母构图编辑、分别生成后选帧，都可按真实能力选用。记录实际使用的方法和依赖资产；成片看起来流畅不能证明它用了哪种生成方法。一个切点失败时先诊断采用区间、位置、速度、接触阶段，再决定重剪或有针对性重生成。

## 3. 选择一个反复出现的视觉元素

适合时选一条亮线、一个圆形、铰链、弧线或色块作为贯穿元素。写明它表达什么、每次出现保留什么、变化什么，以及最后怎样回到产品。避免把某个案例的亮线、黑底或光效固定成所有产品的风格。

例如同一条弧线可以先表现材质轮廓，再表现动作轨迹，最后落在产品自身曲面。每次重复应增加意义或视觉变化；只有重复背景而没有推进时，减少次数。视觉元素不能遮住产品关键结构或迫使现实场景加入不合理道具。

## 4. 给观众识别与阅读的时间

按内容安排“建立联系 → 动作接力 → 体验细节/短文案 → 产品展示 → 品牌片尾”，这是可调整的节奏骨架。接力片段可以快，复杂动作需更久，重要文案和产品主镜头需留可读时间。

卡拍不等于每镜一样长。先在粗剪中验证每个物体与动作能否被理解，再安排音乐重音、疏密和停顿。运动接力避免意外停顿；有意的产品展示、静止匹配和片尾停留可以成立，不把“每镜必须一直动”应用到所有镜头。节奏变化应有内容原因，不靠黑场或任意加速填时长。

## 5. 简短输入，内部补全制作记录

用户给产品图/链接、产品名称和一个卖点即可开始。先读取已有材料、检索必要事实，形成可审阅方案；只有影响下一步的关键缺口才补问。受众、文案、视觉元素、手势参数、时间码与技术配置由 Agent 提出或维护，合理假设写入方案，不让用户填写制作表。
