# 匹配转场产品广告 · Match-Cut Product Ads

视频优先使用 MiniMax H3，以支持参考产品连续性与连贯动作；用户明确指定且满足要求时优先遵从。先核实可用性，不可用或针对失败修正一次后仍失败时，在已有授权内使用同等能力模型，明显改变确认结果前先取得决定。

让同一形状或动作跨场景继续，把现实动作与产品体验联系起来，在音乐节拍上切换世界，最后落到产品主镜头和品牌片尾。基于 [Sac-Y/match-cut](https://github.com/Sac-Y/match-cut)，保留其匹配剪辑方法、模板、案例与后期代码，生成和交付使用 Design；来源和适配范围见 [provenance.md](references/provenance.md)。

## 使用范围与默认值

- 先区分用户要完整成片、已有素材后期，还是仅研究、脚本、分镜或提示词；只执行所需阶段。创建/维护此技能不启动媒体生成、安装依赖或连接账户。
- 沿用用户已有产品、模型、时长、画幅、语言和授权。未指定时以 20 秒、16:9、1920×1080、25 fps、150 BPM 起稿；文案默认沿用用户语言。模板中的英文与 27 镜只是示例。
- 每个项目独立文件夹，保存 `plan.md`、`montage.json`、`task-map.json`、素材和 `output/vN/`。技术配置由 Agent 维护。
- 图片、视频、音乐、配音、音效优先采用 Design 当前可用能力；实际制作先读 [design-adapter.md](references/design-adapter.md)，查明模型与操作并记录到 `capabilities.json`。缺能力时复用已有素材、改用代码合成或说明具体替代，不擅自切换到外部平台。
- 模型名、最低时长、参考图角色、费用与套餐额度均以当次能力说明/账户返回为准。上游案例的型号与历史费用只作案例背景，不代表 Design 当前能力或消费授权。
- 每个版本在画布新建独立成片节点，旧版本的节点、资源和本地文件全部保留；画布导入、单文件大小、ID 回写、代码合成记录、定向修改范围和检查替代路线遵循 [design-adapter.md](references/design-adapter.md) 的「Design 实战规则」。

## 1. 产品研究与匹配分镜

读取 [planning.md](references/planning.md)；需要理解参考风格时读 [almakan.md](references/almakan.md)，案例可选 [iPhone Duo](examples/iphone-duo/README.md) 或 [Big Mac](examples/big-mac/README.md)。案例是非官方试作，其产品设定和历史费用不能当成当前事实。

用户给产品图或链接、产品名称和一个核心卖点即可开始；先读取现有材料并形成方案，只补问影响下一步的关键缺口。受众、文案和技术参数由 Agent 提出并记录假设，不让用户填写制作表。新产品或不熟悉的信息查官方来源，记录来源与未确认假设。官方产品状态图与 Logo 可在策划期间补齐，在依赖它们的生成前落实；不要让模型猜产品结构。

选一个贯穿全片的角度：产品自身历程、形态展示、共同使用时刻或单一体验隐喻。每个场景中的匹配物体都要有存在理由，人物或故事线在后面得到回应。按产品设计场景、材质、时段与光线，避免机械复制参考片的黑底顶光。

制作真人写实广告，或用户指出 H3 人物假、光线平、画面有 AI 感时，先读 [真人摄影与 H3 画面控制](references/live-action-realism.md)。把人物、光源与暗面、材料反射、焦点和运镜写入 `look-plan.json`（模板：[assets/look-plan.json](assets/look-plan.json)），并用于定帧、代表动作及成片复查。苹果参考片的可见证据与访问限制见 [官方参考研究](references/apple-live-action-study.md)；学习摄影关系，不复制演员身份或假称使用了原片器材。不要仅把“cinematic / photorealistic / 8K”追加到提示词。

按 [体验与手势接力](references/relay-design.md) 为关键接力对写清“现实动作 → 产品操作/体验 → 可见结果 → 核心卖点”，区分产品事实、创意隐喻与概念设定。选择适合产品的贯穿视觉元素，注明每次变化及最终产品收束；不强行套用亮线或固定背景。

分镜表至少包含：镜号、起止帧/节拍、景别构图、场景与光线、动作原因/握法/方向/起止状态、切点、匹配几何、叙事含义和声音桥。接力对另记录观众跟随的主锚点、指尖/接触点、手势、接触阶段及速度，字段见 [relay-plan.json](assets/relay-plan.json)。检查：

- 观众一秒内能看懂两镜如何连接；主体中心相差约不超过画宽 3%，尺度差约不超过 5%。
- 运动切点两侧方向一致、速度相近；改变方向时可在共同静止状态切换。动作需足够完整，不能只拼零碎角度。
- 手部真实施力、物体有支撑、刚体不变形，产品到达明确终态；官方照片决定外观，文案明确终态。
- 匹配主体曝光差以小于 10% 为目标；保留可辨识动作时间，常速约 0.8–1.25×，不以强制加速掩盖失败动作。

复制 [examples/template.json](examples/template.json) 建立 `montage.json`；从 [assets/project.json](assets/project.json)、[assets/capabilities.json](assets/capabilities.json)、[assets/task-map.json](assets/task-map.json) 复制项目记录模板；按接力对复制并填写 [assets/relay-plan.json](assets/relay-plan.json)，无关项标 not_applicable，再按实际方案修改。这些 JSON 是项目记录格式，不是平台 API；25 fps、150 BPM 时每拍为 10 帧。镜头需无缝覆盖时间线；避免把 27 镜模板当成固定配方，20 秒内通常先考虑 3–4 组清楚的动作接力。

方案可审阅后，落实模型、生成数量、费用及重试预留。沿用已有授权；缺少授权时一次给出具体方案和报价，询问“一次确认方案与总预算后做完”或“分阶段看方案、粗剪与视频报价、成片”。记录模式及额度，后续不重复索取已覆盖的确认。只要策划时无需连接账户或等待付费授权。

## 2. 定帧、音乐与动态分镜

读取 [generation.md](references/generation.md) 的定帧部分；按 [output-choices.md](references/output-choices.md) 落实图片清晰度、视频清晰度和画幅/尺寸，各自记录，不相互推定。已有明确选择直接沿用。

- 每镜先做首帧，必须落到特定状态的镜头补尾帧。共享构图的接力镜头以一个主定帧编辑衍生，避免独立生成造成位置漂移。
- 产品参考按可见面和状态分开，避免正反两视图拼图被融合成不可能的物体。提示词写清手指、握持边缘和接下来动作；只描述可见结构。
- 逐张按 [review.md](references/review.md) 看原尺寸产品与手部。构图问题优先用 `align.py`，用 `qc.py onion / match` 检查接力对；合格前不批量衍生错误图。
- 真人路线还需检查脸部或手部原尺寸细节、主光与暗面、前中后景、屏幕和金属反射。参考产品图主要锁定结构，不把其棚拍背景和平光强加给每个生活场景；源定帧的蜡质皮肤和无层次光照先修好，不能指望 H3 自动修复。沿用已有授权，代表镜头自检不新增用户审批。
- 配乐候选数量纳入预算；上游推荐 3 首，可按用户需求调整。用 `music.py analyze` 验证真实 BPM/拍点，不能只相信生成提示词。
- 静帧作为素材，用 Design 原生时间线或随包 `render.py --draft`、`assemble.py --draft` 制作带音乐的动态分镜，明确标为预演。代码路线先检查 [setup.md](references/setup.md)；无代码运行时使用能力足够的原生剪辑。

粗剪按“建立联系—接力—体验细节/文案—产品展示—片尾”组织疏密，按内容调整长度。卡拍不等于等长镜头；动作接力避免意外停顿，产品展示与片尾允许有意停留。

分阶段模式展示预演并落实视频报价；一次确认模式在已有规格和总额度内自检后继续。

## 3. 视频、配音与音效

读取 [generation.md](references/generation.md) 的生成部分，并使用 Design 当前能力说明中的实际参数。报价、提交、等待、下载均记录任务 ID；工具名称与参数不能凭文档示例猜测。

按模型真实支持的首帧/尾帧/参考图模式，默认从合格定帧生成单镜动作，提示词给出动作发生秒数、施力者、握法、运动方向和需保持不动的部分。原流程由后期添加 roll、pull、whip；按实际镜头需求调整，不能把数字后期当成完整三维运镜。用户要求单条源视频内转场时，将各转场的触发、前后状态和时间窗口写入同一生成任务并实际验片，不能以两段后期拼接冒充段内转场。

按模型真实合法时长留出选帧余量，避免锁定首尾帧把快速动作摊成整段慢动作。配音仅在方案需要时生成，拟音按实际动作生成。每个任务默认最多一次有针对性的重试且不超额度；额外模型对比或参考模式变体也计入预算。任务状态未知先查询，不重复提交付费任务。

H3 真人镜头先把一项主要操作拍可信，再添加有动机的运镜；复杂手部操作默认固定或单轴小幅移动机位。摄影参数作为视觉意图写进提示词，不伪造平台的光圈、焦距、快门或负面提示 API 字段。以代表片验证人物身份、肤质、受力和明暗在运动中稳定，再扩大生成；完整方法和英文示例见 [live-action-realism.md](references/live-action-realism.md)。

逐条观察完整运动及切点附近帧：手部是否持续合理、运动是否反向、产品是否达到终态、首尾是否停顿或跳变。对每组实际采用切点查看两侧各至少 2–3 帧，检查主锚点、手势接触阶段、方向与速度，把测量和证据写回 `relay-plan.json.actual/review`；静帧不能证明速度合格。记录采用区间、输出文件、模型、提示词、参考素材与重试原因。仍有关键缺陷时交付诊断和待处理项，不能声称成片合格。

## 4. 卡点后期、混音与交付

读取 [post.md](references/post.md)，选择 Design 原生剪辑或随包代码；两条路线均需控制帧级切点、字幕、音轨和导出。代码路线按需调用：

| 脚本 | 用途 |
|---|---|
| `render.py CONFIG OUTDIR [--draft] [ids]` | 选帧、几何对齐、旋转/拉远/甩镜、调色、字幕和片尾，输出逐镜 ProRes 与检查帧 |
| `qc.py sheet / onion / cuts / match / look` | 联系表、叠图、切点曝光、匹配测量和原尺寸细节裁切 |
| `align.py IN OUT L T Z` | 裁切缩放定帧，对齐主体 |
| `undot.py IN OUT BOX` | 修复指定屏幕区域的模型伪摄像孔；修改后复查 |
| `music.py analyze TRACK` / `cut CONFIG` | 分析节拍、能量和调性，按小节剪配乐 |
| `mix.py CONFIG` | 配音、拟音、闪避、混音、分轨与响度报告 |
| `assemble.py CONFIG RENDERDIR [--draft]` | 拼接 MP4、ProRes 母版与分轨 |

代码执行顺序：`render → qc cuts → music cut → mix → assemble`；原生路线见 [design-adapter.md](references/design-adapter.md) 的后期与交付步骤。抠像旋转、背景滚动、产品动效等代码合成镜头，以及硬切、连续减速停稳、背景延展消缝和暗底纹理的做法见 [post.md](references/post.md) 的「Design 版代码合成补充」。文字与 Logo 后期准确叠加；匹配剪辑保留运动方向及速度，音乐结尾尽量连续保留原曲收束并把最终重音对齐片尾。

模板有占位素材、macOS 字体和示例时间码，需替换后才能完成真实渲染。字幕字体必须支持实际语言。脚本基于上游代码，已修复首句旁白限幅和音乐交叉淡化的音源边界；详见 [setup.md](references/setup.md) 的输入与导出检查。

按 [review.md](references/review.md) 检查实际输出：全片正常速度观看、原尺寸产品与手部、所有匹配切点、音乐接缝、动作音效、实际帧数/尺寸/时长、音视频解码。建议混音目标为 -14 LUFS ±0.5、真峰值不高于 -1.5 dBTP；未实际听审或播放的项目写“未验证”，不能由脚本通过推定感官质量合格。

交付 `output/vN/` 的 MP4、ProRes 母版及分轨（按用户所需）、配置、可提供的素材和版本说明。通过 Design 正式导入将成片放到目标画布，超过单文件上限的母版留在本地并在画布放预览版；把真实资源、版本、节点 ID 写回记录，用户指定外部目录时同步副本。原生可编辑时间线存在时提供真实入口；代码工程标为配置/脚本源包，视频节点不等于可编辑时间线。只有本地文件完成时明确画布交付尚未完成。保留旧版本，只重做受修改影响的镜头与后期。
