# 检查范围

本技能区分两类检查：制作过程中的**构建检查**由执行者完成；成片的**画面与听感审阅**交给用户。

## 构建检查（执行者完成）

- 确定性：同一时刻重复调用、倒退再返回应得到相同画面。可抽查 0 秒、切镜前后与末帧；GPU 合成可能有单色阶舍入差异，不按 PNG 字节哈希判断。
- 截图稳定性：每帧在编码前执行同一时间点的连续像素确认，重试失败即停止。重复平铺、单帧整屏错位或合成残片是工程故障，不是审美选择；不得交给用户承担发现这类已知故障的责任。更换渲染环境或相关实现时，连续渲染前 3 秒验证，覆盖约 1.5–1.6 秒的已知异常区间。
- 交互：预览开始、Space 暂停恢复、R 重播、←/→ 切镜、分段跳转、静音开关可用；后镜不重播启动黑场。
- 版面：字体已加载、目标语言字符齐全；挖孔安全区、状态栏、字幕与手机边界不冲突；横屏内容方向正确。发现这类明确的工程问题时修好再导出。
- 导出参数：脚本自动核验 h264、yuv420p、尺寸、平均帧率、总帧数、时长（误差不超过一帧另留 20ms 容器公差）、音轨（有声 AAC/48kHz，静音版无音轨），并完整解码。
- 源码完整：换目录仍能定位素材并重新导出，依赖与许可齐全。

## 不做的事

- 不对自己导出的成片做验收式审片，不逐帧挑审美问题，也不依据自查结论自行重做或重新生成。
- 不把技术报告中的 `technical_check: passed` 表述为“画面/声音已通过”；`user_review` 保持 pending，直到用户反馈。
- 用户明确要求核查某段画面或声音时，按其范围分析并报告，再按协作节奏决定是否修改。

## 交付说明

交付回复写明实测片长、尺寸、帧率、声音路线、已完成的构建检查与交付结果，以及未覆盖或受阻的项。修改以用户指出的时间码、镜头或对象为准。编辑技能包本身时不启动付费媒体任务，也不把本机测试描述为平台端到端验证。
