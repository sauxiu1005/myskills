# 手机界面演示视频

把内容变成“手机里发生的事”，交付 **MP4 成片 + 可编辑 HTML/CSS/JS 工程 + 单文件动画预览 + 分镜**。网页预览与视频使用同一绝对时间轴，MP4 自动导出，不以“请自行录屏”作为交付。

参考 Unclecheng 的 phone-ui-demos，保留手机细节、HyperOS/MIUI 视觉语言、系统组件转译和镜头连续性。来源、许可与适配差异见 [provenance](references/provenance.md)。环境、作品组织、声音与交付说明见 [项目交付](references/project-delivery.md)；下文 `pui` 指 `node <skillRoot>/scripts/phone-ui.mjs`。

确认点：交付规格（仅在无法推断时）、分镜、成片审阅。确认点之间连续执行；用户已确认脚本或要求直接完成时，跳过对应确认点。

## STEP 1：接收内容与锁定规格

最低输入为主题与核心内容，可以是功能清单、口播稿、知识点或参考素材。提取受众、目的、产品名称、准确文案/数据、语言、时长、画幅和声音要求，已有答案不重复追问。用户提到产品、Logo、截图或之前的作品时，先在项目中查找。

时长、画幅和声音方式决定排版与节奏，开始制作前确定。能从请求、用途或引用素材推断时直接采用并简要说明；否则用选择题给出推荐规格：当前对话语言、16:9 1920×1080、30fps、约 5–9 镜、每镜 6–12 秒（据内容估算总时长）、合成系统音效、无配乐、无旁白。竖屏需重新排版字幕与手机，不能仅裁切横版。

预览默认静音；MP4 默认包含克制的合成系统音效。用户要求静音则导出无音轨。需要配乐或旁白时使用已有文件或已授权的生成能力；会产生费用的生成先在方案中说明，额外费用由用户确认。

提供界面截图时，逐张查看并标记功能、文字、布局和交互状态；关键文字与控件重建为可编辑界面，截图可作背景或素材。只有单张状态图时，设计必要的点击、输入、加载与结果状态，不把平移静态截图当交互演示。品牌名称、指定收尾文案按原文保留；未指定品牌时可虚构，示例数据明确标注。

按 [项目交付](references/project-delivery.md) 检查 Node、Chrome/Chromium、puppeteer-core、ffmpeg/ffprobe。不自行安装；缺少时说明影响并请用户同意安装方式。用户暂缓时继续完成分镜、预览和源码，成片标记为受阻。

## STEP 2：分镜（确认点）

将分镜写成本片作品中的文本文档：

`镜头 | 起止秒/时长 | 核心信息 | 系统场景 | 壁纸色 | 手机动作与衔接 | 两侧字幕 | 声音事件`

通常按“锁屏通知 → App 打开 → 核心交互 → 数据沉淀 → 锁屏熄屏/品牌卡”组织。按需读取 [系统组件](references/upstream/system-ui-patterns.md)、[手机结构](references/upstream/phone-stage.md)、[大字幕](references/upstream/bg-captions.md)；`assets/upstream/examples/kexue/` 对应镜头仅作视觉参考，示例文案不是用户的产品事实。

- 每镜只讲一件事：要点变通知、对话变聊天、步骤变设置、数据变圆环/控制中心。
- 机身有侧键、天线带、挖孔、反光、SVG 状态栏与 Home 条；至少两层有区别的玻璃/内容材质。
- 深靛舞台贯穿全片，主题壁纸随镜变化，功能语义色保持一致。字幕在手机两侧背景层；竖屏改为上下安全区。
- 每镜至少两次有意义的姿态变化，只有首镜登场，后镜接续前镜姿态。至少一次 App 图标展开转场。
- 字幕入场轮换，手机不压字；弹性入场、60–80ms 列表错峰是起点，按可读性调整。
- 图标使用内联 SVG。未提供品牌时使用虚构 App；用户提供品牌资产时准确使用（上游“禁止真实品牌”只针对其示例）。

需要时请用户确认或调整分镜；用户已确认或明确要求直接完成时继续制作。

## STEP 3：建立可导出的网页工程

在项目工作目录中以随包模板起步（不把技能目录里的示例当作品修改）：

```sh
pui init <projectRoot>/phone-film
```

`index.html` 是镜头总览，`film.html` 是连续播放器，`story.js` 放分镜/字幕/声音事件，`film.js`、`style.css` 放动画与布局。模板是虚构学习产品的 5 镜 30 秒示例，用于演示导出契约；按已确认分镜改写，可扩展设置、控制中心等场景。

读取 [时间轴与导出](references/rendering.md)。每帧调用 `renderAt(seconds)`，状态由绝对时间计算，任意顺序跳转结果一致。不要把上游一次性 cue、CSS 实时时钟或逐页 `location.href` 接到渲染器；保留视觉设计，迁移到连续时间轴。

预览保留黑场启动、默认静音、隐藏 HUD、分段点击、Space 暂停、R 重播、←/→ 切镜。导出模式隐藏启动层、HUD、鼠标与提示；需要的片头黑场写入时间轴。

## STEP 4：构建检查与声音

默认抽帧按当前镜头表计算各镜代表时刻和衔接，不沿用示例的固定秒数。用 `pui stills` 输出少量代表性静帧做构建检查：修复字体缺失、挖孔遮字、字幕压手机、横屏方向错误、玻璃层下孤立元素。这是制作过程中的工程检查，不是对成片的验收式审片。

音效按秒记录在 `story.js`，预览与离线合成读取同一事件表。浏览器截图不会录入 WebAudio，使用随包合成器输出 WAV，或用 `--audio` 传入已完成混音。外部混音见 [rendering](references/rendering.md)。

关键帧与视频导出必须使用随包的稳定截图流程：固定动画时间、等待浏览器绘制，在同一时间点连续两次截图像素一致后才编码；不一致时有限重拍，持续异常则停止并保留诊断帧。不得改写成每帧只截一次的简化流程，不通过改变片头、删除或替换成片帧来掩盖问题。这是制作中的保护，不是成片后的补救审片。详见 [截图稳定性](references/rendering.md#截图稳定性：编码前保护)。

## STEP 5：导出与交付（确认点）

构建问题修正后直接导出，不再另问：

```sh
pui doctor <projectRoot>/phone-film
pui stills <projectRoot>/phone-film
pui export <projectRoot>/phone-film --out <projectRoot>/phone-film/out/video-v1.mp4
pui bundle <projectRoot>/phone-film --out <projectRoot>/phone-film/out/preview-v1.html
```

路径为示意；以上是随包本地脚本。`CHROME_PATH`、`FFMPEG_PATH`、`FFPROBE_PATH` 指向本次环境找到的可执行文件。`--silent` 去除音轨；`--audio <final-mix.wav>` 使用外部母带，不叠加随包音效。渲染可能超过单条命令的等待时限：按 [长任务执行与恢复](references/rendering.md#长任务执行与恢复) 保留持久任务标识和日志，导出未结束时不重复启动。

导出流程：依赖检查 → 字体/素材就绪 → 固定帧率逐帧渲染 → 音效 WAV 或外部混音 → H.264/yuv420p（有声时 AAC 48kHz）+ faststart → ffprobe 核对尺寸、帧数、帧率、时长、音轨并完整解码。不覆盖已有成片，下一版用新文件名。

随后按 [项目交付](references/project-delivery.md) 的交付规则，把成片、单文件动画预览、可编辑源码包和关键帧放入本片作品，交付状态以工具结果为准。用 ffprobe 参数与规格对照，但不对自己的成片做验收式审片、不依据自查结论重做（见 [检查范围](references/qa.md)）。把成片交给用户，概述结构、节奏与关键取舍，请用户确认或指出要修改的时间码。

## STEP 6：按时间码修改

把用户的时间码或批注对应到 `story.js` 中的镜头。复用素材，只改目标镜头与必要衔接，重新导出和打包，将成片、预览与源码包作为原有素材的新版本交付，并更新分镜文档。只要求分镜或文案时停在对应交付，不强制制作视频。

## 制作交接与可迁移交付

代码制作前读取 [执行交接](references/execution-handoff.md)。集中保留已确认的创意简报、输入版本和交付目标。使用可用执行能力制作和渲染，明确报告缺失依赖。随包 CLI 是实现选项，最终交付为可用文件及复现说明。

渲染前使用有许可、覆盖目标语言的工程字体，或明确验证执行环境提供所需字形。本包有意不附带字体；缺少字体时报告前置条件，不默默承诺跨机器排版一致。允许再分发的字体在源码交付前连同许可和来源一起复制进工程。

`bundle` 内嵌 CSS 本地图片、字体和直接媒体属性；不支持的动态加载、CSS import 和 srcset 会明确报错，不把缺资源预览标为完成。避免隐含网络依赖。新增场景需要同时补 film.html 对应结构与 film.js 动画，不只改 story.js 的场景名。修订使用新输出文件名，不在已有工程上重复 init。
