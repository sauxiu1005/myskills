# 口播、分镜与视频 Prompt

> **适用**：当前创意方向、产品依据以及需要持续保持的人物 / 角色关系已经明确，需要组织完整表达、分镜和视频 prompt 时读取。

先确定整条内容如何推进，再完成一条连续表达，最后决定镜头如何承载它。不要先画时间格，再把广告句分别填进去。

## 0. 确定内容推进与 speech plan

在写逐字口播前，先用内部短句想清楚：开场让观众进入什么；后续通过什么动作、观察、观点或回答继续；结尾抵达什么新的理解、状态或选择。它不必是固定三幕式，也不要求每个开场问题在某一镜机械作答，但每一段都要继承前一段并增加新内容。

按用户要求的总时长组织完整表达，为内容段落记录“前面留下的状态”和“这里新增的内容”。段落按意义组织，镜头按拍摄与观看需要组织，生成片段按执行能力组织，三者不必一一对应。更长时长可以用于完整操作、观察、反应和判断，不靠重复卖点或拖长静止画面填满。

在写台词前，同时建立一份全片唯一的 **speech plan**。它是声音归属的真相源：每段人声写清 `speaker`（谁在说）、`source`（镜头内说话 / 画外旁白）和 `voice_identity`（是否与其它 clip 是同一声音）；没有台词的片段明确标记为 `no speech`。

- `镜头内说话`：可见的对应人物正在说话，并按需要口型同步。
- `画外旁白`：叙述者不在画面中；画面人物不应被写成正在说这段台词或对口型。
- 同一 `voice_identity` 出现在多个 clip 时，使用当前模型支持的最可靠方式保持同一声音。若当前能力只能通过 prompt 描述维持声音，则建立一份稳定、简洁的声音特征并在相关 clip 中保持一致；若模型已有 Voice ID、reference 或其它稳定机制，优先使用当前能力而不是重复文字配方。
- 多人对话按每一句的 `speaker` 与先后顺序记录；不同说话人需要有可听见的身份区分，不用预设固定的性别、年龄或声线模板。

speech plan 是内部制作合同，不额外塞进用户确认问题。用户版分镜只呈现最终可听见的关系和听感。

## 1. 写连续口播

围绕当前采用的开场和核心信息，先写一段同一个人能够自然连续说完的话：

- 一段主要推进一个感受、判断或使用过程；同义评价只留最具体的一句。
- 用正在发生的动作和具体观察承接判断，不连续堆抽象形容词。
- 每句口播都对应当前动作、观察或即时判断，并推动下一步动作或态度；不要先写一段脱离镜头的广告词再贴到画面上。
- 允许短句、停顿和不对称表达，不把每句写成结构整齐的广告金句。
- 不强制口播承担 Hook；画面、对话或声音已经完成开场时，主口播可以稍后进入。
- CTA 与前文语气和真实购买路径一致；没有明确入口就自然收住。

避免连续使用同一种语言模板，例如反复的“不是……而是……”“我最喜欢的是……”“属于……那种”。重点不是替换禁词，而是把整段读一遍：如果像四句互不相连的广告标题，重新写成一条生活线。

按实际可说话的时间、目标语言与自然语速估算台词容量，同时为操作、观察、反应和停顿留出空间；能与口播同时发生的动作不重复扣时。所有说话人共用预算，字数仅用于判断能否自然说完，不作为填满时长的指标。超出时先删重复评价、次要卖点和形容词，不要求人物加速说完；用户明确给定或已经采用的逐字台词如需实质改动，按当前协作规则说明影响后再调整。

对谈、采访和 podcast 按可用时长决定话题深度，给人物观点、回应和自然的产品承接留出空间。较短时把它写成一段值得单独观看的切片：围绕一个具体问题和有内容的回答展开，不强求同时完成产品介绍、卖点和 CTA；所有说话人的台词共同占用时长预算。暂时遮住产品后，对话本身仍应值得听。若主持人必须从第一问开始递产品卖点，优先改成朋友问答、街访或普通双人对话。

逐字台词使用 `deliverable_language`：北美/海外受众默认英文，国内受众默认中文，用户明确指定优先。视频生成 prompt 的描述部分用英文书写，逐字台词和画内文字在 prompt 中保持 `deliverable_language` 原文，不翻译。用户审阅版分镜使用 `working_language`，其中逐字台词保持 `deliverable_language` 原文，不翻译。用户提供的准确台词始终保持原文。用户对话语言、受众成片语言与 prompt 描述语言是三个明确区分的层次。

## 2. 从表达和动作设计镜头

先画出完整的真实使用动作链：人物从什么状态开始，如何拿取、打开、使用、穿戴或收起产品，最后停在哪里。拿起、打开、装入、拉好、背上、调整和转身展示可以共同构成一条完整生活逻辑，不因动作多就删掉必要步骤。

再决定每个动作由什么画面承载：

- **A-roll** 承载人物持续表达、反应和主要叙事。
- **B-roll / coverage** 单独拍产品特写、操作步骤、上身关系、使用结果或生活瞬间，再按口播和信息需要穿插。
- 能在同一机位自然完成的动作保持连续；产品与身体关系、遮挡或结构状态变化复杂时，可以切到动作已经完成后的稳定状态。切点省略的是模型不必计算的中间形变，不省略观众理解使用过程所需的信息。
- 丰富感来自有意义的动作、人物反应、视点和 coverage，不要求一次生成或一个连续镜头承担整条复杂物理链。

只有以下变化值得切镜：

- 动作进入了一个无法在当前机位清楚呈现的新阶段。
- 信息重点或观察对象发生变化。
- 需要新的视点来展示产品与人体、环境或结果的关系。
- 场景或时间确实改变。

同一个简单转身、拿取、打开、使用产品或说完一句话的过程，可以保持连续。切镜边界落在完整台词和完整动作之后，不在一句话或一个动作尚未完成时切换片段或重置状态。时间段是内容节奏标记，不自动代表剪辑点。若同一镜头跨多个时间段，在 prompt 中明确 `continuous handheld take`、`the camera continues following` 或同等自然语言；只有确实要切时才写 `cut to` 并说明切换理由。

节奏由观看推进产生，而不是由均匀切镜或时间格产生。新的信息、动作结果、人物反应、关系变化，以及有动机的景别、角度、机位距离、运动、遮挡、构图或景深变化，都可以制造新的观看张力；镜头语言不是装饰，它应改变观众此刻在看什么、期待什么或感受什么。停顿、连续镜头和慢节奏同样可以成立，只要观看状态仍在变化。不要为了“丰富”机械轮换景别或镜头语言。

涉及产品体验时，让关键动作、观察和结果有可见依据，避免只拿着产品念空泛评价。持续展开的演示、观点或对话可以保持同一机位，不设固定时长内的推进次数或镜头配额。

动作、道具或身体关系复杂时，把动作链组织成可独立获得的 coverage；每个画面有清楚的起点、主要动作和结果，并在稳定状态之间衔接。是否切镜、何时变化由内容需要决定，不为增加数量而打断句子或动作，也不靠删掉必要步骤换稳定。

## 3. 用户可审阅版分镜

可审阅分镜按内容顺序呈现，并给出总时长内可容纳的段落预算，不逐秒填格。用户指定的开场时点、音乐卡点、文字同步或其它精确要求才使用时间码；总时长精确不代表每个动作必须精确到秒。用户版只呈现需要判断的内容：

```markdown
# {时长} KOC / UGC 视频分镜

- 创意：{开场实际发生什么，后续如何顺着展开}
- 人物：{谁在什么情境表达}
- 声音：{谁在镜头内说话、谁是画外旁白、每位声音最终听起来怎样，以及同一声音跨片段如何保持连续}

| 内容段落 / 大致时长 | 镜头 | 画面 | 逐字口播 | 声音 |
```

镜头列需要说明是“连续跟拍”“同一机位继续”还是“切到近景”，不能只写一串不同景别，让用户和模型猜哪里发生剪辑。产品限制、refs、模型参数、混音参数和内部禁令不进入用户版分镜。

将分镜与逐字口播保存为可审阅的项目内容，并按当前协作节奏让用户审阅；需要等待用户审阅结果时，提出简洁、结构化的审阅问题。用户反馈时同步更新；用户直接编辑项目内容后，生成前重新读取最新版本。用户的修改本身已经明确解决某个决定时，不为了流程额外增加一次重复确认。

## 4. 根据能力安排生成片段

完整表达和镜头关系形成后，读取所选模型当前的时长、reference、连续性与声音能力，安排生成片段。尊重用户指定的模型；模型上限只决定可执行范围，不决定故事结构。

- 总时长在单次生成能力内，且参考、动作和声音关系适合连续完成时，优先保留为一个生成片段；一个片段可以包含多个内容段落和有理由的切镜。
- 超过单次上限，或复杂动作、场景控制、声音归属需要独立处理时，沿完整句子和稳定动作状态拆分。片段可以长短不同，不预设等长分段；不为了用满模型上限延长内容。
- 为每段明确所覆盖的内容、生成时长、起始与结束状态，以及与相邻片段的衔接。片段时长须可执行，按终剪中保留的时长和过渡重叠核算总时长；无法精确满足时先说明差异并按当前协作节奏处理，不静默取整或裁断内容。
- 一句台词只分配给一个片段，不拆半句或重复。新片段承接已有状态，从新增动作和台词开始。边界不合适时先调整划分；需要实质改变用户已经采用的台词、动作或节奏时，更新分镜并按当前协作规则呈现变化。
- 仅在使用时间码时，将全片位置转换为各片段从零起算的局部时间；没有精确同步需求时，用动作与台词的先后关系表达节奏。

生成前按顺序合并各片段内容，与当前最新分镜核对动作和台词的覆盖、顺序及衔接，避免遗漏、重复或截断。模型或单段时长改变时重新划分与编译，不沿用旧片段的内容预算。

## 5. 编译视频 Prompt

Prompt 只写当前 clip 真正需要的信息，并按自然因果顺序组织：

1. 每张 reference 先写清在本 clip 的职责与适用范围：人物或角色 identity reference 只承接需要持续保持的身份与稳定特征；产品来源承接产品事实；交互 reference 承接已经有证据的上身、手持或尺度关系。再独立写出本 clip 的开场状态、动作和构图。只有用户明确指定、当前分镜 / 项目内容明确标记，或该素材就是为这个 clip 的起始状态专门生成的 keyframe 时，才把它作为 start-frame reference；其它图片默认只承担已声明的 reference 职责。
2. 当前片段的实际时长、平台、画幅、拍摄者与相机关系，以及场景中必要的空间信息。
3. 覆盖本片段完整时长的内容推进、A-roll 或 coverage、动作起点与结束状态，以及连续拍摄或切镜关系。用内容节拍、动作先后、观看状态变化与相对节奏描述推进；只有卡点、口型、准确文字出现时点或其它同步要求依赖具体时间时才写时间码。明确有意的观察与停顿，不让剩余时长成为无安排的空白。
4. speech plan 中的逐字台词、说话人、镜头内/外来源和它发生在动作的哪个位置；画外旁白明确叙述者不出镜，画面人物不说这段台词或对口型。
5. 当前模型用于保持 `voice_identity` 的稳定机制；若只能依赖 prompt 描述，则相关 clip 使用同一份稳定声音特征，本段只补充情绪、力度、停顿或相对语速变化。
6. 环境声和已确认的音乐听感。

英文人物默认使用 `the creator`，不从样板或人设名称自行补 `he / she`；用户明确指定代词时才固定使用，并在所有 clip 保持一致。

含真人画面要有与内容相关的持续状态和小动作，而不是静止脸加产品。具体表现由当前动作和拍摄关系决定，不给每个 prompt 复制同一套眨眼、碎发、晃动或皮肤描述。人物和产品外观已由可靠 reference 传递时，不重复转述完整外观。

手持不是问题，缺少拍摄逻辑才是问题。UGC 临时记录、自拍视频和朋友跟拍可以保留轻微晃动与取景修正；固定教程或稳定产品演示则使用相符的机位。相机变化应帮助观众看清动作、关系或信息。

## 完成条件

- 完整表达是一条连续内容线，每一段都增加新的动作、信息、观点、反应或结果，不是可以任意调换的广告句。
- 镜头变化有内容或观看理由；单镜、少镜或慢节奏也持续产生新的观看价值，不靠机械换景别凑丰富度。
- 台词、动作与生成片段适合实际时长，复杂关系用可独立获得的 coverage 与稳定状态组织，终剪预算符合用户要求。
- Prompt、references、人物指代与 speech plan 前后一致；需要持续保持的身份、声音和逐字台词使用当前模型支持的稳定机制。
