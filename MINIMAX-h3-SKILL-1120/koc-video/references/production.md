# 模型执行与交付

> **适用**：当前采用的创意、分镜与生成片段已经足够明确，需要编译到当前模型、生成、组装或处理失败时读取。

本文件只负责把已经采用的内容编译到当前模型、维护跨 clip 一致性、处理声音与交付。不要在这里重新设计 Hook、人设或内容主线。

## 编译边界

已采用的分镜与 `script-and-shots.md` 共同定义视频 Prompt 的内容与写法。读取能力说明以判断可执行范围，不以模型专属的模板、栏目或机械镜头编号替代本领域的创意与写法。参数、参考素材数量与时长以当前能力契约为准。

## 1. 以当前能力编译，而不是维护固定模型配方

用户明确选择的模型作为硬约束；否则遵循当前模型选择策略及其默认项。只有当前任务的必要能力与默认模型不兼容时，才在当前允许的模型范围内选择更适合的方案。选定模型后，再从当前能力契约读取该模型的参数、时长、reference、连续性、声音、文字与编辑能力。本 Skill 不维护独立于当前能力系统的模型偏好表。

模型、模式或时长变化时，重新判断单段或多段执行，并重新编译受影响的 prompt、台词分配、reference 与衔接。只改生成时长或文件名不能完成适配。

不要在 Skill 中维护固定的模型时长菜单、reference 数量、声音锁定配方、文字生成假设或音频路线。当前模型能直接可靠完成的能力直接使用；不能可靠完成的部分选择当前可用的其它路径。

如果新的执行方式无法保留用户已经采用的内容，或会改变范围、成本或交付形态，按当前协作规则处理，不静默改写。

## 2. 生成前核对方案与 references

所选路线必须能承载当前分镜需要的人物、角色、产品、场景、声音与跨 clip 连续性。每份 reference 只承担它真正可靠的职责；具体输入类型、数量和顺序由当前能力决定。

真正生成前只做一次必要预检，不在前序每个阶段重复同一套检查：

- **内容**：当前 clip 完整覆盖分配给它的动作、台词和信息，整体顺序没有遗漏、重复或无意义填充，边界不截断句子或关键动作。
- **Identity / references**：需要持续保持的人物、角色、产品与关系有正确且不冲突的 reference；每份 reference 的职责明确，普通 reference 不代替当前 clip 真正需要的起始状态。
- **声音 / 文字**：speaker、镜头内外来源、需要跨 clip 保持的 voice identity，以及需要准确显示的文字、logo、价格或 UI 已明确。
- **Prompt 一致性**：每份 reference 的职责与 prompt 描述一致；分镜说话人与 prompt 指代一致。
- **Capability**：所选模型能够承载当前时长、references、连续性、声音与文字要求；不能时先调整执行路线，不静默改写已采用的内容。

这些核对默认在内部完成，不把 checklist 逐项念给用户。

## 3. 视频生成

每个 clip 只使用当前分镜分配给它的画面、动作、逐字台词、speech plan 和声音，按 `script-and-shots.md` 第 5 节编译 Prompt，不套用其它来源的提示词模板、栏目或镜头编号；当前能力只决定可用模型路线、reference、时长、画幅、分辨率、声音和编辑方式。

一个 clip 可以是一条连续镜头，也可以包含有理由的切镜。不要把分镜表每一行机械翻译成一次切镜。多 clip 可以改变场景，但需要持续保持的人物、产品和叙事关系继续沿用；新场景不应只是复制长期人物 reference 的背景与姿态。

## 4. 声音与准确文字

可见人物需要说话时，当前视频模型具备可用的 native speech 能力就优先原声生成，让说话、表演和口型在同一次视频生成中完成。不要因为内容使用数字人或虚拟主持人，就默认拆成独立 TTS + lip-sync 路线；只有用户明确要求外部旁白 / 替换音轨，或所选视频模型无法完成可用的原声表达时，才切换声音方案。默认不走独立 lip-sync。

- 用户给定逐字台词时保持原文；需要镜头内说话时维护发言者与口型关系，需要画外旁白时不要让画面人物承担这段台词。
- 同一 `voice_identity` 跨 clip 时使用当前模型最可靠的一致性机制；如果只能靠 prompt 描述，则保持同一份稳定声音特征。
- 当前模型无法可靠区分同一 clip 的多个说话人时，优先调整可执行划分，或在会改变当前采用内容时把限制交给用户，不静默把不同角色压成同一声音。
- 只有当 BGM 能明确承担节奏、情绪或跨段连续性时才加入；混音目标是让音乐服务内容且不遮挡人声与关键信息，具体混音方法由当前可用后期能力决定。
- 字幕默认不加；只有用户明确需要字幕时才制作。准确评论、价格、产品文字、logo 或 UI 属于画面文字需求，不自动开启全片字幕。
- Hook 或内容依赖准确评论、价格、产品文字、logo 或 UI 时，使用当前能力中可靠的文字保真路径；不要因为某一代视频模型的限制把实现方式永久写死。

没有试听、转写或其它可靠核验时，不宣称原生台词已经逐字准确。

## 5. 多 clip 与最终组装

需要多 clip 时，按当前分镜与内容节奏组装：

- 同一动作或相近场景按内容关系衔接。
- 跨时间或场景时使用与内容相符的过渡，不默认添加无意义黑场或特效。
- 片头从实际内容开始，片尾不截断口播或动作。
- 音乐、字幕、文字 overlay 与其它后期只按当前采用方案加入。

跨 clip 的承接方式由当前模型能力决定：可以是独立稳定起点、首尾帧、视频续写、角色 / 产品 reference 或未来其它可靠机制。无论采用哪种方式，都不改变当前采用的叙事、动作和台词。

## 6. 项目与交付

把分镜、可复用 references、生成 clip、后期资产和最终成片保存到当前项目中，并保持后续修改所需要的对象身份、引用与版本关系。使用当前项目已有的组织与版本机制，不把某一代画布节点、文件路径或具体工具调用写成永久前提。

用户提供的素材与已经存在的可靠项目资产直接沿用。新的候选、修订或替代结果按当前项目语义保存，确保后续修改引用真实结果，而不是靠聊天里的重新描述代替素材。

交付时只报告实际完成的成片与可用资产，以及真正影响用户下一步的限制，不复述 prompt、模型参数或内部检查过程。

## 7. 核验与失败处理

**发现问题不等于获得重新生成授权。**

默认不对已生成结果做验收式内容检查。用户明确要求核查，或工具结果已经明确暴露失败、缺失或执行异常时，再在对应范围内定位问题与最小影响范围。

- 只涉及分析、prompt、分镜、reference 映射、项目文档或其它不产生新媒体的修正，可以在当前授权范围内自行完成。
- 修复需要重新生成图片、视频、音频或其它用户可见媒体时，先说明具体问题、受影响资产和最小修复方案，确认已有授权覆盖本次修复；没有覆盖时，获得用户明确同意后才重新生成。
- 只重做真正受影响的资产；已经可用的 clip、reference 与后期结果保持不动。
- 内容安全拦截、物理关系崩坏、身份漂移、台词截断或同 model 失败，都先诊断产生问题的源头，不在旧 prompt 尾部叠加越来越多禁令。
- 项目写入或非生成型执行失败可以在不新增媒体成本的前提下按当前执行策略重试；仍失败时明确告知用户。

## 交付完成条件

- 分镜、可复用依据、生成资产与最终成片在当前项目中可找到并可继续修改。
- 工具执行没有明确失败或缺失；若已暴露异常，按上面的失败处理规则说明并处理。
- 交付说明只陈述实际完成的资产、已知限制与下一步需要用户决定的事项。
