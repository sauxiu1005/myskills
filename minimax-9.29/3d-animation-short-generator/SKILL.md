# 3D动画短片生成器

当用户想把一句话创意做成完整的故事驱动 3D 动画短片流程时使用本 Skill。所有耐用产物都要按生产顺序落到画布上，并在关键创意点或高成本步骤前用选项卡让用户确认。凡是固定决策、批准、修订、模型选择、分辨率选择、继续/重做关口，都必须调用 question / 选项卡工具，不允许只用普通聊天让用户回复。

核心规则：先故事、后资产；在接收用户输入后立刻用选项卡确认画面比例、总时长、**音频模式**；流程顺序固定；所有需要确认的地方都用选项卡。角色卡和场景卡锁定后，固定顺序为：七列镜头表（每秒指令+音频线索+最终对白+音频模式+嘴部状态+道具状态+位置交接+声音锁+桥接节拍）→ 镜头表自检（七项硬卡）→ 一份单一文本分镜文档（每镜一节，必须写入该镜最终对白的重写版，并明确物件在手里还是不在手里、人物上一镜结尾在哪里、本镜开头在哪里，以及连接上一镜和本镜的最小可见桥接动作，每 panel 强制含嘴部状态）→ 用户主动开启时才加可视化铅笔分镜图 → 视频模型选项卡和分辨率选项卡 → 单镜头视频生成（按音频模式改写 prompt，强制说话人绑定与非说话人闭嘴）→ 全片拼接与 BGM 合成 → 最终复查（含说话人身份与嘴部状态硬卡）。最终成片不能残留分镜痕迹。


## 强制选项卡交互规则

凡是用户需要批准、修订、选择模型、选择分辨率、锁定资产、继续、重做或选择制作分支的流程关口，都必须使用 question / 选项卡工具。不要用“回复继续”这类普通聊天问题替代选项卡。如果某个强制关口还没展示选项卡，用户先在普通聊天里回答了，也要补发选项卡，让用户在选项卡里选择。

## 质检结论、返工授权与停止条件（v1.1.11）

质检是对现有产物的判断，不是追加生成授权。“全部通过才交付”仅指可标记为合格成品的条件，不得解释为自动返工直到通过。逐项记录通过 / 未通过 / 未核验 / 不适用、证据位置、镜头编号与影响；无法核验不得记作通过。未通过或未核验时仍应报告结果并展示现有产物，但标明待审、已知缺陷或不完整，不冒称合格成品。

任何追加图片、视频、音频生成或重新合成都必须先取得覆盖本次操作的明确授权；没有预授权就先用选项卡确认。既有故事、资产、分镜、模型或首轮生成批准，不自动覆盖返工；“检查一下”“更好一点”和无具体范围的“继续”不是追加生成授权。用户已明确授权具体镜头、操作与次数时不得重复索取同一授权。本节对返工授权的专门规则优先于其他章节泛称“继续”或补发选项卡的表述，不改变无关的创意批准关口。

返工卡列出问题证据、受影响镜头及版本、拟修改项、保留项、模型/规格/参考是否变化、追加生成次数、可能费用与停止条件；费用未知要说明，不得编造。默认一次批准只覆盖每个列明产物一次追加生成，不自动执行整条阶梯。用户可预先明确授权更少次数或一个有界批次；同一镜头及同一问题最多初次生成加两次追加尝试（三次总尝试），拆镜、换模型、换错误名称均不重置累计计数，平台更严上限优先。

只修改存在证据的受影响镜头和实际失效的依赖；邻镜先复查交接，不因相邻就重生。合格且未受影响资产保持锁定。文档修订、检查未通过、新候选产物出现均不自动使旧资产作废或使新资产获批。优先提出局部文本或剪辑修正；文字修正不能冒称媒体已修好。只改配乐混音不重生画面，只重画可选铅笔图不重生视频。

达到验收目标、授权次数/预算/时间上限、三次总尝试上限、用户暂停/取消、外部阻塞、同类问题无实质改善或下一步超出授权时，立即停止追加操作，保存已有结果并报告。失败阶梯只是候选策略，不是自动执行队列；未获新授权不得换模型、删参考/角色/道具、拆镜、改时长、改音频模式或扩大范围。到达本问题尝试上限后结束该轮，不通过重新授权机械续跑同一问题；可选择保留待审版本、人工提供素材、仅修文档或另行批准实质不同的方案。旁白驱动仍不在本 Skill 范围内。

## 为什么音频模式是一级选择（v1.1，v1.1.1 修正）

3D 动画短片在当前视频模型上**最高频的失败**是**角色串戏口型错乱**——画面里有两个以上角色 + 一句对白，模型把 A 的台词配到了 B 的嘴上。本 skill 在四层把这个问题堵死：

1. **入口层** — 一上来就用选项卡让用户选「音频模式」（静音 / 对白主导），整条流水线按这个模式调校
2. **镜头表层** — 每一行带 `Audio Mode` 标签（silent / dialogue / narration / mixed）和 `Mouth State` 字段，模型不用猜
3. **Prompt 层** — 视频 prompt 前缀按音频模式改写，明文写入说话人绑定 + 非说话人闭嘴
4. **终检层** — 说话人身份正确性、嘴部状态一致性作为合格判定硬卡；未过不得标记合格成品，但必须报告现有结果，不自动追加生成。

**边界**：本 Skill 不提供「旁白主导」作为用户可选模式。旁白驱动流程不属于本 Skill 范围。

## 全局视觉风格锁

除非用户明确要求其他风格，否则角色卡、场景卡、镜头表、分镜、单镜头视频和最终合成都统一使用温暖的风格化 3D 动画外观。

- 渲染风格：皮克斯感 3D 卡通渲染，高级动画电影质感。
- 角色设计：轮廓清晰、造型语言强、表情丰富，但不追求写实解剖。
- 比例：采用亲和的风格化比例，必要时可用 Q 版比例。
- 发丝 / 毛发 / 材质：有雕塑感块面，也有细腻触感和柔和 SSS 质感。
- 表演：强调挤压与伸展、预备动作、超调与清晰情绪变化。
- 运动：镜头移动清楚、身体弹性强、微表情鲜明。

负向约束：不要写实真人摄影、不要扁平二次元、不要塑料玩具皮肤、不要僵硬人体姿势、不要无生命表情。

## STEP 0：接收需求与制作规划

捕捉：

- 一句话创意或粗略故事
- 目标产物：只要蓝图、只要资产、七列镜头表、文本分镜文档、可选铅笔分镜、单镜头视频、拼接正片、还是 BGM 合成最终成片
- 用户已说明的预估时长
- 用户已说明的画面比例
- 视觉基调
- 台词需求与语言，仅在用户明确指定时才锁定

捕捉后，必须先用选项卡确认：

- 画面尺寸 / 比例
- 总时长
- **音频模式（v1.1，v1.1.1 修正）** — 二选一：
  - **静音（视觉类 3D 动画的推荐默认）** — 纯画面叙事，只用 BGM 和音效。口型风险天然为 0。覆盖皮克斯式视觉短片、动态图形、动作追逐、视觉笑点短片。大部分「皮克斯风短片」的需求其实对应这个模式。
  - **对白主导（需要对话的项目推荐默认）** — 角色在画面里说话贯穿全片。需要严格执行一镜一人 + 反应切镜模式。用于角色驱动戏、TV pilot 式短片、对话喜剧。

只有三个都确认完成或给出自定义值后才继续。把已确认的设置写入项目简报，并用于后续全部步骤。**音频模式一路贯穿到故事大纲（Step 2）、镜头表（Step 5）、分镜（Step 6）、视频 prompt（Step 7）、终检（Step 9）。这是整条流水线最重要的单一选择。**

按以下顺序创建或更新画布产物：

1. 项目简报文本节点（v1.1 新增音频模式字段）
2. 故事大纲文本节点（v1.1 新增音频脊柱图）
3. 角色卡图片节点
4. 无人物场景卡图片节点
5. 七列镜头表节点（v1.1 新增 Audio Mode 列、Mouth State 字段）
6. 单文本分镜文档
7. 可选铅笔分镜图片节点
8. 单镜头视频节点
9. 拼接主视频节点
10. 匹配的 BGM 音频节点与最终合成视频节点

## STEP 1：项目简报

把精炼的项目简报写到画布文本节点，命名为项目名或 `项目简报`。

包含：

- 工作标题
- 一句话前提
- 情绪前提
- 目标观众感受
- 计划交付物
- 已确认的画面比例
- 已确认的总时长
- **已确认的音频模式**（v1.1 新增：`dialogue-led` / `silent`）
- 台词模式与语言（如果用户已在简报里明确了项目语言，则默认沿用该语言；中文项目默认中文对白，除非用户明确要求其他语言；`silent` 时此项置空）
- 音频脊柱摘要（v1.1 新增）：每幕一句话说明哪种音频模式主导该幕
- 初始风险：按所选音频模式标出口型风险等级——`dialogue-led` 高 / `silent` 零

然后用 question 工具展示选项卡：

- 沿用此方向继续
- 重新生成前提选项
- 修订情绪前提
- 调整台词方向
- **更换音频模式（v1.1 新增，跳回 Step 0）**

只有用户在选项卡中选择继续后才进入下一步。不要把普通聊天里的“继续”当成本关口批准，除非它对应选项卡选项。

## STEP 2：故事大纲与守门

创建故事大纲并写入 `故事大纲` 或 `story-outline`。

包含：

- 主角 Want / Need / 缺陷
- 核心世界规则
- 8 拍因果骨架
- 情绪锚点与回收
- **音频脊柱图** — 8 拍每一拍标注主导音频模式（`dialogue` / `silent` / `mixed`）。
- 台词节拍（仅在 `dialogue-led` 模式下保留）。每句台词都必须推进剧情，不只是传递信息，而且应在镜头表和分镜文档阶段就被改写成最终可拍版本。若同一镜头里有两个不同角色开口，视频生成前必须拆成 A/B 反应子镜。镜头表必须额外锁定道具在谁手里、人物上一镜结束位置、本镜起始位置、声音是否沿用同一角色声线，以及连接两镜的最小桥接动作。
- 红线检查

守门检查（v1.1 新增第 7 条，音频模式相关）：

1. 主角要主动推进故事
2. 冲突要从主角缺陷中长出来
3. 巧合不能解决问题
4. 结局要回收前面的情绪锚点
5. 压力角色要有行动性，不是扁平反派
6. 台词要推动关系变化，而不是解释主题（音频模式为 `silent` 时跳过此项）
7. **音频脊柱与所选音频模式一致**（如 `dialogue-led` 不可没有反应切镜；`silent` 不可出现对白节拍）

然后用 question 工具展示选项卡：

- 批准故事并继续
- 修订节拍
- 修订情绪曲线
- 修订台词节拍
- 返回前提
- **修订音频脊柱图（v1.1 新增）**

## STEP 3：角色卡

生成角色参考卡并放到画布。推荐顺序：

1. 主角卡
2. 如果故事包含变身、揭示、摘下伪装或前后身份切换，则必须增加“变身后角色卡”
3. 施压 / 对比角色卡
4. 可选配角卡

每张角色卡尽量做成 16:9 生产参考图，并包含清晰可读的标注。如果故事有变身、揭示、摘下伪装或前后身份切换，“变身前 / 变身后”都必须单独做成角色卡，且视为两个独立身份锚点：

- 角色名
- 角色定位
- 主 3/4 视角
- 正 / 侧 / 背三视图
- 表情（v1.1 新增：所有可能在画面里说话的角色额外提供「neutral mouth closed」参考图和「speaking」参考图，作为口型安全的身份锚定图）
- 服装 / 道具细节
- 重要道具标注
- 提示中重复身份锁
- 简短视觉 ID 备注
- **v1.1 新增：speaks_on_screen 标记** — 每个角色标注 `speaks_on_screen: true|false`。`dialogue-led` 模式下所有会上台词的角色都标 `true`；`silent` 模式下全部为 `false`。如果项目语言是中文，所有说话参考句默认也写成中文，除非用户明确要求其他语言。对于变身故事，变身前形态和变身后形态都要单独标注为可说话或不可说话，并分别作为身份锚点。

主要角色卡生成后展示选项卡：

- 锁定角色设计并继续
- 重新生成主角卡
- 调整具体视觉细节
- 增加另一张角色卡

并提醒用户：修改锁定角色后，先列出实际引用该形态且已失效的镜头及依赖，只修对应镜头表行和分镜节；变身或揭示镜头先复查，不一律重做。追加资产、视频和重合成须取得上述范围授权，未受影响产物保持锁定。

## STEP 4：场景卡

在角色卡之后生成场景参考卡。场景卡只能展示环境，不出现人物、剪影、手、脸或角色客串。

包含：

- 主环境总览
- 关键光态
- 情绪子空间
- 连续性地标
- 环境中的重要道具

然后用 question 工具展示选项卡：

- 锁定场景设计并继续
- 重新生成场景卡
- 增加另一个场景角度
- 调整光位或布局


## 连续性总检查表

每个镜头的镜头表和分镜都必须显式携带这些连续性字段：

- C1 空间锚点：始终可定位场景的固定参照物
- C2 离场状态：离场角色或物件离开本镜时的样子
- C3 光影继承：下一镜如何继承上一镜的光向和强度
- C4 时间线：一天中的时段、季节天气，以及剧情时间是否推进
- C5 色调：每个 shot 都要标色调，防止整体调性漂移
- C6 主角 vs 配角强度：主角的视觉和情绪强度必须高于配角和路人
- C7 弱帧对齐 vs 强帧锁死：多镜叙事优先弱帧对齐，转场/反转/动作连续优先强帧锁死

决策表：

- 多镜叙事类：推荐弱帧对齐
- 转场或情绪分界类：推荐强帧锁死
- 打斗/追逐等动作连续类：推荐强帧锁死
- 同场景多机位：推荐弱帧对齐

每个 shot 在进入视频阶段前，都必须补齐下面 9 个字段。


## 对白说话人拆分规则

对白主导项目中，只要视频模型负责生成原生声音，就不要把两个不同角色的台词放进同一个渲染片段。若某个镜头含两个以上说话人，视频生成前必须拆成子镜头：

- A 镜：说话人 A 说完本句；其他可见角色嘴巴闭合
- 反应拍：非说话人反应，嘴巴闭合
- B 镜：说话人 B 说完本句；其他可见角色嘴巴闭合

只有在不生成原生声音、后期另行配音时，才允许一个片段内保留多说话人。此规则用于防止“公主台词被青蛙念出”这类说话人串线错误。

## STEP 5：七列镜头表（v1.1 新增 Audio Mode 列）

在角色卡和场景卡锁定后，创建标准化镜头表。这一步是强制步骤，不能和分镜或视频生成互换。

**v1.1 变化**：表头从六列升级到七列，每秒指令新增嘴部状态字段。**第七列 = `Audio Mode`**，原 `Audio & Dialogue Track` 列升级为强制含 `Mouth State` 字段。

必要参考：按 `references/shot-table-spec.md` 执行七列表结构、每秒指令规则、全表规则、批准卡和七项自检门。每一行还必须补齐连续性总检查表里的 C1–C7 字段。

最低运行约束：

- 创建名为 `标准镜头信息表` 或 `standard-shot-table` 的表格节点
- 严格使用七列：`Shot ID & Duration`、`Continuity Handoff`、`Reference Anchors (Spatial + Identity)`、`Hook Type`、`Shot Description (Per-Second Directives)`、`Audio & Dialogue Track`（含 `Mouth State` 字段）、**`Audio Mode`（v1.1 新增）**
- 每一行都必须包含完整的每秒指令、连续性衔接、空间锚点、Hook 类型、音频/对白时序、**每秒嘴部状态**、**单镜音频模式**
- 每一行还必须补齐 C1–C7：空间锚点、离场状态、光影继承、时间线、色调、主角 vs 配角参考强度梯度、弱帧/强帧取舍
- 进入分镜前先跑镜头表自检（**v1.1 从六项升级到七项**）

随后用 question 工具展示 `references/shot-table-spec.md` 里定义的批准和自检选项卡；不要依据普通聊天回复直接推进。

### 按音频模式的镜头表规则（v1.1，v1.1.1 默认优先级修正）

音频模式不同，镜头表的硬约束也不同。前两个是 **3D 动画的主用模式**，第三个是罕用备选：

- **静音（silent，主用，视觉类 3D 动画推荐默认）**：
  - 全部行 `Audio Mode = silent`（或纯 SFX 时标 `SFX`）
  - 无任何画面内嘴部动作、无旁白
  - 每秒 `Mouth State` 全部为 `closed`
  - 口型风险由构造法消除（= 0）
- **对白主导（dialogue-led，主用，需要对话时推荐默认）**：
  - 至少 70% 行 `Audio Mode = dialogue` 或 `mixed`
  - 每行 dialogue 严格执行一镜一人 + 反应切镜
  - 反应切镜为强制而非可选
  - 这是说话人绑定 + 嘴部状态防御机制**最活跃**生效的模式

## STEP 6：文本分镜文档 + 可选铅笔分镜

镜头表自检通过后，先展示分镜模式选项卡，再生成任何分镜产物。

必要参考：按 `references/storyboard-guidelines.md` 执行默认文本分镜文档、可选铅笔分镜、按镜抽取、批准卡和回退规则。

**v1.1 变化**：每个 panel 强制含 `Mouth State` 字段，四象限内容新增 `Audio Mode` 微标签。旁白 panel 必须写明在场角色在画外音期间的表情路径（即便嘴不动）。

最低运行约束：

- 默认模式是一份权威的单一文本分镜文档，每镜一节
- 铅笔分镜图只是可选的可视化资产
- 只有用户明确标记重点迭代时，才把某镜抽成独立文本节点
- Step 7 必须读取对应的文本分镜节或抽取节点，而不是铅笔图

所有分镜批准后，再进入视频模型选项卡。

## STEP 7：视频模型选项卡 + 单镜头视频

在任何片段渲染前，默认使用 MiniMax H3 作为推荐视频模型；只有用户想更换模型时才展示视频模型选项卡。必要时仍展示分辨率/参数选项卡，并遵守模型能力限制。

必要参考：

- `references/model-selection.md`：模型选择、分辨率选择和**音频模式感知的 prompt 改写**（v1.1 新增）
- `references/fallback-policy.md`：重试梯度、漂移处理和升级策略（**v1.1 新增角色串戏 / 嘴部漂移专用梯度**）

最低运行约束：

- 每个片段默认使用 MiniMax H3，除非用户明确选择其他模型
- 每个片段都绑定到已批准的分镜节、准确角色卡和准确场景卡
- **v1.1 新增**：每个片段的 video prompt 绑定到该行 `Audio Mode` + 每秒 `Mouth State`——prompt 前缀按音频模式改写，强制说话人绑定 + 非说话人闭嘴。分镜文档里的对白是唯一来源，视频 prompt 只负责逐字复用已批准台词；如果台词不够推动剧情，必须在镜头表或分镜文档阶段改写完成，不能留到视频阶段再临场补台词；每句台词都必须推动故事发展、揭示目标、制造阻力、改变关系或回收前文，不允许只做寒暄式对答；声音也必须沿用同一角色声线，除非故事明确要求变声；如果前后镜之间存在跳步风险，必须先补一条桥接动作，再进入新的故事点。
- 渲染前剥离所有分镜专用标签
- 如果片段偏离已批准的参考锚点，按 `references/fallback-policy.md` 处理

所有片段渲染完后，按镜头顺序放到画布并分组，再展示 `references/model-selection.md` 里定义的片段批准卡（**v1.1 新增「说话人身份已确认」「对白与分镜逐字一致」「对白推进剧情」「故事已在镜头表/分镜阶段锁定」「道具与位置连续」「声音连续」「桥接动作连续」「变身形态连续」「单片段单说话人」勾选项**）。

## STEP 8：全片拼接、BGM 匹配与最终输出

所有片段批准后，拼接完整正片，匹配或生成一条连续 BGM，输出最终合成视频。

必要参考：按 `references/qc-checklist.md` 执行拼接规则、BGM 规则、最终检查（**v1.1 新增说话人身份与嘴部状态硬卡**）、分组纪律和重生成纪律。

最低运行约束：

- 保留已批准的镜头顺序
- 只使用已批准的最新资产
- 对白、反应和重要音效下压 BGM
- 除非用户明确要求，不要自动加字幕或文字
- 最终视频不能残留分镜痕迹、标注、箭头、时间标记或面板边框

最后执行终检（含说话人身份 + 嘴部状态硬卡）。已核验合格且获批的版本可交付为成品；其他版本交付检查报告和可用产物，明确待审、已知缺陷或缺失项，并等待有界返工授权，不自动循环至全部通过。细则见 `references/fallback-policy.md` 与 `references/qc-checklist.md`。

## 边界

不要把这个 Skill 用于单张图片、简单编辑、单条片段、Logo 设计或纯提示词咨询。如果用户只要 prompt，用视频提示词流程。如果用户只要角色卡，用角色拆解流程。

**音频模式路由**：本 Skill 只支持 `silent` 与 `dialogue-led`。旁白驱动短剧或第一人称画外音项目不属于本 Skill 范围。
