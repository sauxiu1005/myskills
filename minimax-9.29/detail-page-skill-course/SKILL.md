# 技能教学类课程详情页设计助手

当用户需要为技能教学类课程设计电商详情页时，使用本流程。

**什么是技能教学类课程？** 核心是"教用户掌握一种技能来解决实际问题"——考试提分、编程开发、设计软件、写作表达、理财投资、健身减脂、摄影修图、乐器演奏、语言学习、职场沟通等。

**与通用详情页的区别：** 通用 skill 用"感性→理性"三段式（Hook→Empathy→Evidence），适合 SaaS/会员/咨询等泛品类。本 skill 用6层说服漏斗，专为技能教学设计——用户不只是要被打动，还要理解"我怎么通过这个课，在真实场景里掌握技能、解决问题"。

---

## 核心设计法则

### 法则 1：6层说服漏斗

顺序不可打乱，每一层解决用户心中一个具体疑问：

| 层级 | 页面 | 用户疑问 | 核心功能 |
|------|------|----------|----------|
| L1 | 头图亮点页 | "这是什么课？跟我有关吗？" | 1秒抓注意力：课程名+核心亮点+视觉冲击 |
| L2 | 场景痛点页 | "对对对，我就是这样！" | 建立共鸣：真实场景下的具体问题 |
| L3 | 解决方案页 | "这课怎么帮我解决？" | 方法论层：独特方法/体系/框架 |
| L4 | 课程安排页 | "具体学什么？学多久？" | 执行层：讲次/模块/学习路径 |
| L5 | 师资成果页 | "老师靠谱吗？真有用吗？" | 信任层：资历+成果+学员效果 |
| L6 | 服务保障页 | "还有什么附加价值？" | 临门一脚：社群/答疑/资料/售后 |

**为什么这个顺序有效：** L1-L2 情感唤醒（"跟我有关"）→ L3-L4 理性说服（"怎么帮我"）→ L5-L6 信任闭环（"靠谱吗"）

**常见错误顺序：**
- ❌ 先课程安排再痛点 → 用户不知道为什么要学，看目录就划走
- ❌ 先老师介绍再方法 → 用户不关心老师是谁，关心"你能帮我解决什么"
- ❌ 痛点和方案混一起 → 感受不到"问题→解决"的清晰路径
- ❌ 没有场景只有痛点 → "选择题做不对"不如"考场上二选一总是选错那个"

### 法则 2：场景 > 痛点 > 功能

技能教学的说服力来源于场景代入感，不是罗列功能。

| 层级 | 弱文案 | 强文案 |
|------|--------|--------|
| 场景 | "学习遇到困难" | "考场上二选一，你总是选错那个" |
| 痛点 | "选择题正确率低" | "明明复习了三遍，模考分数反而更低了" |
| 方案 | "教你做题方法" | "拆透出题人的底层逻辑，从感觉选对变成知道为什么选" |

**三问自检：** ①用户能在这句话里看到自己吗？ ②看完会不会"对对对就是这样"？ ③能想象学完后变强了吗？

### 法则 3：方案-课程双层递进

L3（解决方案）和 L4（课程安排）是不同层级，不能混为一谈：

| | L3 解决方案页 | L4 课程安排页 |
|---|---|---|
| 回答 | "用什么方法帮你？" | "具体怎么学？" |
| 颗粒度 | 方法论/体系/框架（抽象） | 模块/讲次/知识点（具体） |
| 举例 | "逻辑破题法" | "第1讲·选择题逻辑破题法（上）" |
| 用户感受 | "方法听起来靠谱" | "这么安排，我确实能学会" |

**铁律：** L3 讲"为什么这个方法有效"，L4 讲"具体怎么执行这个方法"。

### 法则 4：师资成果的证据链

L5 构建完整信任证据链，每一环回答更深一层的疑虑：

老师资历（凭什么能教）→ 教学方法特色（跟别人有什么不同）→ 教学成果数据（学生效果如何）→ 学员证言（真人怎么说）

- 数据 > 形容词（"百万+学生验证" > "广受好评"）
- 具体 > 笼统（"选择题正确率提升23%" > "成绩明显提高"）
- 第三方背书 > 自说自话

### 法则 5：文字海的5级降噪

技能课文案通常很长，严格分5个层级让用户"扫"就能抓住重点：

| 层级 | 功能 | 字号比例 | 字重 |
|------|------|----------|------|
| L1 主标题 | 核心卖点 | 100%（最大） | 加粗 |
| L2 板块标题 | 区块引导 | ~60% | 加粗 |
| L3 重点词 | 划重点 | ~40% | 中等 |
| L4 正文 | 具体描述 | ~35% | 常规 |
| L5 辅助说明 | 注释小字 | ~25% | 细体 |

相邻层级字号差 ≥ 30%。

### 法则 6：无形技能的有形化四件套

技能看不见摸不着，用视觉手段将学习成果具象化：

1. **路径可视化**：阶梯图/路径图/时间线 — 展示"从不会到会"的成长轨迹
2. **成果对比**：Before/After — 学前vs学后的能力差异
3. **方法可视化**：流程图/框架图/思维导图 — 把方法论变成可感知的结构
4. **数据锚点**：具体数字（课时数/提分幅度/通过率/学员数）— 用数据代替形容词

每套详情页至少使用其中2种。

## STEP 0: 收集课程信息

向用户了解以下信息（已知的不重复问）：

### 必要信息
1. **课程名称**：正式名称和副标题
2. **教什么技能**：这门课教用户掌握什么能力
3. **目标用户**：谁会来学（身份+当前水平）
4. **场景痛点**：用户在什么真实场景下遇到什么具体问题（越具体越好）
5. **解决方案**：课程用什么独特方法/体系来解决这些问题
6. **课程内容**：几讲、分几个模块、每个模块学什么
7. **老师介绍**：资历、教学特色、标志性成果

### 可选信息
1. 学员成果数据：提分幅度/通过率/就业率等具体数字
2. 增值服务：社群/答疑/资料/直播等
3. 品牌调性：专业严谨 / 年轻活泼 / 高端精品 / 温暖陪伴
4. 品牌色：如有指定 hex 色值
5. 参考图：如有竞品或喜欢的风格参考
6. 尺寸：详情页比例（默认 3:4 竖版）

如果用户提供了参考图，先分析参考图的设计语言再开始规划。

## STEP 1: 规划6层说服漏斗

基于收集到的课程信息，为每一层规划具体内容。

### L1 头图亮点页（Hook）

规划要素：
- 课程名称的视觉呈现（主标题+副标题）
- 3-4个核心亮点标签（浮窗卡片形式）
- 品牌背书元素（平台/合作方/数据）
- 核心视觉（老师形象/IP角色/技能相关3D元素）
- 行动号召文案

**亮点提炼原则：** 亮点不是功能列表，是"一句话说清楚为什么这门课特别"。好亮点 = 差异化 + 具体 + 有吸引力。
- ✅ "连续4年高考趋势预测精准命中"
- ❌ "名师授课，内容全面"

### L2 场景痛点页（Empathy）

规划要素：
- 2-4个真实场景下的具体痛点
- 每个痛点有场景代入（不只是"XX不好"，而是"在什么情况下遇到什么问题"）
- 痛点的情绪递进（从轻到重，或从常见到核心）
- 一句总结性金句（把所有痛点归结为一个根本原因）

**场景文案模板：** `[场景描述]，你是不是也[具体行为/症状]？`
- "考场上二选一，你总是选错那个"
- "写代码3小时，bug找了2小时"
- "做了100张设计稿，甲方说第一版最好"

### L3 解决方案页（Method）

规划要素：
- 课程的核心方法论/教学体系（不是具体课时，是方法论层面）
- 每个方法如何对应 L2 的痛点（形成"痛点→方案"的一一映射）
- 方法的差异化表达（"我教的跟别人不一样"的核心点）

**方案文案模板：** `[痛点] → 我用[方法名]帮你[达成效果]`
- "选择题选不准 → 逻辑破题法，让你从感觉选对变成知道为什么选"
- "bug找不到 → 系统排错四步法，30秒定位问题根源"

### L4 课程安排页（Curriculum）

规划要素：
- 课程总览（几讲/几模块/总时长）
- 模块划分及每个模块的核心主题
- 学习路径的递进关系（基础→进阶→实战→冲刺）
- 每个模块的目标金句（学完这个模块你能做到什么）

**视觉呈现建议：** 阶梯式上升路径图（暗示能力递进）/ 时间线流程图（暗示学习节奏）/ 模块卡片式布局（清晰展示结构）

### L5 师资成果页（Trust）

规划要素：
- 老师核心资历（1-2句话，不是完整简历）
- 教学方法特色（跟别的老师不一样的地方）
- 教学成果数据（具体数字：学员数/提分/通过率/就业率）
- 学员证言/好评（如有）

### L6 服务保障页（Service）

规划要素：
- 增值服务清单（社群/答疑/资料/直播/作业批改等）
- 服务的具体描述（不是只写"有社群"，而是"报课即入专属群，每天定时分享精华资料"）
- 适合人群补充说明（如有额外适用场景）
- 最终 CTA（行动引导）

---

输出完整的6层架构方案（每层的文案内容+视觉方向），呈现给用户确认。

## STEP 2: 用户确认架构

将6层架构方案呈现给用户。在此阶段确认：
- 6层的文案内容是否准确
- 场景痛点是否真实、有代入感
- 方案→课程的递进关系是否清晰
- 师资成果的数据是否真实可用
- 是否需要合并/拆分某些层（某些层内容少可以合并）

**灵活合并原则：** 6层是逻辑层，不一定是6张图。
- 内容少的层可以合并（如 L5+L6 合并为一张"师资与服务"页）
- 内容多的层可以拆分（如 L4 课程安排内容特别多，拆成2张）
- 最终出图张数 = 用户确认的张数，通常4-6张

用户确认后进入生成阶段。

## STEP 3: 生成详情页

按用户确认的架构，生成详情页图片。

### 生成要求

**文字渲染：**
- 核心是文字，文字准确性第一优先级
- 主标题必须清晰可读，无错字
- 严格遵循5级降噪体系
- 中文文字使用适合品牌调性的字体风格

**6层逻辑连贯性：**
- 每张图独立，但阅读顺序有逻辑递进感
- L2 的痛点和 L3 的方案要一一对应
- L3 的方法论和 L4 的课程安排要逻辑衔接
- 视觉上用统一的色系和设计语言串联

**视觉风格：**
- 全套保持视觉一致性（同色系、同设计语言、同字体系统）
- 应用无形技能有形化策略（路径图/成果对比/方法可视化/数据锚点，至少2种）
- 现代感细节（圆角卡片、弥散阴影、渐变、装饰元素）
- 背景不要纯白，使用主色的极低饱和度变体

**批量生成策略：**
- 所有详情页在同一批次生成（或分2批），确保风格统一
- 每张图的 prompt 都包含共享的风格锚点
- 每张图有独立的内容和布局描述

## STEP 4: 呈现结果 + 迭代

展示所有生成的详情页，按6层漏斗顺序排列。

**检查清单（内部执行，不向用户展示）：**
- 文字是否清晰可读、无错字
- 5级字号层级是否清晰
- 6层说服逻辑是否连贯（用户能从 L1 一路看到 L6 不跳出）
- 场景痛点是否有代入感
- 方案→课程的递进是否清晰
- 师资成果的信任链是否完整
- 全套色彩/风格是否统一
- 无形技能有形化元素是否到位

如有问题，定位具体原因后针对性重新生成。
